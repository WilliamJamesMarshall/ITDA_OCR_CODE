# 364장 검증 실행 기록

- 원본 CSV/XLSX/inspect.ndjson은 읽기만 한다. 수정된 XLSX C열을 채점 정답으로 사용한다.
- 기존 20260909 audit에 완료된 baseline 364장과 중단된 p3 282장이 있었다. baseline은 원본·이미지·운영 코드 해시 확인 후 재사용한다. 중단된 p3는 최종 결과에서 제외하고 20260910 폴더에서 이미지 364장을 새 프로세스로 다시 실행한다.
- 실험 규칙은 기존 experiments.py와 바이트 단위로 동일하게 고정한다. 정답 채점 후 규칙을 수정하지 않는다. 운영 src와 가중치는 변경하지 않는다.
- p1은 과거 연도(2000–2099) 및 부분 날짜, p2는 날짜 순서와 영문 월 표기, p3는 좌표계별 문맥 분리 및 전역 최후 날짜 우선 제거를 누적 적용한다.
- p1/p2/p3 재평가는 동일 baseline OCR 출력을 고정한 후처리 비교다. OCR 호출과 조기 종료를 재실행하는 p3 이미지 평가와 구분한다.
- baseline_replay는 기존 선택 규칙을 동일 OCR 출력의 최종 선택 모드로 다시 실행한 대조군이다. 이 대조군에서 p1로의 변화를 후처리 개선으로 비교한다.
- OCR 프로세스는 JPEG와 로컬 모델만 읽는다. 정답 XLSX, annotations, 전사 문자열, ID별 예외 정답을 판독에 사용하지 않는다.
- 채점은 364행 모두 문자열 완전일치로 측정한다. NONE-MM-DD, YYYY-MM-NONE, NONE을 그대로 비교한다. 실행 오류는 NONE 정답과 일치해도 실패이며 결과에 ERROR로 표시한다.
- 원본과 동일한 시트명·8열·정답·D열 비교 수식으로 baseline/p3 새 XLSX를 저장한다. 각 단계 CSV와 종합 Markdown 보고서도 labels에 저장한다.
- 시간은 초기화 포함 전체 구간, 이미지 처리 구간, 이미지별 중앙값·p95를 분리한다. baseline과 p3는 서로 다른 시점의 단일 실행이다. 같은 첫 OCR 입력의 시간비로 실행 시점 영향을 점검한다. 반복 통제 실험이나 공식 평가 환경 측정은 아니다.
- baseline의 과거 가중치 해시는 기록되지 않았다. 이번 가중치 해시를 전후 대조하되 과거 가중치 동일성을 증명했다고 주장하지 않는다.
- 앞선 384/386 시각 검토 결과는 주석 정보가 포함된 다른 입력 조건이다. 이번 결과를 그 방식의 재현 성능으로 해석하지 않는다. 독립 미사용 테스트셋이 아닌 개발 검증셋이다.

## 결과 재생성 순서

1. check_provenance.py로 원본·정답·이미지·코드의 일치를 확인한다.
2. run_ocr.py p3는 새 결과 위치에서만 실행한다. 기존 p3.jsonl은 덮어쓰지 않는다.
3. replay.py를 baseline, p1, p2, p3 인수로 각각 실행한 뒤 paired_timing.py를 실행한다. OCR과 시간 측정용 재평가는 동시에 실행하지 않는다.
4. score.py로 8열 CSV와 채점 JSON을 생성한다.
5. build_results.mjs inspect로 원본 양식을 확인하고 build로 새 XLSX를 생성한다. 원본 공유 수식의 후속 행이 가져오기에서 빠지는 문제를 새 파일의 동일 수식 복원으로 처리한다.
6. restore_export_metadata.py로 내보내기에서 빠지는 글꼴 분류·빈 대각선 서식 메타데이터만 복원하고 verify_outputs.py로 모든 값·수식·서식·CSV·파일 해시를 검산한다.
7. check_provenance.py로 완료 시점의 보존 여부를 확인하고 report.py로 보고서를 생성한다.

판독과 재평가는 저장된 runtime JSON의 Paddle 환경을 사용한다. XLSX 생성은 번들 Node와 Artifact Tool, 읽기 검산은 번들 Python을 사용했다. Node가 정상 저장 로그 이후 종료 코드 1을 반환하는 현상이 있어 출력 파일 자체의 전수 검산을 완료 조건으로 삼았다.
