# 오류 계측·영역 식별 구현 결과 — 2026-09-11

## 완료 범위

구조적 진단 계획의 **1단계: 오류 계측·영역 식별**을 완료했다. 검출 결과 수집, 좌표 변환, 관측/영역 식별, 후보·역할 단서, 종료/실패 로그, 시간 계측을 기능 단위로 함께 연결했다. karpathy-guidelines에 따라 기존 날짜 선택/복구 순서와 0단계 제출 계약은 유지했다.

| 기존 손실 | 이번 구현 |
|---|---|
| 날짜로 파싱되지 않은 문자열이 최종 후보에서 사라짐 | 후보 생성과 독립된 원문·박스·다각형·역할 어휘·전체/부분 파싱 결과 기록 |
| 검출됐으나 인식 결과에서 걸러진 영역 소실 | 설치 PaddleX의 `dt_polys` 중 인식 결과에 없는 영역을 `detected_without_text`로 보존. 기존 선택/확대 입력에는 추가하지 않음 |
| 확대·회전·타일의 좌표계가 달라 같은 위치 추적 불가 | 각 패스의 실제 크기와 원본으로 돌아가는 아핀 변환 보존 |
| 같은 위치의 문자열이 달라지면 과거 역할 근거 소실 | 관측 ID와 영역 ID에 원문·역할 어휘 근거를 개별 보존 |
| 최종 날짜만으로 종료/실패 원인 파악 | 패스별 후보·숫자/순서 확실성·종료 사유·OCR 시간·예외 기록 |
| 타임아웃 때 이전 관측 소실 | OCR 시작/완료마다 JSONL 저장. 미완료 호출은 성공으로 취급하지 않음 |

## 좌표·역할의 안전 조건

- 원본 좌표는 **EXIF 방향 보정 후 이미지의 연속 경계 좌표**다. 파일의 보정 전 픽셀 좌표나 마지막 픽셀 인덱스와 구분한다. EXIF 보정 전 좌표로의 역변환은 미구현이다.
- 확대는 자른 범위와 실제 리사이즈된 폭/높이로 변환한다. 90/180/270도 회전과 네 타일도 각각 역변환한다.
- 원본 경계 상자 IoU 0.75 이상인 후보가 유일하고 해당 패스에서 아직 연결되지 않았을 때만 같은 영역 ID를 사용한다. 최초 상자를 고정해 누적 위치 이동을 막고 다대일/모호한 중첩은 별도 ID로 남긴다.
- 연결 상태는 `geometric_overlap_hypothesis`다. **기하학적 대응 가설이지 동일 인쇄 영역의 의미적 확정은 아니다.** 곡면·중첩 행 등은 다음 역할 연결 단계에서 검증해야 한다.
- 실제 좌표가 없는 인덱스 대용 상자는 `synthetic_index`로 표시하며 원본 좌표 대응에 사용하지 않는다. 과거 캐시에 없는 변환도 추측하지 않는다.
- `role_hints`는 `lexical_only` 근거다. 제조시설 안내문의 ‘제조’를 확정 제조일로 사용하지 않는다. 새 관측에 역할을 자동 전파하거나 날짜 점수를 변경하지 않는다.
- `full_parses`, `partial_parses`, `date_like`는 진단용 해석/탐색 단서이지 소비기한 승인 결과가 아니다. 설명문·숫자 문구도 포함될 수 있다. 숫자나 누락 필드를 복원하지 않는다.
- 후보의 source/variant/상자에 대응하는 관측 ID를 기록한다. 합쳐진 줄처럼 직접 대응이 없는 경우 연결을 추측하지 않고 빈 목록으로 남긴다.

## 출력 및 시간 지표

기존 실행과 `predict.ipynb`는 그대로다. `PipelineConfig.collect_trace=True`가 기본값이며 제출 CSV 옆에 `출력파일명.trace.jsonl`을 만든다. 포장 원문이 포함되므로 제출 CSV와 구분해 로컬 검수용으로 관리한다. `collect_trace=False`는 기록을 끄며 기존 로그를 삭제하지 않는다. 비활성 실행의 trace 경로는 null이다.

- 이벤트: `image_start` → 반복되는 `ocr_start`/`ocr_pass` → `image_end`. 로딩 실패는 좌표 시작 없이 오류 종료만 남을 수 있다. 직렬화 실패 시 앞선 선택 종료 뒤에 오류 종료가 추가될 수 있으며 오류 기록이 최종 상태다.
- 시작/완료마다 저장하여 강제 종료 전 관측과 진행 중인 호출을 구분한다. JSONL 마지막 행은 강제 종료로 잘릴 수 있어 완전한 행까지만 사용한다. 미완료 이미지의 날짜를 NONE으로 생성하지 않는다.
- 검증 시작 시 trace 파일을 초기화하므로 모델 초기화 중 타임아웃에도 이전 실행 로그가 섞이지 않는다.
- 직접 `predict_image` 호출은 `ImagePrediction.trace`로 조회한다. 파일 저장은 배치 경로 또는 명시한 trace 콜백이 담당한다.
- 기존 5열 제출과 `NONE-NONE-NONE` 계약은 유지한다.

`ocr_backend_seconds_per_image`(배치), `ocr_backend_seconds_per_completed_image`(검증)는 완료된 이미지의 `recognize` 호출 합을 이미지 수로 나눈다. 호출 중 최초 복구 모델 초기화는 포함하지만 이미지 로딩·전처리·판정·로그/CSV 저장·미완료 호출은 제외한다. OCR 호출 한 번당 시간이 아니다.

평가 보고서에 이 값과 장당 목표의 차이를 추가했다. **결합 합격은 계속 초기화·입출력을 포함하는 전체 경과시간 기준이다.** OCR 호출 구간만 3초 미만이라고 합격 처리하지 않는다. 1,500초 목표 초과 시 계속 실행, 2,400초 강제 종료 정책은 유지한다.
