# OCR 검증 기준 — 2026-09-10 갱신

현재 기준은 **500장, 정확도 95% 이상, 내부 처리시간 목표 1,500초 이내**다. 필수 시간 제한 2,400초와 내부 목표를 구분한다. 과거 보고서의 미정 목표나 1,600초 초안 대신 이 기준을 사용한다.

| 항목 | 현재 기준 |
|---|---:|
| 기준 입력 수 | 500장 |
| 내부 정확도 | 95% 이상: 500장 중 최소 475장 정확히 일치 |
| 내부 시간 목표 | 1,500초 이내 |
| 내부 평균 시간 | 3초/입력 이미지 이하 |
| 내부 처리량 | 초당 1/3장 이상 |
| 필수 500장 시간 제한 | 2,400초 이내 |

## 비교 방법

- 정상 완료 시 `T / N`: 전체 실행시간을 **처리가 완료된 입력 이미지 전체 수**로 나눈다. 정답을 맞힌 사진이나 라벨이 있는 사진만 분모로 쓰지 않는다.
- 타임아웃·실패로 일부만 완료되면 `T / 완료 수`를 보고한다. 중단된 이미지에 쓴 시간도 T에 포함한다. 예정된 500장을 분모로 사용해 속도를 부풀리지 않는다. 완료가 0장이면 장당 시간은 `null`이다. 미완료 실행의 500장 환산값은 제공하지 않는다.
- `N / T`: 초당 처리량도 함께 보고한다.
- `500 × T / N`: 서로 다른 입력 수의 속도를 비교하기 위한 환산값이다. 실제 500장 실행시간으로 표기하지 않는다.
- N장 내부 상대 시간 예산은 `3 × N`초다. 100장/400초는 총시간이 짧아도 4초/장이므로 미달이며, 500장/1,500초보다 느리다.
- 동일 표본에서 정확도와 상대 속도를 모두 만족해야 내부 결합 기준을 충족한다. 500장 미만의 결과는 상대 기준 충족 여부만 표시하고 `local_500_joint_target_met`와 실제 500장 타임아웃 판정은 `null`로 둔다.
- 전체 입력의 확정 정답이 있어야 하며, 출력 누락·미확정 라벨·실행 오류·제출 형식 미준수/미확인이 있으면 결합 합격으로 처리하지 않는다. 전체 누락은 정상 추론의 `NONE`이어야 하며 실행 오류를 정답으로 세지 않는다. 과거 `NONE-NONE-NONE`은 의미상 비교만 호환한다.
- 입력 수만 맞춘 개발 표본과 제품/중복 그룹을 분리한 독립 평가를 구분한다. 작은 표본의 빠른 결과, 저장 OCR 재생, 개별 사진 시간만으로 전체 목표 달성을 주장하지 않는다.

## 측정 범위와 설정

현재 `scripts/evaluate_pipeline.py`는 별도 작업 프로세스를 실행하는 `validation_runner.py`의 실제 경과 시간을 사용한다. 작업 프로세스 시작/import·이미지 탐색·모델 초기화·이미지 로딩·OCR·판정·결과 CSV 저장을 포함한다. 부모 프로세스의 초기 import/라벨 로딩과 최종 평가 리포트 저장은 제외한다. 공식 제출 환경의 외부 프로세스 전체 시간 검증은 별도로 수행해야 한다. 이전 프로세스 내부 타이머와 범위가 달라 과거 숫자와 직접 비교하지 않는다.

기본 목표는 `DEFAULT_TARGET_SECONDS_500 = 1500.0`이며, 예를 들어 `--target-seconds-500 1200`으로 이후 내부 기준을 2.4초/장으로 낮출 수 있다. 필수 2,400초 기준은 바뀌지 않는다.

## 목표 미달과 강제 종료는 별개

- **1,500초 초과:** 중단하지 않는다. 500장을 완료하면 장당 실제 시간과 3초의 차이·배율을 보고한다. `internal_target_missed_within_hard_limit`는 내부 목표 미달이지 2,400초 제한 위반이 아니다.
- **2,400초 도달 시점까지 미완료:** 작업 프로세스를 종료하고 `timeout`으로 기록한다. 특정 이미지의 OCR 호출이 반환되지 않아도 종료할 수 있다. 운영체제 스케줄링 때문에 경과 시간은 2,400초보다 미세하게 클 수 있다.
- 완료된 행은 이미지별 체크포인트로 보존한다. 미완료 이미지에 가짜 `NONE`을 넣지 않고 출력 누락으로 평가한다. 이전 실행의 CSV를 이번 결과로 오인하지 않도록 부분 출력으로 교체한다.
- 정상 완료·내부 목표 미달·타임아웃·실행 실패를 구분한다. 실제 500장 완료 시간이 1,500~2,400초라면 내부 시간 목표는 미달, 필수 시간 제한은 충족이다. 정확도 95% 충족 여부는 따로 표시한다.
- CLI는 타임아웃 때 보고서/부분 CSV를 저장한 뒤 종료 코드 `124`, 실행 실패는 `1`을 반환한다. 내부 목표만 미달한 정상 완료는 종료 코드 `0`이다.
- 작은 표본에도 실행 안전장치는 2,400초로 유지하지만 실제 500장 시간 제한 충족 여부를 주장하지 않는다.

장당 **기준 비교값**은 초기화·입출력 등 위 측정 범위가 포함된 `actual_seconds_per_completed_image`이다. 순수한 개별 이미지 로딩·OCR·판정 합계는 `completed_prediction_seconds_per_image`로 별도 제공한다. 타임아웃 때 이 보조 값에는 중단된 이미지의 미완료 소요시간이 빠지므로 합격 판단에 사용하지 않는다. 이미지 단위 평균이며 OCR 호출 한 번당 시간이 아니다.

## 부분점수와 형식 준수 — 제출 계약 정비 후

2026-09-11부터 `ocr_backend_seconds_per_completed_image`와 장당 목표 차이를 보조 지표로 제공한다. 완료 이미지의 OCR 백엔드 호출 합(호출 중 복구 모델 초기화 포함)만 측정하므로 로딩·전처리·판정·로그/CSV 저장·미완료 호출은 제외한다. 결합 합격은 기존 전체 경과시간 기준을 유지한다. 단계별 증거는 런타임의 `trace_path`에 있는 JSONL에 보존하며 중단된 마지막 행은 불완전할 수 있다.

- 내부 정확도는 `accuracy_metric = exact_match_rate`, 목표 95%를 유지한다. 공식 부분점수는 배점과 NONE 채점 방식이 확인되지 않아 `official_partial_score = null`이다.
- `field_metrics.year/month/day`: `total`은 해당 실행 범위의 평가 가능 라벨 전체 수이며 출력 누락도 포함한다. `matches / total`은 NONE 일치도 포함하는 내부 필드 일치율이다.
- `known_total`은 정답에 해당 값이 있는 수. `known_matches`, `known_wrong`, `known_missing`(정상 출력에서 해당 필드를 NONE으로 둠), `known_unavailable`(실행 실패·잘못된 출력·행 누락)을 구분한다. `known_match_rate`의 분모는 `known_total`이다.
- `absent_total`은 정답에 해당 필드가 없는 수. `absent_matches`, `absent_spurious`(값을 만들어 출력), `absent_unavailable`을 구분한다. 해당 분모가 0인 비율은 0%가 아닌 `null`이다.
- `prediction_categories`는 반환된 전체 행의 완전/부분/전체 누락/잘못된 날짜 건수다. `submission_format`도 미라벨 행을 포함한 반환 행 전체를 검사한다. 전체 행 누락은 별도 `labels_without_predictions`와 런타임 완료 수로 판단한다.
- `submission_format.final_date_compliant_rate`는 최종 문자열 준수율, `rows_compliant_rate`는 5열 순서와 개별 필드 일관성까지 맞는 비율이다. 구형 단독 `NONE`은 의미상 정답일 수 있어도 새 제출 형식에는 미달이다. 모든 행 형식 확인 결과가 없으면 `submission_format_met = null`이고 결합 합격은 false다.
- 이 지표 변경은 OCR 인식/역할/순서 규칙 개선이 아니며, 이번 단계에서는 독립 500장 검증 및 `테스트용데이터`를 사용하지 않았다.
