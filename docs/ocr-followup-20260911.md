## 1. 반영한 변경

### 미검출 영역 복구

기본 OCR에서 유효 날짜 후보가 없고, 신뢰도 높은 수평형 독립 기한 표제가 하나만 있으면 그 주변을 최대 한 번 확대 검출한다. ‘까지’만 읽고 전화번호·영양성분부터 확대하던 경로보다 먼저 실행한다. 범위는 표제 높이와 이미지 경계로 제한하고 변환 좌표를 기존 trace에 기록한다. 설명 문장, 여러 표제, 이미 읽힌 날짜가 있는 경우에는 이 신규 경로를 적용하지 않는다.

`003531`은 이 경로에서 `2020:09:20`을 읽어 `2020-09-20`으로 정상 추출했다. 번호에 의존하지 않고 표제와 좌표만 사용한다.

### 월·년 형식 안내 우선

`MM/YYYY` 또는 ‘월/년 순’ 안내와 연결되는 단일 월·년 토큰을 부분 날짜로 유지한다. 별도 표시 안내 또는 가까운 안내만 사용하며, 다른 프레임의 안내를 무조건 가져오거나 여러 대상에 배포하지 않는다. 낮은 점수, 잘못된 월, 명시된 다른 완전 소비기한은 자동 승격을 막는다.

`02/2022`가 다른 패스에서 `022022`로 읽혔다고 해서 `2022-02-20`이라는 새 일자를 만들지 않는다. `003590`은 `2022-02-NONE`으로 수정됐다. 저장 기록에서는 같은 유형의 `003633`도 개선됐다. 포장에 ‘해당 월 1일까지’라는 설명이 있더라도 이번 변경은 기존의 **인쇄된 날짜 필드 보존·확정 부분 라벨 계약**을 유지한다. 안내에서 일자를 계산하는 새로운 규칙이나 라벨 변경은 도입하지 않았다.

### 역할이 결정된 날짜 쌍의 반복 인식 축소

기존의 제한된 가까운 두 날짜 정책이 성립하고, 두 값뿐이며 모든 후보가 충분히 높은 OCR 점수이고 숫자 복원·명시 제조일 충돌이 없으면, 순위 점수 차이가 작다는 이유만으로 OCR을 반복하지 않는다. 숫자가 약하거나 추가 날짜가 있으면 기존 복구를 유지한다. 사용자 DMY 기본값을 썼다면 종료하더라도 `order_resolved=False`는 그대로 남긴다.

## 2. 시간 및 출력 계약 검증

34장 전후 비교는 동일 입력 해시, 동일 모델, 실행 순서 교차, 공통 초기화 분리 방식으로 수행했다.

| 34장 평균 | 변경 전 | 변경 후 | 3초 목표 대비 변경 후 |
|---|---:|---:|---:|
| OCR 호출 시간 | 3.033초/장 | 2.724초/장 | −0.276초 |
| 이미지 로딩·후처리 포함, 공통 초기화 제외 | 3.167초/장 | 2.843초/장 | −0.157초 |

이미지 처리 평균은 약 10.2% 감소했다. 두 방식이 공유한 모델 초기화는 3.716초이며 위 평균에서 제외했다. 이를 실제 500장 시간이나 초기화 포함 전체 실행 시간으로 바꾸어 보고하지 않는다.

별도의 기존 14장 제출 실행은 **프로세스 시작·초기화·입출력을 포함해 55.113초, 3.937초/장**이었다. OCR 호출 시간은 3.468초/장으로 각각 목표보다 0.937초, 0.468초 길었다. 상대 목표 `14×3=42초`를 넘겨도 중단하지 않고 14장 전체를 마쳤다. 제출 형식 14/14 준수, 실행 오류 0건, 정답 14/14다. 평가 상태는 `internal_target_missed_within_hard_limit`이며 500장 통과/실패 판정은 비워 두었다.

따라서 **전체 평균 3초/장 목표까지 완료했다고 보고하지 않는다.** 1,500초 소프트 목표와 2,400초 강제 종료 계약은 변경하지 않았다.
