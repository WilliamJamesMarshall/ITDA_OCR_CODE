# 상대 처리시간 목표 및 강제 타임아웃 구현

## 적용한 기준

500장 기준 내부 목표는 **정확도 95% 이상 + 1,500초 이내**, 즉 **장당 3초 이하**다. 단순히 작은 표본의 총시간이 짧아졌다고 속도 개선이라고 판단하지 않는다. 기본 정확도는 정확한 정규화 날짜 일치율이며 500장에서는 최소 475장이다.

- 1,500초를 넘겨도 계속 실행한다. 내부 시간 목표 미달과 필수 제한 위반을 구분한다.
- 작업 실행이 2,400초까지 완료되지 않으면 실제 프로세스를 종료하고 타임아웃으로 보고한다. OCR 호출이 반환되지 않는 상황도 포함한다.
- 완료 후 실제 `전체 경과시간 / 완료 이미지 수`를 장당 목표와 비교하고, 초 차이와 배율을 기록한다. 정상 완료에서는 완료 수와 입력 수가 같다.
- 미완료 실행은 예정된 500장을 분모로 사용하지 않는다. 완료 0장이면 장당 시간은 알 수 없음으로 표시한다.
- 향후 `--target-seconds-500 1200`처럼 내부 목표를 낮출 수 있다. 강제 종료 제한은 그대로 2,400초다.

기존 작업 폴더에 있던 날짜 판정·복구 영역 선택 및 목표 평가 변경은 보존했다. karpathy-guidelines에 따라 이번 수정은 검증 실행 관리·체크포인트·보고·테스트를 한 기능 묶음으로 제한했다. 이번 단계에서 OCR 날짜 판정 규칙을 추가로 바꾸거나 정확도가 개선됐다고 주장하지 않는다.

## 구현과 검증

평가 CLI에서 별도 작업 프로세스를 실행한다. 부모가 벽시계 기준 제한을 감시하며, 이미지별 완료 결과를 체크포인트로 남긴다. 타임아웃 때 완료 행만 CSV에 저장하고 미완료 이미지는 출력 누락으로 평가한다. 오래된 CSV나 인위적인 NONE을 이번 정답으로 세지 않는다.

상태는 정상 완료·타임아웃·실행 실패로 분리하고, 내부 목표 충족 여부는 별도 평가 필드로 제공한다. 보고서 저장 후 타임아웃은 CLI 종료 코드 124, 실패는 1, 내부 목표만 미달한 정상 완료는 0이다.

자동 테스트 **116개 통과**. 다음 경계를 검증했다.

- 500장 1,500초 초과~2,400초 완료는 내부 목표 미달이지만 타임아웃 충족 판정은 참.
- 2,400초 초과/미완료는 타임아웃이며 합격으로 처리하지 않음.
- 실제로 멈춘 자식 프로세스 강제 종료와 체크포인트 보존: 기다림을 줄이기 위해 테스트 한정 제한 3초 사용. 실제 2,400초를 기다린 시험은 아님.
- 완료 0장, 일부 완료, 프로세스 충돌, 잘린 체크포인트, 오래된 결과 CSV, CLI 종료 코드 구분.
- 기존 날짜 판정·출력 계약의 회귀 테스트.

## 실제 OCR 실행

기존 SHA-256 고정 개발 표본 14장으로 새 평가 CLI를 실행했다. 완료 후 원본 이미지와 코드 해시를 검증했다. 최종 측정 결과는 `artifacts/validation-deadline-20260910/report.json` 및 `verified.json`에 보존한다.

시간 측정은 작업 프로세스 시작/import, 모델 초기화, 이미지 탐색·로딩, OCR·판정, 결과 CSV 저장을 포함한다. 부모 프로세스의 초기 import/라벨 로딩과 최종 평가 보고서 저장은 제외한다. 과거 프로세스 내부 타이머와 측정 범위가 다르므로 이전 시간과 직접 비교하지 않는다.

최종 코드의 14장 실제 실행 결과:

| 항목 | 결과 | 내부 목표와 비교 |
|---|---:|---|
| 완료 | 14/14장 | 정상 완료, 타임아웃 아님 |
| 정답 | 10/14장 (71.43%) | 개발 표본에서 95% 미달 |
| 전체 경과시간 | 51.34초 | 14장 상대 목표 42초 초과 |
| 장당 실제 전체 처리시간 | 3.667초 | 3초 대비 +0.667초, 1.222배 |
| 개별 이미지 로딩·OCR·판정 평균 | 3.342초 | 보조 지표; 초기화/프로세스 시작 등 제외 |
| OCR 호출 | 41회 | 이미지 14장의 누적 호출 |

기존 동일 14장 출력 CSV와 결과가 바이트 단위로 동일하다. 검증 실행 관리만 바꾼 작업이며 정확도 향상을 주장하지 않는다. 초기화 비용과 표본 구성 때문에 이 장당 시간으로 실제 500장의 통과/불통과를 판정하지 않았다. 실제 500장 결합 판정과 필수 시간 제한 충족 여부 필드는 모두 `null`이다. 최종 코드·이미지 해시가 일치함을 확인했다.

## 다음 단계 — 있음
