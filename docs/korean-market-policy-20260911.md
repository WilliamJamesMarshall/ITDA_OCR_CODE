# 한국 식품 문맥 날짜 정책 적용 기록

2026-09-11. 근거는 사용자가 이번 요청에 첨부한 소비기한 OCR 정책이다. 원문 사본은 [요청 규칙](C:/ITDA_OCR_CODE/artifacts/korean-market-policy-20260911/requested-policy.txt)에 보존했다. 이 문서는 국가별 식품 표시 법규를 확인한 자료가 아니라 **사용자가 승인한 프로젝트 판정 정책**의 구현 기록이다.

## 기존 정책에서 달라진 점

| 구분 | 이번 기본 실행 |
|---|---|
| 한국 식품 기한 문맥 + 두 자리 세 숫자 | `YY.MM.DD`, `YY-MM-DD`, `YY/MM/DD`, 공백/가운뎃점 구분자를 YMD 우선 해석 |
| 명시 날짜 순서 | 한국어 문맥보다 우선. `일월년순`, `DDMMYY`, `MM/DD/YYYY` 등을 보존 |
| 시장/순서 미확정 | 과거 마지막 DMY 기본값 대신 `REVIEW_REQUIRED`, 후보 보존, 최종 날짜 미확정 |
| 한국 문맥의 `26.02.29` | 2026년 비윤년이므로 보류. `2029-02-26`으로 뒤집거나 28일로 고치지 않음 |
| 두 자리 연도 | `20YY`; 기존 2035 상한을 2099로 확장. 과거 날짜를 거부하지 않음 |
| 제출 | 기존 5열 유지. 미확정 날짜는 `NONE-NONE-NONE`, REVIEW 상태는 별도 trace |

운영 호출은 `PipelineConfig()`에 기본 생성되는 `DateContext()`를 모든 OCR 패스·복구·최종 판정에 전달한다. 저수준 `select_date`에서 문맥을 생략하면 과거 DMY API를 유지한다. 새 정책을 직접 사용하려면 `select_date(lines, context=DateContext())`를 호출한다. `date_context=None`은 이전 동작의 비교용이며 기본값이 아니다.

순서만 불명확한 경우와 달력상 불가능한 경우의 종료 조건은 다르다. 맑게 읽힌 숫자의 순서만 모호하면 REVIEW로 종료하지만, `26.02.29`처럼 시장 순서에서 불가능한 값이면 기존 국소 숫자 복구를 계속 허용한다. 복구 후에도 불가능하면 최종 REVIEW이며 임의 숫자를 만들지 않는다.

## 문맥의 적용 범위

- 이 프로젝트 입력은 식품 사진이라는 문맥을 사용한다. `소비기한`, `유통기한`, `품질유지기한`, `까지`가 해당 날짜 또는 기하학적으로 연결된 역할에 있을 때 한국 식품 문맥으로 추론한다. 단순히 사진 어딘가에 한글/브랜드가 있다는 이유로 YMD를 부여하지 않는다.
- 기본 추론은 **국내 제조/내수 상품이라는 사실을 외부 검증한 분류가 아니라 요청에 따른 문맥 휴리스틱**이다. 근접 수입/외국 원산지 문구가 있으면 KR 자동 우선을 막는다. 원본 좌표가 확보된 다른 확대 패스의 수입 문맥도 유지한다. 별도 상품 전체 분할 모델은 추가하지 않았으므로 같은 사진에 여러 상품이 있는 경우 완벽한 상품 귀속을 보장하지 않는다.
- 신뢰할 수 있는 상품 정보가 있는 호출자는 `DateContext(market='KR', product_type='food', language='ko')`처럼 전달할 수 있다. 화장품 등 비식품은 이 정책을 사용하지 않는다. metadata KR와 수입 문맥이 충돌하면 보류한다. 외국 시장 정보는 명시적으로 전달된 `JP→YMD`, `US→MDY`, `GB/EU→DMY`를 사용하되 명시 포장 순서가 우선한다. 국가를 브랜드나 바코드 접두사만으로 추정하는 분류는 넣지 않았다.
- 메타데이터는 해당 호출의 대상 상품에 적용된다. 섞인 데이터 전체에 일괄 KR을 지정하면 안 된다. 기본 실행은 파일명/일련번호에 따른 국가·정답 조회를 하지 않는다.

## 날짜와 부가 인쇄를 분리

시각은 `HH:MM` 또는 유효한 `HH:MM:SS`로 분리한다. `26:04:24`처럼 시간이 될 수 없는 세 숫자는 날짜 구분자 후보로 해석하지만 `09:23:04`는 시각으로 제외한다. 날짜 뒤 A/B/F2 등 1~3자리 영문·영숫자 코드는 LOT/라인 **후보**로만 보존하며 제조 공장이나 생산시각이라고 확정하지 않는다. 시각이 바로 다음 줄에 있으면 같은 프레임의 가까운 유일한 날짜에만 연결한다.

8~14자리 연속 숫자와 두 긴 숫자 묶음으로 나뉜 바코드 후보는 날짜에서 제외한다. 다만 `2026 04 24`, `19 09 2021`처럼 이미 세 필드로 구분된 날짜를 숫자 합계가 8자리라는 이유로 지우지 않는다. 요청의 바코드 배제 규칙 때문에 순수 `20260424` 같은 8자리 인쇄도 기본 시장 정책에서는 제외되며, 구분자 있는 날짜와 동일하게 취급하지 않는다. 6자리 `050926`과 명시 DDMMYY 안내는 유지한다.

날짜 모양 영역의 기존 O/0 등 문자 복구는 후보 및 보정 이력으로 유지한다. 원문·LOT를 전역 치환하지 않고, 읽히지 않은 숫자를 첨부 예시나 정답 파일에서 채우지 않는다. 고신뢰도 숫자 오독 자체를 문맥 정책만으로 해결했다고 보지 않는다.

`policy_details`에는 원문, 최종 기한, 순서, 시각, 코드, 근거, 시장, 제조일(명시되고 유일하게 해석되는 경우)을 분리한다. HIGH/MEDIUM/REVIEW는 설명용 등급이며 첨부의 예시 `0.99`/`0.90`을 실제 보정된 정답 확률로 기록하지 않는다. 기존 점수 체계에 예시의 +50/+40 등을 그대로 섞지 않는다. 촬영 시점에 대한 검증된 메타데이터가 없으므로 현재 날짜에 가까운 값을 가점해 숫자를 고르는 기능은 추가하지 않았다.

## 첨부 예시와 검수 정답의 구분

첨부의 빨간 빼빼로 예시는 `26.05.30`, 보라색 제품은 `26.08.30`으로 적혀 있지만 직전 원본 검수 기록은 각각 `000034=26.06.30`, `000255=26.08.20`이었다. 이번 요청은 **순서 정책 변경**으로 적용했으며, 이 숫자 차이를 근거로 원본·검수 정답을 덮어쓰거나 파일별 예외를 추가하지 않았다. 단위 테스트는 첨부 문자열 자체를 검사하고, 실제 사진 검증은 기존 고정 정답을 유지해 구분한다.

## 검증 범위

기존 고정 개발 55장 전후 실제 OCR과 705건 저장 OCR 재생을 별도 집계한다. 이전 정답→REVIEW, 이전 정답→바코드 배제로 미출력, 실제 정답 증가와 잘못된 확정을 각각 남긴다. 새 정책이 보류를 요구하므로 ‘기존 정답 손실 0’을 통과 조건으로 만들어 보류 정책을 몰래 되돌리지 않는다. 정확도 95% 목표는 전체 날짜 일치 기준으로 유지한다.

독립 500장 및 `테스트용데이터`는 사용하지 않는다. 3초/장(500장 1500초)은 상대 목표이며 초과 즉시 중단하지 않는다. 2400초 강제 종료와 부분 기록 보존을 유지한다. 실제 OCR 호출 시간과 초기화/입출력 포함 시간을 혼용하지 않는다. 수치는 검증 실행의 결과 파일에 기록한다.

### 저장 OCR 705건 재생

같은 705건에서 기존 **558/705 → 새 정책 558/705**다. 새로 맞힌 26건과 기존 정답 손실 26건의 대상은 서로 다르다. 손실 중 20건은 새 순서 REVIEW, 5건은 후보 배제 후 미출력, 1건(`000316`)은 완전 날짜 대신 `NONE-03-01` 부분 출력이다. 단순 총합이 같다는 이유로 회귀가 없다고 보고하지 않는다.

새 상태는 SELECTED 585건, REVIEW_REQUIRED 59건, NOT_FOUND 61건이다. 이 상태 집계는 정답률이 아니며 SELECTED에 오답도 포함된다. 저장 OCR 재생은 기존에 저장된 여러 패스의 원문을 판정한 것이고 실제 이미지 OCR/조기 종료/시간과는 다르다. 근거는 [cache.json](C:/ITDA_OCR_CODE/artifacts/korean-market-policy-20260911/cache.json)에 있다.

55장 새 정답은 **`000033` 1장**이다(`2017-06-26 → 2026-06-17`). 기존 정답 손실은 **4장**이며 모두 미출력으로 바뀌었다. `003681`, `003707`, `003714`는 순서 근거가 없는 REVIEW, `003645`는 구분자 없이 인식된 `20210902R`의 8자리 숫자가 제외된 영향이다. 이 손실을 오류가 없거나 정확도가 향상된 것으로 보고하지 않는다. 14장은 55장에 포함된 개발 부분집합이므로 합산하지 않는다.

55장 필드별 일치는 연 44→41/55, 월 47→41/55, 일 44→41/55다. 새 출력은 완전 34개·부분 6개·전체 NONE 15개이고, 상태는 SELECTED 40·REVIEW_REQUIRED 6·NOT_FOUND 9다. NOT_FOUND를 실제 기한 부재의 검증으로 해석하지 않는다. 필드 점수를 공식 부분점수로 환산하지 않았다. 제출 형식은 55장과 14장 모두 준수했다.

변경 후 55장의 실제 OCR은 3초 목표보다 **0.688초/장**, 공유 초기화 제외 처리 시간은 **0.866초/장** 길다. 14장 실제 제출 경로의 OCR은 **3.284초/장**(+0.284), 프로세스 시작·초기화·입출력 등을 포함하면 **3.747초/장**(+0.747)이다. 해당 14장 정규화 500장 환산은 1,873.405초이지만 실제 500장 검증이 아니며 `actual_500_timeout_met=null`이다. **내부 95%·장당 3초 동시 목표는 미달**이다. 새 보류 정책이 불필요한 오확정을 줄일 수 있어도 채점 정확도 향상을 보장하지 않는다.

원문 문자열을 제공한 첨부 7개 예시는 정책 단위 테스트를 통과했지만, 실제 사진 7개가 모두 정상 인식된 것은 아니다. `000033` 이외 6장은 숫자 오독/미검출 또는 미확정이 남아 있다. 기존 원본·검수 정답은 유지했다.
