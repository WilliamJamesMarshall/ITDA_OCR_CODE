### 0.3 목표 날짜 선택의 보강 우선순위 — 구현 제안

1. **명시 역할 우선:** 같은 날짜와 연결되는 소비기한/유통기한/품질기한 표제와 제조일 표제를 우선한다. 명시된 제조일을 위치나 최신 날짜 규칙으로 소비기한으로 바꾸지 않는다. 명시 근거끼리 충돌하면 국소 문맥/숫자 확인 대상으로 남긴다.
2. **무표제 두 날짜의 제한된 추론:** 대상 상품의 같은 날짜 블록 또는 대응 관계가 확인된 영역에서 제조일·기한 쌍으로 볼 수 있는 두 날짜를 비교한다. 다른 상품, 바코드, 품목 번호, 시각, 안내문의 예시 날짜는 비교 대상이 아니다. 먼저 각 날짜를 인쇄 순서·달력 제약·기존 순서 정책으로 해석한 뒤, 비교 가능한 두 날짜 중 시간상 나중인 것을 목표 기한으로 선택한다. 개별 표제가 없다는 이유만으로 이 추론을 금지하지 않는다.
3. **‘뒤에 있는 날짜’는 보조 근거:** 운영진은 시간/위치 중 우선순위나 충돌 해결을 정하지 않았다. 이 보고서는 숫자와 순서가 충분히 확인되면 시간 선후를 우선하고, 시간 비교가 불가능하되 제조일·기한 쌍 및 읽기 순서가 분명하면 뒤쪽 후보를 선택하는 방식을 제안한다. 이 경우에도 읽히지 않은 필드는 채우지 않는다. ‘뒤’는 회전 보정된 해당 블록의 읽기 순서이며, 원본 이미지의 y좌표가 더 큰 모든 숫자가 아니다. 위치와 시간 선후가 충돌하면 충돌을 기록하고 숫자/순서 확인 후 시간 기준을 적용한다. 이 우선순위는 운영진의 추가 확답이 아닌 검증할 설계다.
4. **범위 밖은 별도 처리:** 관련 없는 날짜가 섞였거나 세 개 이상 날짜의 역할을 구분하지 못하는 경우에는 전체 최댓값을 선택하지 않는다. 부분 날짜에 임의의 연도·월·일을 넣어 시간 비교를 성립시키지 않는다. 동일 날짜 쌍은 목표 날짜값은 같더라도 두 역할이 확인되었다고 기록하지 않는다.
5. **단일 무표제 날짜:** 실제 날짜 후보가 하나이며 제조일/로트/시각 등 반대 근거가 없을 때 제출 대상 날짜로 채택하는 방안은 검증할 잠정 정책으로만 둔다. ‘역할이 인쇄된 소비기한’과 ‘단일 후보라 추정한 기한’을 구분하며, 질문 1에 대한 운영진 확답은 미확정 항목으로 남긴다. 이번 보강으로 자동 채택을 구현하거나 승인된 정답으로 편입하지 않는다.

위 번호는 **목표 날짜의 역할 선택 단계**다. 기존 사용자가 정한 **날짜 순서 판정의 마지막 DMY 기본값**과 서로 다른 단계이며, 위 5번을 DMY 판정의 5단계로 혼동하지 않는다. ‘나중 날짜가 나오도록’ 날짜 순서를 역으로 고르는 순환 판단도 금지한다. 명시적인 제조일·기한 관계가 있을 때 활용하던 기존 순서 근거와, 이번 무표제 쌍의 역할 추론 근거를 따로 기록한다.

### 0.4 제출 형식과 부분점수에 대한 변경 계획

- **확정 계약:** 선택한 목표 기한의 연·월·일이 모두 없으면 최종 문자열은 `NONE-NONE-NONE`이다. 내부 `None`/미해결 상태와 외부 문자열을 분리한다. 이전 기록의 단독 `NONE`은 당시 결과이며 이번에 소급 수정하지 않았다. 코드가 이미 새 계약으로 동작한다는 뜻도 아니다.
- **부분 출력 제안:** 확실한 필드만 같은 목표 날짜에서 보존해 `2026-09-NONE`, `NONE-02-14`, `2026-NONE-NONE` 등으로 표현한다. 부분 날짜의 정확한 허용 형식/채점은 제공된 답변만으로 모두 확정할 수 없으므로 제출 명세 확인 항목으로 둔다. 숫자 값뿐 아니라 그 숫자가 연·월·일 중 무엇인지 확인되어야 한다.
- **잘못된 부분 복원 금지:** 제조일의 연도와 소비기한의 월·일을 조립하거나, 시각·로트에서 누락 숫자를 빌리지 않는다. 부분점수를 이유로 불확실한 숫자를 확정하거나 실제 없는 일자를 말일로 보충하지 않는다. 역할 선택 자체가 실패했다면 다른 날짜의 확실한 필드를 소비기한으로 제출하지 않는다.
- **평가의 두 축:** 내부 95% 목표는 기존 날짜 전체 일치 기준으로 유지한다. 별도로 연·월·일 각각의 일치율, 실제 값이 있는 필드의 정답/오답/미출력, 부분 출력 비율, NONE 판정 정오를 보고한다. 공식 부분점수 산식이 없으므로 세 필드 각 1/3점이나 특정 가중치를 공식 점수로 사용하지 않는다. 두 지표를 구분하지 않고 ‘95% 달성’이라고 보고하지 않는다.
- **비교와 이행:** 출력 경계·저장 결과·검증기·제출 생성 경로의 계약을 한 기능 단위로 맞춘다. 내부 전체 누락을 외부 3필드로 변환하되 부분 결과까지 모두 NONE으로 덮지 않는다. 기존 결과 비교에서는 완전 누락의 구/신 표기를 의미상 정규화한 정확도와 제출 형식 준수율을 따로 확인해, 문자열 형식 변경을 인식 정확도 향상으로 세지 않는다. 오류/타임아웃 원인은 내부 기록에 남기고, 제출 필드 외의 열 구성은 임의 변경하지 않는다.

## 1. 결론과 작업 범위

핵심은 정규식이나 재시도 횟수 하나의 문제가 아니다. **날짜가 인쇄된 영역을 찾는 일, 그 영역의 문자를 읽는 일, 그 날짜의 역할을 판별하는 일, 날짜 순서를 해석하는 일, 추가 OCR이 필요한지를 판단하는 일이 아직 충분히 분리되지 않았다.** 이 때문에 한 단계의 오류가 이후 단계에서 확신으로 바뀌기도 한다.

근본 개선 방향은 다음과 같다.

1. 날짜로 파싱되기 전에도 날짜 영역과 제조일/소비기한 역할을 보존한다.
2. 같은 인쇄 영역을 원본·확대·대비 보정·복구 검출 결과 사이에서 추적한다.
3. 숫자 인식의 불확실성과 날짜 역할·순서의 불확실성을 따로 판단한다.
4. 원인에 맞는 최소 복구만 실행한다. 같은 인식기로 같은 영역을 반복해서 읽는 것을 독립 검증으로 취급하지 않는다.
5. 근거가 있는 소비기한을 먼저 선택하고, 읽기 쉬운 제조일이나 달력상 유효한 다른 숫자로 대체하지 않는다.
6. 운영진 지침에 따른 무표제 날짜 쌍의 역할 추론을 명시 근거와 구분해 지원하고, 전체 누락 제출 형식과 부분점수용 평가를 독립적으로 정비한다.

이번 작업은 **읽기·진단·계획 수립**이다. 운영 코드, 모델, 원본 이미지, 정답 라벨은 수정하지 않았다. karpathy-guidelines에 따라 실제 확인과 구조적 위험, 구현 제안을 구분했다.

### 이번 세션에서 제외하는 작업

사용자 요청에 따라 **독립 500장 검증은 이 세션의 다음 단계에 포함하지 않는다.** `C:\ITDA_OCR_CODE\테스트용데이터`는 별도 테스트 일정용으로 남기며 이번 진단에서 열람·OCR 실행·정답 추정·튜닝에 사용하지 않았다. 아래 개발 검증은 이미 사용하던 개발 자료와 회귀 사례에 한정한다. 과거 보고서에 적힌 독립 500장 후속 작업보다 이 범위가 우선한다.

내부 날짜 전체 일치 정확도 95%, 장당 목표 3초(500장 기준 1,500초), 강제 종료 2,400초라는 **평가 기준 자체는 유지**한다. 공식 채점은 부분점수를 포함하므로 내부 전체 일치율과 공식 점수는 같은 지표가 아니다. 기준을 유지하는 것과 이번 세션에서 별도 테스트를 실행하는 것은 다르다.

- 기존 73장 실제 전후 비교와 최신 검증 경로의 14장 실제 결과.
- 핵심 오답 `000276`, `003645`, `003666`, `003714`의 원본 사진과 단계별 OCR 기록을 직접 대조.
- 설치된 PaddleX 인식 후처리 코드: 선택된 문자 확률의 평균을 줄 점수로 반환하며, 현재 프로젝트는 문자별 대안/분포를 보존하지 않는다.
- 인식 문자열만 사람이 읽은 값으로 바꾸는 **진단용 입력 실험**. 실제 모델 개선이나 정확도 성과가 아니라, 어느 단계에 문제가 남는지 확인하는 용도다.

### 수치의 범위

| 기존 기록 | 결과 | 해석 제한 |
|---|---|---|
| 고정 705건의 전체 저장 OCR 재생 | 555/705 | 실제 실행의 조기 종료·복구 분기와 다름 |
| 당시 150건 자동 오답 분류 | 인식/토큰화 81, 순서/근거 필터 52, 후보 순위 5, NONE/부분 날짜 12 | 각 사진의 최종 원인을 확정한 전수 육안 결과가 아님 |
| ROI 선택 변경 73장 실제 비교 | 56/73 → 56/73, 호출 323 → 306 | 호출 절감이지 정답률 개선이 아니었음 |

특히 `003666`은 전체 저장 OCR에서는 정답 후보도 존재해 ‘후보 순위’로 분류됐지만, 실제 실행은 첫 잘못된 인식에서 종료한다. **저장된 모든 OCR을 한꺼번에 넣은 원인 분류와 실제 실행 중 발생한 원인이 같다고 볼 수 없다.**

## 3. 실제 오답 네 가지의 원인

번호는 현재 폴더 기준이다. 추가 수집 자료는 이전 번호와 달라졌으므로 파일 경로/해시로 대응했다.

| 현재 번호 | 원본·정답 근거 | 실제 동작 | 확정할 수 있는 문제 |
|---|---|---|---|
| `000276` | 제조일 `25.09.26 19:28`, 소비기한 `26.03.25 까지`; 정답 `2026-03-25` | 소비기한의 `26`을 `2E`로, 제조일의 숫자와 ‘제조일자’도 여러 형태로 오독. 최종 `2023-09-25` | 숫자 오독 + 제조일 표제 오독 + 인접 ‘까지’ 문맥 오배정 + 순서 근거 상실이 겹침 |
| `003645`(이전 `003654`) | `2021.09.02 A` | `a0E1.0R0EH`, 확대 후 `20E1 0R0ER`, 대비 보정/복구에서도 유사 오독. 최종 NONE | 날짜 영역을 다시 읽어도 문자 인식이 실패함. ROI 우선순위만으로 해결되지 않음 |

| `003714`(이전 `003734`) | `01.07.2020 00:14`, `01.07.2023 (P183A)`가 모두 보임. 검수 정답은 `2023-07-01` | 두 날짜 모두 약 0.99로 인식하지만 2020년 후보에 더 높은 점수를 부여하고 두 번째 패스에서 종료 | 핵심은 숫자 인식이 아니라 두 날짜 중 어느 것을 사용할지에 대한 역할/포장 형식 근거 |

### 000276: 어떤 과정으로 제조일이 소비기한이 되는가

1. 첫 인식에서는 소비기한이 `비기:2E.03.25 까지`여서 완전 날짜 후보를 만들지 못한다.
2. 확대 인식에서 제조일 표제가 `제조일파`로 읽힐 때에는 부정 문맥으로 처리되어 제조일 점수가 낮아진다.
3. 복구 검출에서는 같은 제조일 표제가 `레조일차`로 바뀌어 제조일 키워드에 매칭되지 않는다.
4. 이 관측에는 아래 행의 `까지`가 인접 긍정 문맥으로 붙는다.
5. 기존 패스에서 얻은 제조일 역할이 같은 물리적 영역의 새 관측으로 이어지지 않는다. 새 관측은 `25.09.23`이라는 날짜 후보로 다시 경쟁한다.
6. 마지막 출력에서 DMY 기본값을 적용한 `2023-09-25`가 남는다.

따라서 `E→6`만 추가하거나 제조일 감점만 높이는 것으로는 전체 문제가 해결되지 않는다. 숫자·역할·영역의 연결이 함께 필요하다.

진단용으로 숫자만 올바르게 입력하면 `2025-03-26`이라는 다른 오답이 나온다. 표제까지 올바르게 입력하되 기존 낮은 줄 점수를 유지해도 날짜 쌍의 순서 근거가 채택되지 않는다. 두 표제와 숫자를 올바르게 넣고 진단상 높은 신뢰도를 부여했을 때는 기존 ‘역할이 명시된 날짜 쌍’ 규칙으로 `2026-03-25`가 선택된다. **이는 실제 인식 점수를 임의로 올리라는 뜻이 아니라, 줄 전체 점수 하나가 숫자·역할·순서 사용 여부를 함께 막는 구조를 보여주는 실험이다.**

### 003714: 새 운영진 지침으로 보강되는 무표제 날짜 쌍 선택

사진에는 두 날짜 위에 `Best before`가 있지만 각 행마다 MFG/EXP가 따로 명시되어 있지는 않다. 기존 보고서는 개별 역할 근거의 부족을 지적했다. 이제 운영진이 무표제 제조일·기한 쌍에서 뒤쪽 또는 시간상 나중인 날짜를 선택하도록 안내했으므로, **개별 표제가 없다는 이유만으로 시간 선후 추론을 배제하던 권고를 수정한다.**

이 사례의 같은 블록 내 두 날짜 `2020-07-01`·`2023-07-01`에는 시간상 나중인 `2023-07-01`을 선택하는 정책이 검수 정답과 부합하며, 뒤쪽 배치도 같은 선택을 뒷받침한다. 이는 ‘2020년 날짜가 사진에 제조일로 명시되어 있다’는 판독 사실이 아니라 운영진 지침을 적용한 역할 추론이다.

현재는 표제에 가까운 위 날짜에 더 높은 점수를 주고, 기간 끝 보완 로직은 550일 이하만 검토하여 이 3년 차이 쌍을 배제한다. 해결 계획은 **운영진 지침에 해당하는 날짜 쌍 선택을 거리 가점 및 임의의 550일 상한과 분리**하는 것이다. 상한을 1,100일로 바꾸는 사례 맞춤 수정이나 이미지 전체의 최신 날짜 선택으로 확장하지 않는다. 변경 효과는 아직 실행 검증하지 않았다.

## 4. 숫자 오독·누락의 구조적 문제

### 4.1 처음부터 인식된 글자에 기대어 복구할 위치를 고름

현재 확대 대상은 첫 OCR의 짧은 숫자 줄에서 최대 2개를 고른다. 이전보다 날짜를 우선하지만, 날짜가 전혀 검출되지 않거나 글자 대부분이 누락되면 선택 근거 자체가 없다. 순수 숫자 바코드와 조각난 날짜의 구분도 문자열만으로는 제한적이다.

필요한 개선:

- ‘유효한 날짜 문자열이 있음’과 ‘날짜가 인쇄된 영역이 있음’을 별도 상태로 둔다.
- 원본 해상도에서 날짜 영역을 찾는 제한된 경로를 둔다. 첫 단계는 기존 박스·라벨·국소 이미지 특징을 활용하고, 부족한 유형에 한해 날짜 영역 검출 모델의 추가/학습을 검토한다.
- 정답 영역을 사람이 지정한 진단 실험으로, 검출 실패와 인식 실패를 먼저 분리한다. 올바른 영역을 줘도 못 읽는 경우에는 검출기부터 바꾸지 않는다.

### 4.2 복구 검출기를 바꿔도 문자 인식기는 같음

기본 검출기와 복구 검출기는 다르지만 둘 다 `korean_PP-OCRv5_mobile_rec`를 쓴다. 잘못 잡은 글자 영역은 다른 검출기로 나아질 수 있지만, 점 인쇄 숫자의 모양을 반복해서 잘못 해독하는 현상에는 같은 오류가 남을 수 있다.

필요한 개선:

- 박스가 충분히 정확한 경우 검출+인식을 다시 모두 실행하지 않고 **잘라낸 날짜 줄의 인식만 재실행**하는 경로를 만든다.
- 모양·범위가 다른 국소 입력이나 별도의 경량 날짜 문자 인식 후보를 비교한다. 대체 인식기를 바로 채택하거나 매 이미지마다 병렬 실행하지 않는다.
- 단순 입력 보정으로 해결되지 않는 유형은 실물 날짜 줄을 바탕으로 인식기를 보완 학습한다. 숫자뿐 아니라 구분자, 영문 월, 필요한 단위/접미사도 보존한다. 무조건 숫자만 허용하면 로트 문자가 날짜 숫자로 바뀌는 부작용이 생긴다.

### 4.3 단일 문자열과 줄 평균 점수만 사용

현재 프로젝트는 `rec_texts`, `rec_scores`, 박스를 받아 한 가지 문자열만 저장한다. 설치된 인식 후처리는 가장 높은 점수의 문자들을 선택한 후 그 점수를 평균한다. 이 값은 ‘최종 날짜가 정답일 확률’이 아니다.

필요한 개선:

- 인식 백엔드 어댑터에서 지원 가능성을 확인해 문자별 점수/상위 대안·문자 정렬 정보를 보존한다. 설치 패키지를 직접 임시 수정하는 방식은 피하고, 버전과 디코더를 재현 가능하게 관리한다.
- 날짜 숫자 구간과 MFG/EXP 등 역할 구간의 신뢰도를 따로 계산한다. 상위 대안이 있더라도 모두 날짜로 조합하지 않고 제한된 후보만 비교한다.
- 실제 오독 자료에서 점수 구간별 정답률을 측정하여 조기 종료 기준을 보정한다. `003666`처럼 높은 점수로 틀리는 사례도 별도 추적한다.

### 4.4 유효한 날짜라고 숫자가 맞는 것은 아님

25와 26은 모두 유효한 일자다. `2021-06-26`은 달력 규칙을 통과하므로 정규식/날짜 유효성 검사만으로 `2021-06-25`를 복원할 수 없다.

필요한 개선:

- 문자 모양·다른 관측·검증된 영역 정보를 인식 근거로 사용한다.
- 정답을 보고 특정 숫자를 치환하는 규칙이나, 현재 날짜와 가까운 값을 정답으로 고르는 규칙은 넣지 않는다.
- 누락·치환·삽입을 구분하고, 실제 인쇄에서 누락된 필드와 OCR이 놓친 필드를 구분한다.

### 4.5 확대·줄 결합·부분 날짜에 남은 제한

현재는 축에 평행한 박스로 확대하고 일정 여백을 사용한다. 원근 왜곡·곡면·반사·점 인쇄에서 가장 적절한 입력이 된다는 보장은 없다. 줄 결합은 같은 좌표계의 근접한 최대 4개 줄에 한정되며, 품목 번호/시각과 잘못 합쳐질 위험도 있다. 이들은 코드상 제한이며 각 오답에 대한 단독 원인으로 모두 확정한 것은 아니다.

필요한 개선:

- 검출 다각형과 원본 좌표를 보존해 기울어진 날짜 줄을 정렬하고, 영역별 품질에 맞는 여백/확대율을 비교한다.
- 날짜 블록 안에서만 조각을 조합한다. 주소·영양성분·시각·로트는 별도 유형으로 유지한다.
- 완전 날짜 후보 하나가 있다고 모든 부분 날짜 검토를 끝내지 않는다. 명시적인 월/년 소비기한이 무관한 완전 날짜보다 우선할 수 있어야 한다.
- 단순 이진화·강한 선명화·합성 복원은 항상 유리하다고 가정하지 않는다. 원본을 함께 보존하며 숫자 획을 새로 만들어내는 처리는 정답 근거로 쓰지 않는다.

## 5. 제조일/소비기한 구분의 구조적 문제

### 5.1 읽기 쉬운 날짜만 역할 판정에 참여함

현재 후보 생성 및 날짜 쌍 역할 연결은 파싱된 날짜를 중심으로 동작한다. 소비기한 문자가 손상되면 그 영역은 최종 후보 경쟁에서 사라진다. 그 상태에서 잘 읽힌 제조일/로트가 높은 점수를 받을 수 있다.

해결: 날짜를 읽기 전에도 `제조일 영역`, `소비기한 영역`, `역할 불명 날짜 영역`을 표현한다. ‘소비기한 영역은 있으나 숫자를 못 읽음’을 제조일 후보로 대체하지 말고, 해당 영역의 복구 과제로 남긴다.

### 5.2 가까운 단어가 어느 날짜에 속하는지 불명확

현재는 문자열 앞뒤 최대 24자와 박스 간 거리로 긍정/부정 문맥 점수를 더한다. 같은 프레임만 연결하는 안전장치는 있지만, 가까운 두 행의 ‘까지’가 제조일에도 붙을 수 있다. 제조시설 안내문의 ‘제조’는 날짜 표제가 아닌데도 부정 키워드에 걸릴 수 있다.

해결:

- 역할 표제, 일반 설명문, 별도 위치 안내문을 먼저 구분한다.
- 같은 날짜 블록 안에서 정렬·행/열 관계·표제와의 대응을 이용해 연결한다. 두 개의 표제를 두 개의 날짜에 일대일로 연결하는 기존 보호는 유지·확장한다.
- 같은 행에 명시된 MFG 같은 강한 근거는 약한 주변 ‘까지’ 점수에 덮이지 않게 한다. 다만 같은 블록의 근거 충돌은 불확실 상태로 남긴다.

### 5.3 같은 인쇄 영역의 역할이 관측마다 다시 초기화됨

현재 다른 프레임의 박스를 무작정 섞지 않는 처리는 올바르다. 그러나 원본으로 되돌리는 좌표 변환/영역 ID가 없어서, 같은 제조일을 한 관측에서는 제조일로 보고 다른 관측에서는 역할 없는 날짜로 다시 평가할 수 있다.

해결:

- 원본 이미지 좌표계, 확대/회전/타일 변환, 인쇄 영역 ID를 명시적으로 보존한다.
- 기하학적으로 같은 영역임을 확인한 관측끼리만 숫자와 역할 근거를 합친다.
- 현재 프레임 차단을 그냥 제거하지 않는다. 잘못된 좌표 혼합과 다른 상품의 근거 전염을 다시 만들 수 있다.

### 5.4 날짜 문자열로 묶고 최고 점수 관측을 대표로 삼음

현재 후보는 정규화 날짜값으로 묶고 가장 높은 점수의 관측을 대표로 사용한다. 서로 다른 인쇄 위치에 같은 날짜가 있거나, 같은 위치가 관측별로 다른 날짜로 읽힌 상황을 충분히 표현하지 못한다. `source/variant`가 다르면 최대 0.60의 일치 가산점도 준다.

해결:

- 먼저 물리적 날짜 영역별로 관측을 묶고, 그 안에서 문자 후보를 비교한다.
- 영역의 역할은 후보 날짜 문자열과 별개로 유지한다. 강한 부정 근거가 대표 관측 교체로 사라지지 않게 한다.
- 같은 인식기·같은 픽셀·겹치는 확대 결과는 상관된 증거로 취급한다. 단순 패스 수 대신 모델/영역/변환의 중복을 고려한다.
- 별개 위치의 동일 날짜를 숫자가 같다는 이유만으로 하나의 역할로 합치지 않는다.

### 5.5 제조일만 있는 사진과 소비기한 인식 실패의 구분

최근 제조일 전용 종료 규칙은 일부 NONE 사례의 불필요한 OCR을 줄였다. 그러나 ‘소비기한을 발견하지 못했다’와 ‘소비기한이 실제로 없다’는 다르다. 현재 숫자 2개 이상인 소비기한 단서를 검사하는 보호가 있어도, 숫자가 모두 미검출되면 그 보호가 작동하지 않을 수 있다. 이는 검증이 필요한 구조적 위험이다.

해결: 제조일 전용 종료에는 관련 영역의 탐색 범위와 미해결 인쇄 영역 여부를 함께 확인한다. `기간 없음`, `숫자 판독 실패`, `역할 불명`, `실행 오류`를 내부적으로 분리한다. 최종 목표 기한의 **세 필드가 모두 미확인인 경우** `NONE-NONE-NONE`으로 직렬화하도록 변경할 계획이다. 일부 필드만 모르는 경우에는 선택된 같은 기한의 확인된 필드를 보존한다. 없음 판정의 속도를 유지하되 그 오판율도 측정해야 한다.

### 5.6 날짜 쌍 추론을 기간 상한·국가 추정과 분리해야 함

550일 제한과 고정 최대 연도 2035 등은 암묵적 가정이다. 반면 이번 답변 이후 무표제 제조일·기한 쌍의 나중 날짜 선택은 적용 범위를 갖는 운영진 지침이다. 이들을 같은 수준의 임의 가점으로 섞으면, 올바른 날짜 쌍이 상한 때문에 탈락하거나 무관한 미래 숫자가 기한으로 선택될 수 있다.

해결:

- 달력 유효성과 상품의 현실적 기간에 대한 가정을 분리한다.
- 명시된 역할을 우선하고, 개별 표제가 없는 관련 날짜 쌍에는 0.3절의 제한된 역할 추론을 적용한다. `인쇄 표제로 확인된 역할`과 `운영진 지침으로 추론한 역할`을 구별한다.
- 무표제 쌍의 시간 비교는 날짜 순서 해석 이후에 수행한다. 나중 날짜가 되도록 YMD/DMY/MDY를 고르는 순환 판단을 하지 않는다. 날짜 쌍이 운영진 지침의 적용 대상이라면 기간이 550일을 넘는다는 이유만으로 배제하지 않는다.
- 브랜드·국가만으로 날짜 순서를 고정하지 않는다. 같은 상품이라도 수출 시장, 포장 버전, 수입 라벨에 따라 표기가 달라질 수 있다는 가능성을 설계에 반영한다.
- 검증된 포장 규칙에는 적용 상품 식별 근거, 포장 형식/버전, 역할과 순서, 검증 자료, 충돌 시 처리, 적용 범위를 기록한다. 일련번호별 정답 예외는 금지한다.

### 5.7 완전한 날짜 후보가 있다는 이유로 복구 경로가 닫힘

타일 복구 조건은 현재 ‘날짜 없음 또는 부분 날짜’에 연결되어 있다. 역할/숫자가 의심스러워 `stop_ocr=False`여도 완전한 날짜 모양의 후보가 남아 있으면 이 복구 경로로 들어가지 않는다. `000276`의 마지막 복구 관측에서 잘못된 제조일 후보가 남는 상황도 이에 해당한다. 반대로 회복할 근거가 없는 부분 날짜는 여러 단계를 계속 돌 수 있다.

해결: 재시도 여부를 단순한 후보 유무가 아니라 **미해결 원인과 복구할 영역이 있는지**로 결정한다. 추가 타일을 무조건 허용하자는 뜻이 아니다. 읽기 실패한 소비기한 영역이 있으면 그 영역의 인식 복구를, 명시적으로 일자가 없는 월/년 표기라면 부분 날짜 종료를 선택한다. 최종 강제 종료를 실제 내용의 확신과 구분한다.

## 6. 권장하는 내부 처리 구조

새 대형 모델이나 복잡한 그래프 시스템을 처음부터 만들라는 뜻은 아니다. 기존 모듈 안에서 다음 정보를 분리해 누적하는 방향이다.

| 단계 | 보존해야 하는 정보 | 다음 단계에 넘기는 결과 |
|---|---|---|
| 영역 검출 | 원본 다각형, 좌표 변환, 물리적 영역 ID, 품질/가림 여부 | 날짜 가능 영역 및 표제/문맥 영역 |
| 문자 인식 | 원문, 날짜 구간, 문자 후보/점수(지원 확인 후), 모델/처리 이력 | 읽힌 문자와 불확실 위치 |
| 역할 연결 | 제조/소비/품질기한/시각/로트/미상, 명시/정책 추론 구분, 근거의 출처와 강도 | 숫자가 불완전해도 유지되는 역할 및 추론할 날짜 쌍 |
| 날짜 후보 구성 | 실제 토큰 경계, 완전/부분 날짜, 가능한 순서, 수정 이력 | 여러 해석을 보존한 날짜 후보 |
| 목표 선택 | 대상 상품·영역, 명시 역할 우선, 해석된 날짜의 시간 선후, 블록 읽기 순서, 정책 적용 범위 | 소비기한 후보와 선택 근거 또는 복구할 정확한 원인 |
| 복구·종료 | 영역·숫자·역할·순서 중 무엇이 불확실한지, 예상 비용, 필드별 확인 상태 | 필요한 국소 복구 또는 새 제출 계약(전체 누락 `NONE-NONE-NONE`) |

`digits_confident`, `order_resolved`, `stop_ocr`는 이미 일부 분리되어 있다. 여기에 역할 확실성, 영역 탐색 완료 여부, 관측 충돌 여부를 연결해야 한다. `stop_ocr`가 참이라는 사실을 날짜가 확실히 맞는다는 의미로 사용하지 않는다.

최종 순서는 사용자의 기존 정책을 유지한다. **명시 순서와 검증된 근거를 먼저 사용하고, 숫자와 대상 날짜는 명확하지만 순서만 모호하면 DMY로 출력한다.** 순서만 모호한 경우 추가 OCR을 하지 않는다. 이 정책은 제조일/소비기한 대상 자체가 불명확한 경우까지 ‘아무 날짜나 DMY로 변환’하라는 뜻이 아니다.

## 7. 장당 3초 목표를 지키기 위한 복구 설계

전체 평균의 기준은 `T/N`이다. 모든 개별 이미지를 3초에서 자르는 것은 아니다. 쉬운 사진은 한 번에 끝내고 어려운 소수의 사진에 추가 시간을 쓰되 평균을 관리한다.

1. **영역 없음:** 날짜 영역을 찾는 제한된 검출 복구.
2. **영역은 있으나 숫자가 불명확:** 그 영역의 정렬/국소 입력을 바꾸고 인식만 재실행.
3. **숫자는 명확하나 역할이 불명확:** 날짜 숫자를 계속 다시 읽지 말고 연결된 표제/포장 문맥을 확인. 운영진 지침의 적용 대상인 두 날짜는 시간 선후/읽기 순서로 해결할 수 있으면 추가 OCR 없이 선택 근거를 기록하고 종료.
4. **대상과 숫자는 명확하고 순서만 모호:** 기존 근거 순서 적용 후 DMY 기본값으로 종료.
5. **회복 가능한 근거 없음:** 무제한 전체 이미지 재시도나 정답 추측을 하지 않음.

속도 개선의 우선순위는 불필요한 전체 검출/인식 제거, 동일 영역 중복 제거, 필요한 날짜 줄만 인식, 가능한 범위의 줄 인식 배치화다. CPU 작업자를 무작정 늘려 4스레드 인식기끼리 경쟁시키는 방식은 먼저 채택하지 않는다.

효과는 `평균 전체 시간 = 초기화/입출력 비용의 장당 몫 + 기본 처리 비용 + 각 복구의 실행 비율 × 복구 비용`으로 나눠 측정한다. 실제 적용 여부는 해당 복구가 새로 맞힌 수, 잃은 기존 정답 수, 추가 시간, 고신뢰 오답 변화로 판단한다. 한정된 어려운 사례의 시간으로 전체 속도 개선을 단정하지 않는다.

1,500초는 내부 목표일 뿐 중단 조건이 아니다. 2,400초 강제 종료, 부분 결과 보존, 완료 이미지 수 기준 시간 보고는 이미 구현된 검증 관리 규칙을 유지한다.

## 8. 학습/보완에 필요한 데이터

기존 최종 날짜 정답만으로는 검출·인식·역할 연결을 각각 학습하거나 평가하기 어렵다. 개발 자료에 다음 보조 주석이 필요하다.

- 날짜 전체 블록과 줄/표제의 원본 다각형.
- 정규화하기 전 실제 인쇄 문자열: 구분자, 시각, 로트, 영문 월 포함.
- 각 날짜의 역할과 그 역할을 뒷받침하는 인쇄 문구/포장 근거.
- 운영진 지침으로 추론한 역할, 적용 날짜 쌍/읽기 순서 및 명시 역할과의 구분. 단일 무표제 날짜는 미확정 정책 사례로 구분하고 승인 정답으로 자동 편입하지 않음.
- 날짜 순서의 근거 및 근거가 없는 경우. 검수자가 정답을 안다는 것과 사진에 근거가 보인다는 것을 분리.
- 원래 없는 필드, 가려진 필드, 이미지에는 있으나 OCR이 놓친 필드.
- 인쇄 유형, 번짐·반사·곡면·저해상도 등 품질 태그.
- 같은 상품/같은 원본/유사 포장 그룹과 파생 확대 이미지의 연결.

숫자 줄 학습은 실제 오류 유형을 우선하며, 합성은 점 인쇄·간격·구분자·변형 등 실제와 비교 가능한 범위를 보충하는 용도다. 합성만 잘 읽는 모델을 채택하지 않는다. 날짜 블록 주변의 품목 번호·영양성분·시각은 오탐을 막는 음성 사례로 포함한다. `테스트용데이터`와 그 파생물은 여기에 넣지 않는다.

## 9. 다음 명령 이후의 후속 작업 계획 — 파일명이 아닌 기능 단위

아래는 계획이며 이번 보고서 보강에서는 어느 단계도 실행하지 않는다. 출력 계약 변경과 인식 성능 개선은 성과를 구별하되, 같은 기능에 필요한 수정은 파일명별로 나누지 않고 함께 처리한다.

| 단계 | 한 묶음으로 처리할 일 | 완료 확인 |
|---|---|---|
| 0. 제출·평가 계약 정비 | 전체 누락 직렬화, 부분 필드 보존, 제출 생성/저장/검증 경계 일관성, 전체 일치율·필드별 지표 분리 | 완전 누락은 `NONE-NONE-NONE`, 부분 결과 손실 없음, 구/신 누락 의미를 맞춘 회귀 비교와 형식 준수율 별도 보고. 공식 배점 미확정 표시 |
| 1. 오류 계측·영역 식별 | 날짜 영역/원본 좌표/관측 이력/미완전 후보/역할 근거를 보존하고 기존 사례를 재분류 | 출력 유지 확인, 원인 추적 가능, 날짜가 파싱되지 않아도 소비기한 영역이 남음 |
| 2. 목표 날짜·역할 연결 | 제조일/소비기한/일반 설명문 분리, 같은 영역의 역할 유지, 완전·부분 후보의 역할 기반 경쟁, 제조일 전용 종료 보호, 무표제 날짜 쌍의 제한된 시간/위치 추론 및 분리된 순서 안내 연결 | 잘 읽힌 제조일이 읽기 실패한 소비기한을 대체하지 않음. 명시적 MFG/EXP, 무표제 두 날짜, 위치/시간 충돌, 다른 상품/시각 혼입, 명시 DDMMYY를 나누어 확인 |
| 3. 숫자 인식 복구 | 정답 영역 진단 → 국소 정렬/인식 전용 복구 → 필요 시 경량 인식 후보/보완 학습, 문자 신뢰도와 조기 종료 보정 | `25→26` 같은 고신뢰 오독 및 숫자 누락 감소, 기존 정답 손실과 비용 확인 |
| 4. 통합·상대 성능 검증 | 기존 개발 회귀 자료에서 현재/변경안 비교, 위험별 종료 정책과 복구 예산 조정 | 동일 자료의 정확도·장당 시간·오류 유형을 함께 보고. 목표 3초 대비 차이 명시 |

1단계의 정보를 2·3단계가 공동으로 사용한다. 원인이 독립적인 항목은 개발 순서를 조정할 수 있지만, 숫자 예외를 먼저 추가한 뒤 역할 문제를 점수로 덮는 방식은 피한다. 수정 파일마다 단계를 다시 나누지 않는다.

**독립 500장 검증과 `테스트용데이터` 활용은 위 일정에서 제외한다.** 외부 테스트가 별도 일정이라는 이유로 개발 회귀 검증까지 생략하는 것은 아니다.

### 개발 검증에서 반드시 구분할 지표

- 날짜 영역을 실제로 찾은 비율과 숫자 전체 문자열 일치율.
- 숫자 치환/누락/삽입 및 고신뢰 오독의 수.
- 정답이 후보에 들어온 비율과, 후보에 들어왔을 때 최종 선택된 비율.
- 제조일 오선택, 일반 설명문 오연결, 역할 미상, 부분 날짜 과잉 완성, NONE 오판.
- 각 단계에서의 조기 종료와 그 정오, 실제 실행에서 사용되지 않은 후속 후보.
- 날짜 전체 일치율(내부 목표 95%)과 연·월·일 각각의 일치율. 값이 존재하는 필드의 오독/미출력과 실제 부재 필드의 NONE 판정을 분리하고 각 분모를 명시. 공식 부분점수 산식 확인 전 필드 평균을 공식 점수로 표시하지 않음.
- 기존 정답 손실 목록 및 필드 수준 손익, 완전/부분/전체 누락 출력 비율, 제출 문자열 형식 준수율.
- 평균 전체 초/장, 실제 OCR 실행 시간/장(집계 범위 및 병렬 호출 시간 합과 벽시계 시간의 차이 명시), p50/p95, 각 복구 호출률·비용. 두 시간 지표를 혼용하지 않고 각각 3초/장 목표 대비 차이 보고.

문자·역할·순서 모듈은 사람이 보정한 입력으로 분리 진단하고, 개선된 모델을 실제 입력으로 돌리는 검증은 별도로 한다. 사람이 보정한 입력에서 잘 작동했다는 결과를 모델 정확도로 세지 않는다.

### 보강 정책의 개발 회귀 항목 — 실행은 보류

- 첨부 사례: 번진 연도/명확한 월일/시각 분리, `20/06/2026`의 유일한 DMY 해석, 떨어진 DDMMYY 안내와 `050926` 연결. 첫 사진은 연도 및 단일 날짜 역할이 미확정이므로 완전 날짜 정답을 임의 생성하지 않는다.
- 날짜 쌍: `003714` 같은 3년 간격 쌍, 명시 제조일이 더 뒤에 인쇄된 사례, 시간 선후와 읽기 순서가 뒤집힌 사례, 동일 날짜 쌍, 부분 날짜 쌍. 550일 경계가 역할 선택을 부당하게 막지 않는지 확인한다.
- 반례: 타 상품 날짜, 바코드/로트/시각, 제조시설 설명문, 세 개 이상 무표제 날짜, 달력상 유효하지만 한 자리 오독으로 가장 늦어지는 날짜. 최신 날짜 선택이 인식 불확실성 검사를 우회하지 않는지 확인한다.
- 계약: 연·월·일 전부 없음, 각종 부분 누락, 내부 오류/타임아웃의 기록 보존, 구형 단독 NONE과 새 전체 누락 문자열 비교. 형식 수정만으로 기존 정확도가 변한 것처럼 집계하지 않는다.
- 평가: 날짜 전체 오답이어도 맞은 필드가 남는 경우를 별도로 표시하되, 서로 다른 후보의 필드를 합쳐 부분 일치율을 부풀리지 않는다.

## 10. 피해야 하는 해결 방식

- `E→6`, `5→6` 같은 전역 치환 또는 파일 번호별 정답 예외.
- 유효한 날짜이면 숫자가 맞다고 확정하거나, OCR 줄 점수를 정답 확률로 취급.
- 모든 사진의 날짜 최댓값 선택, 대상 블록을 확인하지 않은 위/아래 행 역할 확정, 국가/브랜드만으로 순서 고정. 단, 0.3절의 관련 무표제 날짜 쌍에 한정한 운영진 지침 적용은 허용할 계획이다.
- 제조일 감점·소비기한 가점·550일 임계값만 반복 조정.
- 모든 사진에 모델/회전/타일을 추가하거나, 숫자와 순서 불확실성을 구별하지 않는 재시도.
- 같은 인식기의 유사 패스를 독립 투표로 계산.
- 실제 없는 연도·일자를 채우거나 로트/시각의 숫자를 가져와 날짜 완성.
- 제조일밖에 파싱되지 않았다는 이유만으로 소비기한이 없다고 결론.
- 14장/73장 개발 실험과 저장 OCR 재생의 정확도를 합쳐 전체 성능이라고 보고.
- 별도 테스트 자료를 개발·보완 학습·튜닝에 섞는 것.
- 답변이 비어 있는 연도 후치 질문을 운영진의 일괄 DMY 승인으로 기록하거나, 질문 2의 답변을 질문 1의 승인으로 확대하는 것.
- 공식 부분점수 배점을 추측하거나, 부분 필드 평균을 내부 전체 일치 95% 달성으로 바꿔 보고하는 것.
