# ITDA 제3회 연합학술제 제출 계약 및 테스트 기준

이 문서는 OCR 구현 전에 확인해야 할 제출 요구사항과 구현 완료 후 검증할 기준을 정리한다.
코드나 최종 제출물을 동결하는 문서가 아니라, 개발 중 계속 지켜야 할 입출력·실행 경계를 정의한다.

## 1. 근거와 적용 원칙

### 공식 근거

- [제3회 ITDA 연합학술제 참가자 안내서](https://orchid-drum-814.notion.site/c74214f064ee837d81a80118ec8bf80a)
- 저장소 루트의 `README.md`

두 자료가 충돌하면 오프라인 채점과 재현성을 더 구체적으로 설명하는 `README.md`의 조건을 우선 적용한다.
공식 자료에 없는 내용은 제출 규칙으로 단정하지 않고 이 문서의 **미확정 사항**에 기록한다.

### 이번 단계의 범위

- 요구사항별 관찰 가능한 합격 기준 정의
- 현재 템플릿의 충족 상태 기록

### 이번 단계의 비범위

- 모델 가중치 다운로드
- 정확도·속도 개선
- 최종 Commit, PDF 또는 이메일 제출물 동결

## 2. 대회 과제

상품 뒷면 이미지에서 소비기한을 찾아 이미지마다 한 행의 정규화된 날짜 정보를 생성한다.
제조일자, 바코드, 전화번호, 영양성분 등 날짜와 혼동될 수 있는 숫자는 소비기한으로 선택하지 않아야 한다.

개발용 공개 데이터는 라벨이 없는 상품 이미지 3,352장이다. 실제 채점은 운영진이 별도로 준비한 비공개 입력 경로를 주입해 수행하므로 공개 데이터의 수량, 파일명 또는 정렬에 의존하면 안 된다.

## 3. 실행 계약

### 실행 환경

| 항목 | 계약 |
| --- | --- |
| Python | 3.10 |
| 장비 | Standard 4-Core vCPU, GPU 없음 |
| 제한시간 | `predict.ipynb` 전체 실행 최대 2,400초 |
| 네트워크 | 채점 중 인터넷 연결 없음 |
| 의존성 | `requirements.txt`에 정확한 버전으로 명시 |
| 실행 진입점 | 저장소 루트의 `predict.ipynb` |

패키지 설치와 사전 가중치 준비 시간은 추론 속도 평가에서 제외된다. 그러나 `predict.ipynb`의 Run All은 준비된 로컬 가중치만 사용해 오프라인으로 완주해야 한다.

### 입력 계약

`predict.ipynb` 첫 번째 코드 셀은 다음 환경변수를 읽어야 한다.

```python
import os

INPUT_DIR = os.environ.get("ITDA_INPUT_DIR", "./val_images")
OUTPUT_PATH = os.environ.get("ITDA_OUTPUT_PATH", "./submission.csv")
```

- 입력 디렉터리나 출력 파일을 다른 값으로 다시 대입하지 않는다.
- `/content/drive`, `./data` 등 개발자 환경의 절대·상대 경로에 의존하지 않는다.
- 입력 파일 수를 3,352개로 하드코딩하지 않는다.
- `image_id`는 확장자를 제거한 실제 파일명 문자열을 보존한다.
- 비공개 입력에서도 지원할 이미지 확장자만 결정적으로 탐색하고, 비이미지 파일은 처리 대상에서 제외한다.

현재 구현 기준 지원 대상으로 `.jpg`, `.jpeg`, `.png`를 대소문자와 무관하게 사용한다. 이는 공개 데이터에 맞춘 구현 기준이며, 공식 채점 입력의 전체 확장자 목록으로 단정하지 않는다.

### 노트북 실행 계약

- 새 커널에서 위에서 아래로 Run All만 수행해 완주한다.
- 이전 셀의 수동 실행 결과나 로컬 캐시에 의존하지 않는다.
- `input()`, `getpass()` 또는 대화형 위젯으로 사용자 입력을 기다리지 않는다.
- 추론 시 사람이 후보를 선택하거나 결과를 수정하지 않는다.
- GPU가 없어도 실행된다.
- 한 이미지의 실패가 전체 실행을 중단시키지 않도록 실패 정책을 명시한다.
- 최종 결과는 환경변수 `OUTPUT_PATH`가 가리키는 위치에 저장한다.

### 가중치와 외부 자원 계약

- 오픈소스 사전학습 가중치는 사용할 수 있다.
- 유료 LLM/VLM 외부 API를 추론에 호출하지 않는다.
- 대형 가중치 파일을 Git에 직접 커밋하지 않는다.
- 필요한 가중치는 노트북 실행 전에 준비한다.
- `download_weights.sh`를 사용한다면 사전 준비 단계에서만 실행한다.
- `predict.ipynb` 실행 중 자동 다운로드나 네트워크 요청을 하지 않는다.
- OCR 라이브러리의 자동 다운로드 옵션을 명시적으로 비활성화한다.

안내서에는 코드 내 자동 다운로드도 가중치 제공 방법으로 언급되지만, `README.md`는 채점 서버가 오프라인이라고 명시한다. 따라서 제출 구현에서는 **사전 다운로드만 허용하고 Run All 중 다운로드는 금지**하는 쪽으로 해석한다.

## 4. 출력 계약

### CSV 스키마

열 이름과 순서는 다음과 같아야 한다.

| 순서 | 열 | 값 |
| ---: | --- | --- |
| 1 | `image_id` | 확장자를 제거한 이미지 파일명 문자열 |
| 2 | `year` | 4자리 연도 문자열 또는 `NONE` |
| 3 | `month` | 2자리 월 문자열 또는 `NONE` |
| 4 | `day` | 2자리 일 문자열 또는 `NONE` |
| 5 | `final_date` | `YYYY-MM-DD` 또는 `NONE` |

추가 계약:

- 입력 이미지마다 정확히 한 행을 생성한다.
- 입력과 결과 사이에 누락되거나 중복된 `image_id`가 없어야 한다.
- 날짜 열은 문자열로 저장해 월과 일의 앞자리 0을 보존한다.
- 정상 날짜의 `final_date`는 `year`, `month`, `day`를 하이픈으로 연결한 값과 일치한다.
- 두 자리 연도가 있는 날짜는 `YY` 앞에 `20`을 붙여 네 자리 연도로 정규화한다. 예를 들어 `25.12.04`는 `2025-12-04`, `26.03.11`은 `2026-03-11`로 처리한다.
- `12.04`처럼 연도 숫자가 전혀 없는 날짜는 완전한 날짜로 확정하지 않고 날짜 네 열을 모두 `NONE`으로 둔다.
- 선택 가능한 완전한 날짜가 없다고 판단한 경우 날짜 네 열을 모두 `NONE`으로 둔다.
- 존재하지 않는 날짜와 달력상 잘못된 날짜를 정상 결과로 출력하지 않는다.
- CSV 저장 시 DataFrame 인덱스를 포함하지 않는다.
- 출력 디렉터리와 파일명은 반드시 `OUTPUT_PATH`를 따른다.

## 6. 품질 평가 기준

공식 정확도 산식은 공개되지 않았다. 로컬 개발에서는 다음 값을 대리 지표로 기록하되 공식 점수라고 표현하지 않는다.

- 완전일치율: `final_date`가 수동 검수 정답과 완전히 같은 비율
- 오탐: 날짜가 없거나 소비기한이 아닌데 날짜를 출력한 건수
- 미탐: 소비기한이 있는데 `NONE`을 출력한 건수
- 잘못된 후보 선택: 제조일자 등 다른 날짜를 선택한 건수
- `NONE` 정밀도와 재현율
- 오류 유형별 정확도: 회전, 흐림, 반사, 복수 날짜 등

검증셋에는 사람이 확인한 라벨만 정답으로 사용한다. OCR이나 규칙으로 생성한 미검수 결과를 정답으로 간주하지 않는다.

추가 수집 데이터는 소비기한이 표시된 일반 상품 데이터로 한정한다. 추가한 데이터마다 공개 데이터만으로 해결하기 어려웠던 오류 유형과 수집 필요성을 기록해 타당한 추가 수집 이유를 제시한다.

| 4-Core 2,400초 | 미검증 | 실제 OCR과 전체 실행 기록 없음 |
| 정확도 | 측정 불가 | 검수된 라벨셋과 실제 예측이 아직 없음 |

이 표의 `충족`은 확인한 정적 항목에만 적용한다. 실제 제출 가능 상태를 의미하지 않는다.

## 8. 비공개 평가 항목 및 팀 결정사항

공식 자료가 공개하지 않은 평가 세부사항과, 그 불확실성에 의존하지 않기 위한 팀 내부 처리 정책을 구분한다.

| 항목 | 공개 상태 | 적용 정책 |
| --- | --- | --- |
| 정확도 50점 계산식 | 비공개 | 공식 산식을 추정하지 않는다. 로컬에서는 완전일치율·오탐·미탐을 대리 지표로 사용한다. |
| 일부 필드 정답의 부분점수 | 비공개 | 부분점수를 기대하지 않는다. 날짜 네 필드가 모두 일관된 완전 정답이 되도록 검증한다. |
| 두 자리 연도 | 팀 결정 | `YY`를 `20YY`로 정규화한다. `25.12.04`는 `2025-12-04`, `26.03.11`은 `2026-03-11`이다. |
| 연도 숫자가 전혀 없는 날짜 | 예시 해석에 따른 팀 결정 | 네 자리 연도를 만들 근거가 없으므로 날짜 네 필드를 모두 `NONE`으로 처리한다. |
| 잘못된 `NONE` 판정 | 정확도 감점 | 소비기한을 인식할 수 있는데 `NONE`을 출력하면 미탐으로 기록하고 정확도 오류로 계산한다. |
| 추가 수집 데이터 | 팀 결정 | 소비기한이 표시된 일반 상품 데이터를 사용할 수 있다. 데이터마다 타당한 추가 수집 이유를 기록한다. |
| 비공개 입력 확장자 | 비공개·비차단 | 공개 데이터의 알려진 확장자를 대소문자와 무관하게 지원하고, 파일 수나 이름 범위를 하드코딩하지 않는다. |
| RAM·운영체제·스레드 세부 제한 | 비공개·비차단 | 공개된 Python 3.10·4-Core CPU·2,400초 조건만 계약으로 삼고 특정 미공개 환경에 의존하지 않는다. |

이 표의 팀 결정은 공식 채점 규칙이라는 뜻이 아니다. 공식 공지가 추가되거나 사용자가 명시적으로 변경할 때만 갱신한다.
