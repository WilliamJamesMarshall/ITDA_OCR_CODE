# 날짜 판정 정책 통합과 검증 결과

2026년 9월 10일

요청한 다섯 단계의 날짜 순서 선택과 DMY 기본값을 실제 OCR 실행 경로에 반영했다. 단위·계약 테스트는 통과했지만, 정확도 95% 목표는 미달이다. 기존 YMD 사진이 순서 근거를 얻지 못하고 DMY 기본값으로 바뀌는 회귀가 확인되어 운영 품질 달성 완료로 판단하지 않는다. 500장 공식 환경 속도 검증도 아직 남아 있다.

## 통합한 동작

- 숫자 날짜의 YMD·DMY·MDY 후보를 생성하고 달력 유효성을 동일하게 검사한다.
- 영어·한국어 순서 안내와 실제 년월일 단위를 우선한다. 분리된 안내는 같은 OCR 좌표계의 가까운 날짜에 연결한다.
- 인근의 같은 날짜를 풀어 쓴 기한 표기로 순서를 해소할 수 있다.
- 검증된 제품 규칙은 포장 식별 문구·순서·검증 출처를 가진 로컬 설정으로 적용한다. 실제 검증된 규칙 데이터는 아직 등록하지 않았으며 기본 목록은 비어 있다. 일련번호 예외나 국가 추정 규칙은 넣지 않았다.
- 앞 단계에서도 순서가 모호하면 유효 DMY를 선택하고 fallback_dmy 사유를 기록한다. 명확한 숫자의 단일 후보는 추가 OCR 없이 종료한다.
- 낮은 OCR 신뢰도, 문자 보정, 서로 다른 날짜 경쟁 등 숫자·대상 불확실성은 복구할 수 있다. 제조일만 있는 경우, 명시 안내 충돌, 불가능한 날짜, 누락 필드를 DMY로 만들어내지 않는다.
- 날짜 뒤 시각·로트 숫자 분리, 붙은 EXP 문구, 날짜 조각 병합과 부분 날짜 출력 계약을 보완·유지했다.
- 평가 입력 목록을 실행 전에 정하고 출력 누락도 오답에 포함한다. 정확도 95% 목표 통과 여부를 평가 결과에 추가했다.
- OCR 호출 수, 선택 사유별 건수, 모델 초기화 시간, 함수 진입부터 저장까지의 시간을 보고한다. 기존 다섯 제출 열은 유지한다.

## 검증 결과

### 기능과 회귀 검사

62개 테스트 통과. 새 정책의 세 순서 후보 생성, 명시 순서 우선, DMY 기본값, 좌표계 분리, 로컬 제품 규칙, 추가 OCR 없는 종료, 저신뢰 복구, 출력 누락 채점을 포함한다.

이전 테스트 중 근거 없이 두 자리 날짜를 YMD로 가정하던 사례는 새 정책과 충돌하므로, 구간 선택 기능을 검증하는 테스트에 명시적인 YY.MM.DD 안내를 추가했다. 그 대신 안내 없는 같은 유형이 DMY가 되는 테스트를 별도로 추가했다. 기존 이미지 정답이나 검수 라벨은 변경하지 않았다.

사용자 검수 441장의 기존 판독 숫자에 대해 441장 모두 검수 정답을 날짜 후보로 생성한다. 이는 사람이 읽은 숫자를 사용한 후보 생성 확인이며, 최종 선택 정확도 또는 이미지 OCR 정확도 100%가 아니다.

### 동일한 고정 OCR 증거를 사용한 비교

| 평가 기록 | 변경 전 | 변경 후 | 개선 | 회귀 |
|---|---:|---:|---:|---:|
| 추가 수집 386장 | 298/386, 77.20% | 284/386, 73.58% | 8장 | 22장 |
| 기존 352장 중 수동 확정 341장 | 307/341, 90.03% | 260/341, 76.25% | 0장 | 47장 |

양쪽에 동일하게 이전 실행의 전체 OCR 증거를 제공했다. 조기 종료·추가 OCR이 달라지는 실제 이미지 전체 재실행 정확도와는 구분한다. 기존 검증셋의 미확정 11장은 채점에서 제외했다. 사용한 기존 수동 라벨 원본의 SHA-256이 기존 평가 스냅샷과 일치함을 확인했다.

최종 비교에서 남은 회귀 69건은 모두 fallback_dmy 선택으로 발생했다. 즉 숫자를 읽었더라도 YMD를 선택할 앞 단계의 근거가 없으면 새 정책에 따라 다른 날짜가 출력된다. 기본값을 임의로 YMD로 되돌리거나 정답 일련번호를 조회해 이 회귀를 숨기지 않았다.

### 실제 이미지 재실행

두 평가 기록에서 사전에 일정 간격으로 선택한 24장을 로컬 Windows CPU와 기존 Paddle 모델로 실제 재인식했다.

- 최종 코드 결과: 14/24 정답, 실행 오류 0건.
- OCR 호출 55회, 그중 11장은 1회 호출로 종료.
- 스크립트 시작부터 import·모델 초기화·OCR 처리·진행 기록까지 약 84.25초.
- 평가 중 코드가 변경되지 않았고, 대상 원본 이미지 해시가 유지됨을 확인했다.

이 측정은 개발 PC의 소규모 동작 점검이다. Python 프로세스 생성부터 최종 제출 파일 저장까지를 재는 공식 500장 벤치마크가 아니며, 500장으로 환산해 속도 달성을 주장하지 않는다. 이 표본은 독립 블라인드 평가셋도 아니므로 전체 정확도를 대표하지 않는다.

## 현재 완료 범위와 다음 작업

파일별 단계가 아니라 판정·조기 종료·평가 계측을 한 기능 단위로 통합하고 검증했다. 원본 사진, 검수 문서, 기존 수동 라벨과 이전 평가 기록은 수정하지 않았다. 개발용 변경은 작업 트리에 반영했지만 정확도 목표 충족이나 운영 채택 완료는 아니다.

다음 작업은 있다.

1. **정확도 개선:** DMY 기본값 전에 실제 YMD·MDY 근거를 찾도록 순서 안내 인식·연결과 검증된 제품·포장 규칙을 구축한다. 숫자·대상 날짜 인식 오류도 함께 개선하고 기존 정답 회귀를 재검증한다. 현재 로컬 제품 규칙 데이터가 없는 점을 우선 해결해야 한다.
2. **정확도와 속도 공동 검증:** 동일 제품 변형이 개발셋과 섞이지 않은 독립 평가에서 95% 이상을 확인하고, 공식과 같은 4-vCPU 조건의 500장 초기화·입출력 포함 실측을 수행한다. 효과가 낮은 복구 경로는 정답 변화와 비용을 함께 비교해 축소한다. 2,400초는 타임아웃이며 단순 통과를 최적화 완료로 보지 않는다.

추가 수집·학습이나 새로운 모델 없이 현재 코드만으로 95%가 가능하다는 근거는 아직 없다. 이번 결과에서 그 목표를 달성했다고 보고하지 않는다.
