## 3. 기존의 무엇을 보존할 것인가

두 종류의 보호 자료를 분리한다.

1. **학습용 정상 복습 자료:** 기존 optimizer 역할의 승인 원본에서 기존 모델이 실제 전사를 맞힌 crop. 숫자 위치·글꼴·언어·인쇄 형태·길이·저화질·회차를 층별로 포함한다. 검증 역할 crop는 넣지 않는다.
2. **평가용 고정 보호 목록:** 기존 모델이 맞힌 각 year/month/day 필드와 올바른 NONE, 제조일 배제·날짜 선택의 중요 반례. 기존 5320개 정답 필드를 이미지별로 고정한다. 평가 원본 일부는 이미 학습에 노출됐으므로 독립 검증셋으로 부르지 않는다.

기존 모델도 틀릴 수 있으므로 모든 출력을 정답처럼 모방하지 않는다. 전사와 충돌하는 기존 출력은 보호 학습에서 제외하고 검토한다. “기존 최종 날짜가 맞음”만으로 같은 이미지의 모든 crop 전사가 정확하다고 간주하지 않는다.

기존 상품 그룹의 학습/검증 역할은 영구 유지한다. 내부 25crop가 1·3회에 치우친 한계는 별도로 보고한다. 새 검증 자료가 필요하면 기존 optimizer 그룹을 검증으로 바꿔 독립성이라 주장하지 않고, 미학습 상품 그룹의 별도 수집·승인을 요청한다. 이번 범위에 6회나 신규 자료 수집을 자동 추가하지 않는다.

## 4. 학습 목적과 변경 폭의 설계

첫 시도는 복잡한 기법을 모두 넣지 않고, **검증된 인식 오류 교정 + 정상 복습 + 제한된 파라미터 갱신**으로 설계한다.

- 오류 자료와 정상 자료를 원본 단위로 묶고 한 원본의 많은 crop가 손실을 독점하지 않게 한다. 예비안은 두 집합의 정규화된 손실 평균을 1:1로 시작하는 것; 아직 최적 비율도 승인값도 아니다. 실제 원본 수·오류 유형을 먼저 확정한다.
- 회차 216:500:500:394:500 비율은 모집단 보고 기준으로 유지하되, 교육 목적의 오류/보호 손실 비율과 별개로 관리한다. 회차·유형별 coefficient뿐 아니라 실제 loss와 gradient 크기도 기록한다. 기존 비율 승인을 새 설계에 자동 적용하지 않는다.
- 전사에 대한 CTC/NRTR 기본 감독은 유지하고 두 head의 크기·문자 길이 효과를 계측한다. 날짜 필드 성적을 학습 목적의 대리 지표인 CER보다 우선하는 후보 선정 기준으로 사용한다. 비미분 가능한 최종 선택 점수를 단순히 loss에 더했다고 주장하지 않는다.
- 기존 채택 checkpoint에서 시작한다. 검출기·영어 인식기·BN 통계는 고정한다. 한국어 backbone을 고정하고 출력 쪽 일부만 갱신하는 보수적 후보를 먼저 검토한다. 정확한 파라미터 이름과 개수는 Paddle 모델 구조 확인 후 명시한다. 부족할 때만 상위 블록을 별도 실험에서 연다.
- LR·학습 범위·데이터 혼합을 동시에 바꾸지 않는다. 짧은 중간 checkpoint에서 보호 성능을 비교하고 퇴행 시 멈춘다. 중간 검사 횟수·step·LR·예산은 실행 전 사용자에게 고정하여 보고한다. 1 epoch 완료 자체를 목표로 삼지 않는다.
- 정상 복습으로도 보존이 어렵다면 기존 모델의 문자 확률 분포를 기준으로 하는 지식 증류를 다음 대조 실험으로 검토한다. 승인 전사와 일치하는 학습 역할 crop에 한정하고, teacher 고정·시퀀스 정렬·추가 시간/메모리를 검증한다. 기존 오답까지 복제하지 않는다.

일부 층을 고정하는 방식은 [PyTorch 공식 전이학습 설명](https://docs.pytorch.org/tutorials/beginner/transfer_learning_tutorial), 이전 능력을 보존하며 새 능력을 학습하는 접근은 [Learning without Forgetting](https://arxiv.org/abs/1606.09282)을 참고한 제안이다. 이 프로젝트의 Paddle OCR에서 효과가 확인됐다는 뜻은 아니다.

저장 증강 1106장은 계속 제외한다. 원본의 승인 crop만 사용하고, 실시간 증강은 현재 없음에서 시작한다. 필요하면 별도 승인·대조 실험으로 추가하며 저장 증강 제외와 혼동하지 않는다. 24·25문자 crop의 실제 소비 및 특수 토큰 처리는 보완된 로더로 검증하고 묵시적 다른 crop 대체를 금지한다.

## 5. 실험 순서와 채택 조건 제안

1. 오류 원인 감사와 오류/정상/평가 보호 목록을 작성한다. 모호한 전사는 격리하며 기존 유효 승인 전체를 재요청하지 않는다.
2. 동일 최신 정답·원본 목록을 고정하고 기존 모델+기존 코드(A), 기존 모델+수정 코드(B)를 구분한다. 저장 trace 재생은 후보 생성·복구 전체를 재현하지 않으므로 코드 효과의 확정 전수 성적으로 취급하지 않는다. 필요한 새 실행은 별도 승인한다.
3. 개선 학습 후보(C)는 B와 동일 추론 코드로 평가하여 B→C에서 모델 효과를 분리한다. 한 번에 하나의 학습 설계 차이만 두고 이전 실패 후보의 효과를 합쳐 해석하지 않는다.
4. 내부 crop 검증과 고정 개발 보호 점검을 통과한 후보만 승인된 전수 평가로 보낸다. 전체 시간·추가 점검 시간은 학습 시간과 분리한다.
5. 최종적으로 사용자에게 획득과 손실 **둘 다** 제출한다. 회차별 총점 비퇴행과 중요 보호 필드 손실 0을 보수적 기준으로 제안한다. 모든 5320개 보호 필드 손실 0을 자동 반영 기준으로 두면 매우 엄격해질 수 있으나, 이를 완화하려면 손실 목록과 이유를 별도 승인받는다. 순증가만으로 손실을 숨기지 않는다.

최종 목표는 각 회차 95%, 정확도 year/month/day 정답 수/(3N), 실패·누락은 분모 유지, NONE 정답 득점이다. 216/394장은 각각 691.2/1260.8초, 500장은 전체 1600초 목표, 2400초 강제 종료와 구분한다. 노트북 초기화·저장·종료를 포함한다. 전수 평가는 1회 단독 CPU0–3 → 2·3회 → 4·5회 CPU0,1,4,5 / 2,3,6,7, 각 4스레드다. 통합 학습은 CPU0–3 한 작업이며 생존 작업과 중복하지 않는다.
