# 새 세션용 프롬프트

## 매 새 세션: 현재 단계와 실행 계획 보고

아래를 새 세션에 그대로 붙여 넣는다. 현재 단계는 실행 상태에서 매번 계산하며 1단계로 고정하지 않는다.

```text
C:\ITDA_OCR_CODE 프로젝트의 OCR 테스트·머신러닝 진행 상태를 확인하고, 이번 세션에서 수행해야 할 단계와 실행 계획을 먼저 보고해.

먼저 notebooks/docs/protocol/grouped_8_rounds.md와 notebooks/docs/training/grouped_operations.md를 읽고,
저장소 루트에서 다음 읽기 전용 명령을 실행해.
.\.labeling_paddle_env\Scripts\python.exe notebooks/project/run.py scripts.run_round_groups status
.\.labeling_paddle_env\Scripts\python.exe notebooks/project/run.py scripts.run_round_groups verify

새 실행 작업 공간은 C:\ITDA_OCR_WORKSPACE\grouped-8-rounds-v2야.
전체는 5단계, 8회차이며 1단계=1회 단독, 2단계=2·3회 병행,
3단계=4·5회 병행, 4단계=6·7회 병행, 5단계=8회 단독이야.

답변 첫 문장에 '전체 5단계 중 현재 ○단계이며, 이번 대상은 ○회차 [및 ○회차]입니다'라고 밝혀.
완료 증거가 모두 유효할 때만 다음 단계로 판정하고, 전부 완료됐으면 5단계 종료라고 말해.
각 회차가 최초 테스트 전/테스트 완료·채점 대기/사용자 검토 대기/원본 대응 대기/학습 승인 대기/
후보 학습·검증/통합 학습·검증/최종 선정 중 어디에 있는지 구분해.
같은 묶음의 한쪽만 끝났다면 완료한 쪽을 재실행하지 말고 남은 일을 정확히 보고해.

기존 sequential-8-rounds의 1회 테스트 및 remediation 실제 학습 기록도 연결해서 확인해.
오래된 training_started=false나 checkpoint 존재만으로 학습 미실행/단계 완료를 단정하지 마.
이미 유효하게 승인된 작업은 재승인을 요청하지 말고 승인 원문·보고서·범위·해시를 확인해.

다음 내용을 포함해 보고해:
1. 현재 단계/회차와 완료 판단의 실제 파일 근거, 이전 모델·후보 기각 이력.
2. 대상 이미지 범위/장수/초기 개발 노출/증강본 및 대응 원본 준비 상태.
   mapping_readiness와 원본 대응 조사 결과를 읽고, 출처 불명과 '출처 확인·원본 파일 부재'를 구분해.
   22건의 existing_product_references가 유효하면 기존 상품사진 연결 완료로 보고하되, reference_only 증강본을 학습 원본으로 취급하지 마.
   과거 삭제된 원본은 임의 복원·재번호화하지 말고 복원 결정과 기존 승인 상태를 확인해.
3. 사용할 코드·모델 경로와 해시. 기본 weights와 검증 bundle이 같은지.
4. CPU 0–3/4–7 배정, 4스레드, 오프라인·노트북 전체 시간·메모리 확인 계획.
5. 회차별 대표 보고서 경로와 기존 최초 결과 보존 방법.
6. 오답의 구조적 원인 분석·근본 해결을 두 회차에서 병행할 계획과 코드 사본 분리 방법.
7. 사용자 보고서 확인·피드백·명시적 승인 후 대응 원본과 승인 crop만 누적 학습하는 절차.
8. 이번에 실행 가능한 작업, 부족한 데이터/증거/승인, 예상 시간과 종료 조건.

2회는 초기 개발 499장+AMLT000263 1장, 3~8회는 초기 개발 미사용 이미지만 사용해.
테스트 증강 파일은 optimizer/내부 검증에 넣지 말고 원본 대응 미확정이면 해당 학습을 막아.
학습/검증 상품 그룹 역할을 영구 유지하고, 두 회차의 최초 테스트가 모두 끝난 뒤 학습해.
후보를 공용 가중치에 자동 반영하지 말고, 누적 회귀와 묶음 통합 검증·선정 후 다음 묶음으로 진행해.
1회 95%·평균3초, 2~8회 각각 95%·전체1500초, 전체2400초 강제 종료를 구분해.
8회 학습 후에는 종료하며 별도 독립 최종 성적이 없음을 밝혀.

이번 프롬프트는 상태 확인과 실행 계획 보고 요청이야. 새로운 정식 테스트·학습·가중치 변경은 시작하지 마.
문서·상태·실제 결과가 다르면 그 차이를 먼저 설명해.
```

## 보고받은 현재 단계의 최초 테스트 실행

```text
방금 보고한 현재 단계의 대상 회차 최초 테스트 실행을 승인한다.
보고한 정확한 이미지 목록·코드·모델과 실제 이 지시를 연결해서 실행하고 회차별 보고서를 각각 작성해.
한쪽의 기존 유효 결과를 다시 실행하지 말고, 상태와 해시가 달라졌으면 변경 내용을 먼저 보고해.
단독 단계는 CPU4 한 작업, 병행 단계는 CPU 0–3/4–7 두 작업으로 운영해.
기존 오프라인 검증이 이번 고정 사본·모델과 일치하지 않으면 먼저 재검증해.
실패·누락·시간 초과를 보존하고 보고하며, 완료 후 오답 원인과 원본 학습안을 제시해.
이 지시는 미래 결과에 대한 피드백이나 학습 승인이 아니야. 보고서 검토 후 별도로 학습을 승인할게.
```

## 검토한 보고서에 대한 학습 실행

```text
아래 지정한 보고서 버전을 확인했다. 피드백과 학습 범위는 다음과 같다.
- 대상 회차와 보고서 경로/버전: [실제 값]
- 피드백: [실제 의견, 또는 직접 확인한 뒤 '추가 의견 없음']
- 승인할 원본·그룹·crop·학습/검증 분할: [보고받은 자료]
- 시작 checkpoint·코드 사본·학습 config/epoch/LR/증강/BN: [검토한 설정]

위 범위의 회차별 후보 학습과 검증을 승인한다. 기존 검증 그룹은 optimizer에 넣지 말고
테스트 증강 파일 대신 대응 원본에서 승인된 crop만 사용해.
해당 묶음의 최초 테스트가 모두 끝났는지 확인하고, 두 회차 모두 학습 승인이 있으면 CPU를 나누어 실행해.
후보의 내부 검증·export·로딩 및 누적 회차 자동 재평가 결과를 각 대표 보고서에 구분해 보고해.
통합 학습과 다음 묶음 모델 선정은 그 검토안을 받은 뒤 별도로 승인하겠다.
```

통합 학습과 최종 선정도 운영 문서의 실제 review.json을 확인한 사용자 지시에 연결한다.
대괄호가 남은 문구, 템플릿 자체, 다른 회차 승인으로 실제 승인을 만들지 않는다.

## 두 후보 검토 후 통합 학습 승인

```text
현재 단계의 두 회차 후보 결과와 통합 검토서 [integration/review.json 실제 경로·버전]를 확인했다.
피드백은 [실제 의견]이다. 보고한 누적 승인 원본 합집합, 고정 그룹 분할,
통합 코드 사본과 설정 [실제 경로·버전]으로 단일 후보를 만드는 통합 학습과 누적 평가를 승인한다.
승인 근거가 가리키는 회차와 현재 단계가 일치하는지 먼저 보고하고 실행해.
후보별 기존 결과는 보존하고, 통합 결과를 두 회차의 대표 보고서에 각각 연결해.
이 승인은 다음 단계 진행이나 공용 가중치 교체 승인이 아니다. 선정은 결과를 확인한 후 결정하겠다.
```

## 단계 최종 선정 승인

```text
현재 단계의 최종 누적 평가 보고서 [evaluation/review.json 또는 retain_evaluation/review.json 실제 경로·버전]를 확인했다.
피드백은 [실제 의견]이며, [검증 후보 채택 / 검증된 이전 모델 유지 중 실제 결정]를 승인한다.
95%·시간 목표 미달이 있다면 [미달 내용과 수용 여부에 대한 실제 결정]을 적용해.
보호 정답 회귀·실행 오류·출력 형식 실패는 완료로 처리하지 마.
조건이 충족되면 이 단계의 완료 근거를 기록하고, 전체 5단계 중 다음 단계와 대상 회차의 실행 계획을 보고해.
다음 단계의 정식 테스트는 아직 시작하지 마. 5단계였다면 8회 학습·선정 종료와 최종 모델 경로를 보고하고 끝내.
```
