# date-fields-v1 — 사용자 지정 정확도·학습·출력 계약

실제 사용자 지시(2026-09-14): “500장 각각 연-월-일 개수 합치면 1,500개인데 이 중에 맞힌 게 몇 개인지 세는 것이다. 정확도 평가기준을 2회차 및 3회차 테스트 및 머신러닝을 포함해서 모두 이렇게 바꾸고 수정작업 시작해.” 이어 수정 완료 후 2·3회 온라인 재시험을 승인했다. 출처: 현재 작업 `01a09a56-750e-74b3-99c8-c132c5c1f384`. 별도 optimizer/모델 승인은 아니다.

- 모든 새 회차 테스트 및 최종 후보·통합 검증의 주 지표는 `field_correct / field_total`, `field_total=3N`. 500장은 1,500개, 95%는 1,425개 정답이다. 각 연/월/일은 같은 가중치다.
- 실제 CSV 열을 직접 비교한다. final_date에서 year/month/day를 복원해 점수를 부풀리거나 지우지 않는다. NONE 정답은 NONE 출력과 일치하면 득점한다. 누락/실패는 세 필드 모두 0점이고 분모는 줄지 않는다. 일부 필드 형식 오류는 그 필드 0점이며 형식 합격은 별도 차단한다.
- `exact_match_rate`와 `exact_matches`는 과거 비교용 보조 지표다. 95% 및 개발 100% 판정은 field_accuracy를 사용한다. 회차별 점수/시간을 독립 판단하며 묶음 평균으로 미달을 가리지 않는다.
- 내부에는 모든 필드 조합을 표현한다. 저장은 각 필드를 원본으로 삼고, 일부 NONE은 기존 방식의 하이픈 결합을 확장해 표기한다. 전부 NONE은 final_date=NONE. 외부 공지의 부분 final_date 표기 확인이 필요하면 필드를 버리지 않고 직렬화만 조정한다. 개별 필드가 알려지고 final_date=NONE인 부분 행도 내부 평가/검증은 지원한다.
- 공통 소비기한 후보의 확실한 필드를 유지하고 다른 날짜끼리 연/월/일을 섞지 않는다. 복구 partial 때문에 기존 full 증거를 무조건 지우지 않는다. 날짜 역할·문자 증거·순서의 불확실성을 따로 유지한다.
- 누적 후보 평가에 기존 필드 정답 보호를 추가한다. 기존 전체 정답 204건 등 보호도 계속 유지한다. 새 선정은 새 지표가 명시된 평가 증거가 있어야 하며 옛 승인/점수는 변경하지 않는다.
- 새 grouped 학습의 승인 crop pool에는 각 내부 검증 crop의 `date_fields: {year,month,day}`가 필요하다. 날짜 아닌 crop도 전부 NONE인지 사용자가 검토해야 한다. 전사만으로 정답 날짜를 만들어내지 않는다. 그룹별 optimizer/내부 검증 분리는 영구 유지한다.
- epoch checkpoint는 내부 검증 crop의 필드 정확도, 동률이면 micro CER/NED/이른 epoch 순으로 고른다. CTC 문자 손실·문자열 일치율은 보조 OCR 지표다. crop 성적을 전체 원본 N장 성적으로 부르지 않는다. 최종 모델·통합 후보는 누적 전체 이미지의 3N 기준으로 검증한다.
- 기존 frozen 학습 release/이력은 유지한다. 새 학습 release는 필드 정답 pool 해시·accuracy_policy를 승인에 연결한다. 정답 필드 주석이 없으면 해당 학습 준비를 막는다. 이미 승인된 과거 작업에 새 승인을 소급 요구하지 않는다.
- 현재 두 재시험은 각 P2+E2·4스레드(0,1,4,5 / 2,3,6,7), 온라인 로컬 모델, 전체 노트북 1,600초 목표/2,400초 강제 종료. UAC·방화벽 변경 없이 실행한다. 원본/라벨/기존 결과·실패 로그는 보존한다.

세칙별 과거 문서의 '날짜 전체 95%' 또는 '문자열 정확도 우선 checkpoint'는 이후 신규 grouped 작업에 적용하지 않는다. 과거 측정 기록은 당시 의미로 읽는다.
