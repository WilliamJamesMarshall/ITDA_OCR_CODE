# 날짜 줄 복구·역할 연결 후속 작업 상태

후속 정책 변경: 사용자가 한국 식품 문맥의 YMD 우선과 미확정 REVIEW 규칙을 추가 승인했다. 아래는 해당 정책 도입 이전 기록이며, 최신 내용은 [한국 식품 문맥 정책](<korean-market-policy-20260911.md>)을 따른다.

2026-09-11. 이 문서는 작업 기록이며 **전체 품질 목표 달성 또는 남은 작업 없음이라는 보고가 아니다.** 사용자의 요청에 따라 단계별 완료 보고 대신 변경·검증·보류 근거를 파일에 남긴다. 독립 500장과 `테스트용데이터`는 열람·검증·학습에 사용하지 않았다.

## 반영한 기능

1. **명시 누락과 부분 날짜의 종료 근거:** `003512`처럼 기한 항목에 직접 연결된 ‘표기하지 않습니다’가 확인될 때만 NONE으로 종료한다. 제조일밖에 인식되지 않았다는 사실만으로 종료하지 않는다. `003560`의 `03.21까지13:51`처럼 엄격한 부분 표기를 안정적으로 읽은 경우에는 `NONE-03-21`을 보존하고 종료한다. 시각의 숫자를 연도로 빌리지 않는다.
2. **조건부 소형 보조 인식:** 기존 인식이 성공한 줄이나 명확한 완전 날짜는 유지한다. 미해결 날짜형 줄 최대 2곳에만 영문·숫자 모델을 추가 적용한다. 두 개 이상의 안정 화면, 정렬된 날짜 숫자 평균 0.95 이상·최솟값 0.80 이상을 요구하고 강한 경쟁 읽기가 있으면 기각한다. 원문/실측 점수를 보존하며 모델 간 투표 가점을 만들지 않는다. 보조 인식 실패 시 먼저 성공한 기본 복구를 유지한다.
3. **인쇄 패널 경계와 해상도 대응:** 기존 픽셀 줄 복구가 실패하면 밝은 패널 윤곽 안쪽만 분석한다. 패널 밖 경계가 글자 줄이 되지 않도록 마스킹하고, 점 사이 간격은 표제 높이에 비례해 연결한다. 줄 비율을 기준으로 수평 보정하고 최대 2개 줄 전체가 안정적일 때만 채택한다. 기본 배치와 보조 배치는 각각 최대 4개 crop이며 기본 성공 시 보조 배치는 생략한다. `003489`와 `000080`은 이 유형의 개발 사례다.
4. **다른 확대 프레임의 명시 날짜 쌍:** 양쪽 날짜의 명시 제조/기한 역할, 원본 좌표, 같은 인쇄 형식, 가까우면서 서로 다른 줄이라는 조건이 충족될 때만 순서 근거를 연결한다. 로컬 crop 좌표를 서로 비교하거나 같은 줄의 상충 관측을 날짜 두 개로 쓰지 않는다. `000088`은 제조일을 보조 모델이 읽고 소비기한은 다른 확대 패스가 읽는 사례다.
5. **재현성과 실패 이력:** 새 가중치의 버전/해시와 오프라인 경로를 다운로드 스크립트에 추가했다. 실패한 기본 픽셀 박스와 새 보조 박스의 이력 번호를 분리했다. 진단 결과 저장의 일시적 Windows 오류에 대비해 검증 스크립트는 임시 파일 저장→교체와 제한된 재시도를 사용한다.

구체적인 임계값과 호출 순서는 [파이프라인 명세](<pipeline-spec.md>)에 있다. 파일 번호별 예외, 국가·브랜드만으로 YMD를 강제하는 규칙, 읽지 못한 숫자 치환은 추가하지 않았다.

## 검증 범위와 기록

- 이전에 쓰던 개발 34장에, 고정된 705건 저장 OCR 중 ‘첫 패스 날짜 후보 없음 + 유일한 기한 표제’ 조건을 만족한 25장을 합쳤다. 중복 제거 후 **55장**이다. 현재 결과가 좋은 사진만 골라 분모를 줄이지 않았다.
- 705건 저장 OCR 재생은 모델 재실행이 아니며 실제 55장 OCR과 합산하지 않는다.
- 동일 파일 해시의 입력에 시작 시점 코드와 변경 코드를 번갈아 적용한다. 이미지별 시간에는 모델 호출·전처리·판정 등이 포함되나 공유 초기화는 제외된다. 보조 모델의 지연 초기화는 실제 호출에 포함된다.
- 실제 제출 실행 관리 경로는 기존 14장을 별도로 확인한다. 이 경로의 전체 시간에는 작업 프로세스 시작/import·초기화·로딩·OCR·결과 저장이 포함된다. 평균 전체 시간과 OCR 호출 시간은 따로 3초/장과 비교한다.
- 최종 수치와 코드 해시는 [실제 55장 비교](<../../../artifacts/ocr-recovery-closeout-20260911/live.json>), [705건 재생](<../../../artifacts/ocr-recovery-closeout-20260911/cache.json>), [실제 제출 경로](<../../../artifacts/ocr-recovery-closeout-20260911/runner_report.json>), [최종 확인](<../../../artifacts/ocr-recovery-closeout-20260911/final_checks.json>)에 보존한다. 이 파일들의 코드 해시가 같은 실행 묶음인지 확인해야 한다.
- 중간 비교 `stopping_only_live.json`, `secondary_fixed_scale_live.json`은 서로 다른 코드 단계다. `interrupted_48_progress.json`은 저장 오류로 중단된 실행의 체크포인트이며 55장 완료 기록으로 사용하지 않는다. 저장 방식을 보강한 후 55장을 처음부터 재실행해 정상 종료했다. 작은 진단 실행에도 바깥쪽 2,400초 안전장치를 유지했다.

새로 맞힌 것은 `003489`, `000080`, `000088`이며 기존 정답 손실은 0장이다. 기존 34장의 정답은 모두 유지됐지만, 이를 확장 55장의 결과 대신 내세우지 않는다. 14장은 55장에 포함된 개발 부분집합이므로 합산하지 않는다. 14장의 장당 OCR은 3초보다 **0.355초**, 전체 시간은 **0.856초** 길다. 500장 환산 1,927.845초는 정규화 값일 뿐 실제 500장 측정이 아니며, `actual_500_timeout_met`는 미검증(`null`)이다. 1,500초는 목표이고 2,400초는 종료 제한이라는 계약은 바꾸지 않았다. 시간은 단회 로컬 실행값이며 다른 시점의 더 빠른 기록을 골라 최신 결과로 사용하지 않는다.

55장 필드별 일치는 연 **41→44/55**, 월 **44→47/55**, 일 **42→44/55**다. 실제 값이 있는 필드만 보면 변경 후 연 **40/51**, 월 **45/53**, 일 **38/49**가 맞았고 각 필드 6개씩 미출력이다. 실제 부재 필드는 연 4/4, 월 2/2, 일 6/6을 유지했다. 출력은 완전 41개·부분 6개·전체 NONE 8개, 형식 준수 55/55다. 필드 지표를 공식 부분점수나 전체 일치 95%로 바꾸어 해석하지 않는다.

자동 테스트 **233개**, 컴파일 검사, 공백 오류 검사, 55개 입력 해시 및 오프라인 모델 파일 **12개**의 고정 SHA-256을 확인했다. 실제 비교의 실행 오류와 저장 OCR/실제 비교의 기존 정답 손실은 모두 0건이다. 검증의 운영 코드 해시는 `pipeline.py=652ef570…`, `date_extraction.py=568f5ed2…`, `line_recovery.py=d81c688d…`이며 전체 값은 연결된 JSON에 있다. `runner_report.json` 자체에는 코드 해시가 없어 `verified.json`의 실행 전후 해시·입력 확인 기록과 함께 읽어야 한다.

## 미해결 근거를 숫자 문제와 구분

[잔여 오류 진단](<../../../artifacts/ocr-recovery-closeout-20260911/remaining_diagnosis.json>)은 원본에서 읽은 날짜 문자열만 진단 입력으로 제공했을 때 현재 정책이 어떤 값을 만드는지 구분한다. 이는 모델의 성과나 학습 정답 생성이 아니다.

- `000018`, `000033`, `000034`, `000061`, `000255`, `000256`, `000305`: 단일 두 자리 연도 날짜에 대해 확인한 사진 안에서 순서 근거를 확보하지 못했다. 예를 들어 `000033`의 `26.06.17`은 DMY 기본값이면 `2017-06-26`, 고정 검수 정답은 `2026-06-17`이다. 숫자만 잘 읽는 것으로 이 차이가 해소되지는 않는다.
- `003507`, `000090`, `000191`, `000210`: 네 자리 연도의 날짜가 실제로 보이지만, 미검출·겹친 로트/시각 줄·곡면/번짐 때문에 읽지 못하는 개발 사례다. 보조 인식기를 추가했다고 이 유형이 모두 해결된 것은 아니다.
- 기존 고정 OCR 및 2,042건의 보관된 원문 기록에서 빼빼로/ABC와 명시 YMD 안내가 함께 있는 사례를 추가 검색했다. 원본 `001080`의 누드초코 빼빼로 묶음 포장에는 연·월·일 안내가 실제로 있다. 하지만 이 2021년 묶음 포장을 현재 다른 종류/버전의 포장에 일괄 적용할 근거는 확인하지 못했으므로 제품 규칙으로 등록하지 않았다. 이는 전체 3,352장에 그런 근거가 없다는 전수 확정이 아니다.

필요한 것은 해당 날짜가 속한 **동일 제품·판매시장·포장 버전**을 식별하고 그 표기 순서를 확인할 자료다. 다른 상품이 배경에 함께 찍힌 경우 배경의 브랜드/순서 안내를 대상 상품에 적용해서는 안 된다. 검수 정답을 조회하거나 한국어라는 이유만으로 YMD로 바꾸지 않는다.

## 보완 학습 자료의 준비 상태

[학습 자료 출처 점검](<../../../artifacts/ocr-recovery-closeout-20260911/training_readiness.json>): `학습대상데이터`의 기존 매핑 2,610개 중 **705개는 고정 개발 입력과 동일 해시의 복사본**이다. 이 705개를 제외한 1,905개는 후보일 뿐 학습 승인된 원문/영역 주석 자료가 아니다. 동일 해시 제외만으로 같은 상품·포장 그룹까지 분리되었다고 볼 수도 없다.

보완 학습을 진행하려면 남은 후보의 실제 날짜 줄/표제 다각형, 구분자·시각·로트를 포함한 원문, 가려짐/부재 구분, 동일 상품/포장 그룹을 확인해야 한다. 이번에는 원본·정답 라벨을 수정하거나 고정 개발 이미지를 학습에 넣지 않았다. 미검수 OCR 문자열을 정답으로 확정해 학습시키지 않는다.

## 시험했으나 반영하지 않은 것

- 모든 날짜 줄을 영문 모델로 바꾸는 방식: 일부 기존 좋은 숫자/한국어 역할 근거를 잃거나 잘못된 부분 문자열을 채택할 위험이 있어 채택하지 않았다. `english_auto_probe.json`은 첫 패스 입력의 진단이지 최종 파이프라인 정확도 비교가 아니다.
- 인쇄 표제의 위치만으로 검색 영역을 넓힌 시험: `소비기한` 머리표와 ‘상단 표시일까지’를 활용한 5개 개발 사례의 제한된 실험에서 최종 정답 추가를 확인하지 못했다. 비용을 추가하는 이 변경은 운영 코드에 반영하지 않았다. `prefix_probe_unadopted.json`과 `prefix_probe.json`에 기록했다.
- 수동으로 자른 날짜 영역에 대한 소형 모델 비교는 영역 입력을 통제한 진단이다. 실제 자동 검출 성능으로 세지 않았다. 추가로 `region_oracle_probe.json`에서 남은 네 자리 연도 4장의 수동 근사 영역에 사각형/다각형 보정·대비·수평 축소를 비교했다. `003507`은 05/06, `000090`은 2026/2036, `000191`은 05/06, `000210`은 20/29 또는 한국어 접미사의 숫자 오독이 변형별로 남는다. 곡면/겹침이 있어 근사 다각형도 완전한 줄 분리 정답은 아니다. 임계값을 낮추거나 정답에 맞는 변형만 고르는 변경은 반영하지 않았다. 이 영역 주석은 운영 규칙이나 학습 승인 자료가 아니다.

## 계속 진행하기 위한 입력 조건

남은 일이 없어진 것은 아니다. 반복적인 숫자 치환이나 브랜드 일괄 YMD 대신 다음 근거가 필요하다.

1. 순서 근거 부족 7장은 동일 제품·판매시장·포장 버전의 표기 안내 사진 또는 제조사 근거를 확보한 뒤 적용 범위를 검증한다. 현재 DMY 마지막 기본값과 고정 검수 정답 중 어느 하나를 몰래 바꾸지 않는다.
2. 곡면·겹친 줄 4장을 포함한 인식 보완은 원문/줄 경계가 검수된 개발 주석과 별도 학습 후보의 상품 그룹 분리를 먼저 갖춘다. 보완 모델을 만들 경우 기존 개발 705건 및 별도 테스트 자료를 학습에서 제외하고 비교한다. 현재 근사 영역 4장만으로 보완 학습 효과를 입증할 수 없다.
3. 위 근거로 변경한 경우 동일 개발 입력에서 기존 정답 손실·문자/필드 오류·장당 OCR 및 전체 시간을 다시 확인한다. 독립 500장 검증은 이 세션의 다음 작업으로 넣지 않는다.
