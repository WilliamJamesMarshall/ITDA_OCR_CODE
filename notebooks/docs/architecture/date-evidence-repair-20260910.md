## 적용한 기능 묶음

판정 로직·실행 흐름·양성/음성 테스트를 기능 단위로 함께 수정했다. karpathy-guidelines에 따라 실제 사진/OCR 기록에서 확인된 문제만 일반 규칙으로 반영했고 일련번호·국가·브랜드만으로 정답을 맞히는 예외는 추가하지 않았다.

1. **인쇄된 근거 인식과 연결**: `연.월.일`, 반복 글자 `년년.월월.일일`, 마지막 필드가 가려진 `년년월월`을 처리한다. 소비기한의 별도 표기 지시와 한 개의 대상 날짜가 있으면 먼 안내도 연결한다. `EXP04SEP22`/`EXPO4SEP22` 및 같은 기한의 월 이름 대응 날짜를 처리한다.
2. **날짜 종류와 순서의 결합 판단**: 가까운 동일 형식의 제조/시작·기한/종료 쌍에 한해 시간 순서가 가능한 해석을 비교한다. 두 가지 이상이면 결정하지 않는다. 두 날짜와 두 역할 문구의 수직 순서를 함께 대조하여 비스듬한 사진의 최근접 연결 오류를 줄인다.
3. **잘못된 날짜 조합 방지와 종료 상태 분리**: 부분 날짜에서 시각/로트 숫자를 연도로 빌리는 조합을 차단한다. `digits_confident`, `order_resolved`, `stop_ocr`를 구분한다. 숫자는 명확하고 순서만 불명확한 경우 DMY로 출력하고 더 읽지 않는 정책은 유지한다. OCR 모델·복구 횟수·제출 열은 늘리거나 바꾸지 않았다.

우선순위는 명시 순서 → 유일하게 가능한 날짜 → 동일 기한의 명시 대응 날짜 → 조건을 만족하는 날짜 쌍 → 검증된 제품 규칙 → DMY 기본값이다. 제조일만 있는 경우나 없는 연도에는 기본값을 적용하지 않는다. 제품 규칙 인터페이스는 유지하되, 다른 촬영/포장에서도 검증한 실제 규칙이 없어 기본 등록 목록은 여전히 비어 있다.

### 실제 이미지 재실행

저장 증거에서 개선된 15장을 의도적으로 골라 실제 PaddleOCR를 다시 실행했다. 이미지 SHA-256으로 동일성을 확인하고, 각 이미지 처리 직전/직후 및 실행 전후 코드 해시를 검증했다.

- 15장 모두 정답 재현.
- 13장은 최초 OCR 1회로 종료.
- 총 OCR 호출 24회. 부분 날짜 1장은 기존 복구 단계 9회를 사용했다.
- 스크립트 시작 이후 초기화·입력 확인·OCR·진행 로그 저장까지 **35.02초**. 최종 보고서 파일 저장은 이 타이머 이후다.
- 개선 사례의 재현 검사이므로 100% 일반 정확도나 500장 처리시간으로 환산할 수 없다.

중간 24장 표본 실행 중 별도 데이터 재번호 작업이 발생했다. 같은 파일명이 다른 이미지에 재사용된 것을 해시 검증에서 확인했으므로 해당 실행의 14/24 및 84.50초는 **검증 근거에서 제외**했다. 원본 정리 작업에는 개입하지 않았으며, 이후 위 15장 검사는 내용 해시로 다시 찾아 수행했다. 그 첫 시도에서는 14/15였고, 실제 OCR가 `년년.월월`의 점을 누락한 한 건을 확인하여 구분자 없는 반복 안내를 지원한 뒤 최종 15/15를 재검증했다.
