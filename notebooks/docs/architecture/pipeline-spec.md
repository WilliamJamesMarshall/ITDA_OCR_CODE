# 소비기한 OCR 파이프라인 설계

## 1. 목표와 성공 기준

비공개 평가 이미지 500장을 Standard 4-Core vCPU에서 처리한다. 2,400초는 목표 시간이 아니라 타임아웃 상한이다. 전체 OCR의 최종 날짜 완전일치율 95% 이상과 평균 3초/장(500장 1,500초)을 내부 목표로 한다. 1,500초 소프트 목표를 넘겨도 2,400초 강제 종료까지 계속하며, 목표 달성은 독립 평가와 실측 전까지 선언하지 않는다. 입력 수량·파일명·상품 배치를 가정하지 않고, GPU·유료 API·추론 중 네트워크를 사용하지 않는다.

내부 합격 기준은 다음과 같다.

- 전체 날짜 완전일치율 95% 이상. 정답 확정 500장 기준 최소 475장 정답
- 초기화·입출력을 포함한 500장 실제 시간을 측정하고 단순 2,400초 미만을 최적화 완료로 간주하지 않음. 이전 1,800초 환산 기준은 새 속도 목표를 대신하지 않음
- 지원 이미지마다 정확히 한 행 생성
- 이미지 단위 오류가 전체 실행을 중단하지 않음
- 실행 중 다운로드 0건, 외부 API 비용 0원
- 수동 확정 라벨에 대한 `final_date` 완전일치율 우선

## 2. 모델 결정

### 채택

| 단계 | 모델 | 이유 |
| --- | --- | --- |
| 기본 | `PP-OCRv5_mobile_det` | 대부분의 정상 이미지에서 가장 낮은 CPU 비용 |
| 복구 | `PP-OCRv6_small_det` | 작은 모델 크기로 server v5보다 공개 검증 정확도와 속도가 모두 우수 |
| 인식 | `korean_PP-OCRv5_mobile_rec` | 한국어·영문·숫자를 한 모델에서 처리하며 CPU 비용이 낮음 |
| 조건부 줄 복구 | `en_PP-OCRv5_mobile_rec` | 기존 인식으로 읽지 못한 숫자·영문 월 줄만 추가 확인. 검출기는 추가하지 않음 |

PaddleOCR 공식 표의 수치는 서로 다른 평가셋 간 직접 비교가 제한되지만, v6 small은 정확도와 효율의 균형을 목표로 한 9.6MB 검출 모델이다. 최종 결정은 공식 표가 아니라 이 프로젝트의 동일 검증 구간 A/B 결과로 내렸다.

## 3. 실행 흐름

```text
입력 탐색 및 EXIF 방향 보정
  → PP-OCRv5 mobile 기본 추론
  → 날짜 줄 최대 2곳 × 3개 화면 인식 전용 재확인(검출 재실행 없음)
  → 그중 미해결 숫자 줄에만 영문·숫자 소형 인식기로 동일 화면 재확인(최대 6개 crop)
  → 날짜 후보가 없고 독립 기한 표제가 유일하면 표제 주변 확대 검출 최대 1회
  → 그래도 날짜 미검출이면 밝은 표제 왼쪽 패널의 납작한 줄 최대 2곳 × 2개 비율 보정 화면 인식
  → 날짜 조각 ROI 최대 2개 확대 재추론
  → CLAHE 전체 이미지 재추론
  → PP-OCRv6 small 조건부 복구
  → 날짜가 없거나 부분 날짜만 남고 원본 OCR가 희소하거나 날짜 조각이 보이면 겹치는 4개 타일 추론
  → 후보 병합·달력 검증·문맥 점수화
  → YYYY-MM-DD, NONE-MM-DD, YYYY-MM-NONE 또는 NONE
  → submission.csv 생성
```

각 OCR 패스의 증거로 날짜 종류와 순서를 구분한다. **2026-09-11 사용자 첨부 규칙을 적용한 기본 실행**은 명시 순서·대응 날짜·명시 제조일/기한 쌍·검증된 포장 규칙을 우선하고, 남은 두 자리 날짜는 한국 식품 기한 문맥에서 YMD를 우선한다. 국가/형식이 여전히 불분명하면 DMY로 찍지 않고 `REVIEW_REQUIRED`로 남긴다. 한국 문맥에서 YMD가 달력상 불가능하면 유효한 DMY가 있더라도 자동 전환하지 않는다. 숫자가 명확하고 순서만 미확정이면 추가 OCR 없이 보류로 종료할 수 있다. 숫자 저신뢰·문자 보정은 복구 대상이다. 명시 부분 표기의 종료 조건과 복구 모델 지연 초기화는 유지한다. 상세 적용 범위는 [한국 식품 문맥 정책](<korean-market-policy-20260911.md>)에 있다.

### 기본 추론 설정

- CPU 및 MKL-DNN 활성화, 스레드 4개
- 긴 변 최대 1,600px
- detection threshold 0.25, box threshold 0.40, unclip ratio 1.8
- recognition threshold 0.15
- 문서 펼침·문서 방향·텍스트 줄 방향 분류 비활성화
- 모델 이름과 로컬 디렉터리를 모두 명시

### 조건부 전처리

- 보조 줄 인식: 기본 줄 복구가 성공한 관측과 원래부터 명확한 완전 날짜는 변경하지 않는다. 여전히 파싱되지 않거나 문자 보정이 필요한 줄에만 기존 3개 화면을 영문·숫자 인식기로 확인한다. 같은 후보에 적어도 2개 안정 화면이 필요하며, 정렬된 날짜 숫자 평균 ≥0.95·최솟값 ≥0.80을 추가 요구한다. 경쟁하는 강한 화면이 있으면 보류한다. 원문 점수를 낮추거나 두 모델 일치 가점을 더하지 않는다. 보조 실패는 `secondary-recognition-error` 결정에 기록하고 먼저 성공한 기본 복구를 보존한다. 같은 줄 복구 패스의 시간에는 필요 시 보조 모델 지연 초기화까지 포함된다.
- 패널 경계 보완: 기존 밝은 패널의 줄 검출/인식이 블록 전체를 복구하지 못한 경우에만 패널 윤곽 안쪽 마스크와 수평 투영을 사용한다. 비스듬한 패널 밖 경계를 제외하고 점 사이 빈 간격을 표제 높이에 비례해 연결한다. 폭/높이 ≥4인 최대 2개 줄을 목표 줄 비율 4.8·5.2에 맞춰 수평 보정한다(확대 상한 1.0·1.08). 숫자 평균 ≥0.95·최솟값 ≥0.80, 두 화면 일치, 블록 전체 성공을 요구한다. 기존 픽셀 줄 복구가 성공하면 추가 호출은 없고, 실패 시 보조 배치 최대 4개 crop을 더 처리한다. 새 줄은 최대 2개이며 파일 번호/정답값은 사용하지 않는다. 실패한 기본 박스와 보조 박스는 서로 다른 이력 번호를 쓴다.
- 명시 누락/부분 종료: 제조일만 존재하고 같은 표의 기한 항목에 고신뢰 `표기하지 않습니다`가 직접 연결될 때 `expiry-not-printed`로 종료한다. 단순히 기한이 읽히지 않았다는 이유로 NONE을 확정하지 않는다. `MM.DD까지`와 선택적 별도 시각의 엄격한 부분 표기를 안정적으로 재인식하고 날짜 문자 평균 ≥0.90·최솟값 ≥0.70이면 연도를 만들지 않고 부분 출력 후 종료한다. 시각 숫자는 날짜 문자 점수에서 제외한다. 훼손된 완전 날짜, 제조일 전용 생략 안내, 조건문, 경쟁 기한은 빠른 종료를 막는다.
- 프레임 간 명시 쌍: 서로 다른 확대 패스의 날짜도 두 관측의 유효한 원본 좌표와 명시 제조/기한 역할이 모두 확인되고 같은 형식의 서로 다른 가까운 줄이면 시간 선후로 순서 근거를 연결한다. 확대 이미지의 로컬 좌표끼리 비교하지 않는다. 좌표 없음·같은 줄의 충돌·다른 상품의 먼 날짜·숫자 보정이 필요한 날짜는 이 경로를 사용하지 않는다.

- 미검출 점 인쇄 줄 복구: 표제 확대 검출에도 날짜 후보가 없을 때만 적용한다. 유일한 고신뢰 수평 기한 표제 왼쪽의 밝은 패널에서 픽셀 성분으로 최대 2개 납작한 줄(폭/높이 ≥8)을 찾고 가로 0.4·0.45배 화면을 인식한다. 두 화면의 원문 날짜 후보 집합이 같고 줄 점수 ≥0.85, 정렬된 날짜 숫자 평균 ≥0.90·최솟값 ≥0.70일 때만 채택한다. 두 줄 중 하나라도 불안정하면 블록 전체를 보류한다. 날짜 순서는 기존 표제·달력·명시 쌍 규칙으로 판단하며 비율 보정에서 YMD를 강제하지 않는다. 추가 호출은 최대 4개 crop의 배치 인식 1회이며 실패하면 기존 전체 이미지·타일 복구를 유지한다.
- 반복 종료 보완: 주변 문장의 역할 단서는 OCR 점수 0.70 이상에서만 반영한다(날짜 자체의 인라인 근거를 지우지 않음). 명확한 독립 날짜 두 개에 비날짜 문장을 붙인 병합 관측은 새로운 숫자 불확실성으로 취급하지 않는다. 모든 병합 후보가 같은 원문 날짜·값·원본 멤버로 설명되고 독립 날짜 점수 ≥0.95이며 명시 제조일 충돌이 없을 때만 기존 날짜 쌍 조기 종료를 허용한다. 새 날짜 조각·제3의 날짜·상충 표제는 계속 복구한다.
- 날짜 줄 재인식: `enable_line_recovery=True`가 기본값. 검출된 유효 좌표의 짧은 날짜형 줄만 최대 2곳 선택하고 대비 보정/작은 여백 화면을 기존 인식기로 배치 처리한다. 문자 정렬이 확인될 때만 날짜 구간의 문자 평균·최솟값을 기록한다. 같은 모델 화면의 일치는 안정성 검사이며 독립 투표가 아니다. 채택 결과는 기존 한 관측의 활성 문자열을 교체하고 원문·모든 화면·채택 이유는 trace에 남긴다. 복구 실패 시 기존 결과를 유지한다.
- 역할 연결: 일반 제조시설 설명과 제조일을 구분하고 원본 박스가 엄격하게 겹치는 다른 패스의 역할만 전달한다. 충돌은 보류한다. 명시 부분 소비기한은 무관한 완전 날짜보다 우선할 수 있다. 해석을 마친 근접한 두 무표제 날짜에만 나중 날짜 정책을 적용하며 550일을 상한으로 쓰지 않는다. 별개 블록·세 날짜·명시 소비기한이 있으면 이 신규 정책으로 덮지 않는다.

- ROI: 숫자 4개 이상과 날짜 구분자를 포함한 상위 2개 박스 주변을 넓게 crop하고 작은 crop만 최대 3배 확대
- CLAHE: 원본에서 명확한 날짜가 없을 때만 적용
- 타일: 원본 OCR 라인이 32개 이하이면서 날짜 조각이 보이거나 라인이 5개 이하일 때만 62% 크기의 네 모서리 타일 사용
- 강한 이진화·adaptive threshold: 표본 복구 0건으로 제외

## 4. 날짜 후보 생성과 선택

지원하는 핵심 형식은 다음과 같다.

- `2026.05.29`, `2026/05/29`, `2026-05-29`, `2026 05 29`
- `2026년 5월 29일`, `29 MAY 2026`
- `26.05.29`, `260529`, `20260529`
- OCR가 분리한 `2026.` + `05.` + `29까지`

`O→0`, `I/l/|→1`, `Z→2`, `S→5`, `B→8` 치환은 날짜 모양 문자열 안에서만 시도하고 보정 여부를 남긴다. 원문·LOT는 덮어쓰지 않는다. 월별 말일과 윤년을 검사한다. 새 정책의 `YY→20YY`를 지원하도록 연도 상한은 2035에서 2099로 바꿨다. 현재 날짜보다 과거라는 이유로 거부하거나 현재 시점과 가깝게 숫자를 바꾸지 않는다. 이는 임의의 모든 연도 표기를 새로 지원한다는 뜻은 아니다.

명시된 `MM/DD/YY`, `DD/MM/YY`, `YY/MM/DD`, 한국어 순서 표기와 실제 년·월·일 단위를 우선한다. `연.월.일`, `년년.월월.일일`과 마지막 필드가 가려진 `년년.월월..`도 처리한다. 분리된 안내는 같은 OCR 좌표계의 가까운 날짜에 연결한다. 예외적으로 소비기한의 `별도/후면/상단 표기` 지시가 있고 같은 좌표계에 날짜 대상이 하나뿐이면 떨어진 안내도 연결한다. 여러 날짜가 있거나 충돌하는 안내를 전역 적용하지 않는다. 숫자 토큰은 유효한 YMD·DMY·MDY 후보를 먼저 만든다. `소비기한 26.04.24`는 수입 등 반대 문맥이 없을 때 한국 식품 문맥 정책으로 `2026-04-24`를 선택한다. 문맥 없는 `20-06-21`은 새 기본 실행에서 보류이며 `YY-MM-DD` 안내가 있으면 `2020-06-21`이다. `08/18/21`처럼 유일한 달력 해석은 유지하되, 명시/시장 순서와 달력 제약이 충돌하면 다른 순서로 구제하지 않는다.

`EXP04SEP22` 및 숫자 한 자리의 O/0 오독을 처리한다. 가까운 동일 기한의 명시 날짜·월 이름 날짜와 숫자 날짜의 값이 일치하면 대응 근거로 사용한다. 제조일 또는 다른 OCR 좌표계의 날짜를 대응시키지 않는다.

제조/시작과 기한/종료 역할이 명시된 가까운 날짜 쌍은, 자릿수와 구분자가 같고 판독 신뢰도가 높을 때에만 동일 순서라는 제한된 가정을 적용한다. 가능한 공통 순서 중 시작일 < 종료일을 만족하는 것이 하나뿐이면 `labelled_date_pair`로 기록한다. 두 해석 모두 가능한 경우 시장 문맥 또는 보류 단계로 내려가며, 무표기 날짜 두 개·저신뢰 문자·서로 다른 형식에는 이 순서 규칙을 적용하지 않는다. 이 단계는 최대 보존기간이나 현재 연도를 가정하지 않는다.

분리된 `부터/까지`는 두 날짜와 두 역할의 수직 순서·거리·간격을 블록으로 대조하여 기울어진 촬영의 일대일 연결을 보완한다. 경쟁하는 날짜나 역할이 추가되면 이 연결을 사용하지 않는다. 단순 최근접 연결보다 강한 이 근거는 기존 역할 점수 계산에 전달된다. 대상 상품 전체를 분할하는 기능이나 OCR 패스 간 좌표 변환을 구현한 것은 아니다.

제품별 규칙은 `PipelineConfig.product_date_rules`의 `ProductDateRule`로 전달한다. 포장 식별 문구들의 동시 일치, 적용 순서, 검증 출처를 요구하며 명시 안내와 달력상 유일한 후보보다 후순위다. 기본 규칙 목록은 비어 있다. 현재 441장의 순서 라벨만으로 제품 식별 근거를 검증한 것은 아니므로, 국가별 추정이나 일련번호 조회 규칙은 넣지 않았다. 서로 충돌하는 제품 규칙은 강제 선택하지 않는다. 내부 후보에는 order와 order_reason을 보존한다.

`4 14:06` 같은 시각이나 로트 숫자에서 날짜 필드를 빌리지 않는다. `YYYY MON DD`와 `MON YYYY`를 지원하되 `MAY 2021`을 `MAY 20 21`로 잘못 분할하지 않는다. 순서 기본값은 실제 날짜 없음·숫자 판독 실패·제조일만 있는 경우·부분 날짜의 누락 필드에는 적용하지 않는다.

문자 처리 보완: `2106/2022` 같은 붙은 일·월과 명시 연도, `2212/21` 같은 단일 슬래시 날짜를 지원한다. 짧은 연도의 붙은 날짜를 점·하이픈까지 확대하여 주소나 부분 연도로 오인하지 않는다. `2021.1 1.26`의 월 내부 공백, 네 자리 연도를 포함한 이중 구두점, `04/0ct2021`, 연도 위치의 `2U25`/`2D21`, 끝자리 `$`의 제한적 보정은 수리 여부를 남긴다. `E`를 무조건 2 또는 6으로 바꾸지 않는다. 겹친 로트 조각보다 완전한 네 자리 연도 날짜를 보존하고 영문 월 이름 대조표를 날짜로 읽지 않는다.

연도가 없으면 `NONE-MM-DD`, 일이 없으면 `YYYY-MM-NONE`으로 보존한다. 연도 없는 2월 29일은 가능한 월·일 조합으로 인정하되 연도를 추정하지 않는다. 잘못된 완전 날짜의 일부 숫자를 떼어 부분 날짜로 구제하지 않는다. 온도·규격·제조일·로트 번호 등은 부분 날짜로 채택하지 않는다. 날짜 조각 뒤 독립된 `HH:MM` 시각을 두 자리 연도의 날짜로 결합하지 않는다. 예를 들어 `03.31 01:31`은 `2031-01-31`이 아닌 `NONE-03-31`로 보존한다.

숫자 `MM/YYYY`, `MM.YYYY`, `MM-YYYY`도 일자 없는 부분 날짜로 지원한다. 원문에 없는 일자를 1일이나 말일로 채우지 않는다. `월년순`, `MM/YYYY`, `Best before end` 같은 부분 날짜 안내가 같은 OCR 좌표계에서 연결되고 숫자 신뢰도 ≥0.90, 안내 신뢰도 ≥0.75, 경쟁 날짜 없음 조건을 만족할 때 `explicit-partial-date`로 조기 종료한다. 완전 날짜용 `DD/MM/YYYY` 안내를 부분 날짜 안내로 쓰지 않는다. 그 외 부분 날짜는 기존 복구 단계를 유지한다.

후보 점수는 OCR 신뢰도, 네 자리 연도, 소비기한 키워드, `까지`, 공간 근접도, 다른 패스의 일치를 가점하고 제조/생산/`부터`, 전화번호·바코드 문맥과 OCR 문자 수리를 감점한다.

줄 병합과 근접 문맥 판단은 같은 `(source, variant)` OCR 패스 안에서만 수행한다. ROI·타일의 좌표를 원본 좌표처럼 비교하지 않는다. 패스 간 같은 날짜의 일치 가점은 유지한다.

제조일과 소비기한 후보가 함께 있을 때는 전체 이미지에서 가장 큰 날짜를 고르지 않는다. 같은 OCR 좌표계의 가까운 두 후보가 1–550일 간격이고 제조·기한 문맥 또는 비슷한 신뢰도의 무표기 날짜 쌍으로 뒷받침될 때만 종료일을 우선한다. 동일 숫자 구간의 대안 해석은 두 개의 인쇄 날짜로 취급하지 않는다. 분리된 `부터/까지` 문구는 가까우면서 짝의 다른 날짜보다 더 가까운 후보에 연결하며 명시된 종료 문맥을 우선한다. 점수 비교는 패스 간 일치 가점이 반영된 합산 점수끼리 수행한다. 주변 제조 문맥만으로 복구를 조기 종료하지 않는다. 2024년 이상 후보만 따로 고르던 규칙은 제거했다. 낮은 신뢰도의 제조일·기한 쌍을 보존하는 기존 테스트도 유지한다.

## 5. 실패 정책과 출력 계약

2026-09-11 추가된 계측은 날짜 파싱 전에 원문·검출 다각형·영역 ID·원본 역변환을 별도로 보존한다. 인식 결과에서 빠진 검출도 저장하지만 기존 후보/확대 입력에는 섞지 않는다. 기하학적 대응 가설과 역할 어휘 단서는 아직 날짜 선택에 사용하지 않는다. CSV와 별도의 `.trace.jsonl`에 패스 시작/완료·오류를 저장하며 자세한 범위는 [계측 구현 결과](<ocr-region-trace-20260911.md>)를 참조한다. 이 절 이전의 후보 점수/기간 선택 설명은 그대로 동작한다.

`DateSelection.digits_confident`(숫자 판독), `order_resolved`(순서 근거), `stop_ocr`(실행 중단)를 구분한다. 명확한 숫자의 순서가 미확정이면 추가 OCR 없이 REVIEW로 종료할 수 있다. 기존 `confident`는 `stop_ocr`의 호환 이름이며, 정답 확률을 뜻하지 않는다. `policy_details`에는 정책 버전, 원문, 시장/선택 근거, 날짜 순서, 시각/코드, 명시 제조일, `SELECTED`/`REVIEW_REQUIRED`/`NOT_FOUND` 상태를 기록한다. CSV 열을 추가하지 않고 trace에 보존하며 REVIEW의 최종 날짜는 `NONE`이다. 저수준 `select_date(..., context=None)` 및 `PipelineConfig(date_context=None)`는 이전 DMY 동작의 재현/비교용이다. 기본 `PipelineConfig()`는 새 `DateContext()`를 사용한다.

- 이미지 열기나 OCR 예외: `year,month,day`는 각각 `NONE`, `final_date`는 `NONE`으로 기록하고 계속 실행. 내부 실패 원인은 보존
- 입력 폴더 없음, 지원 이미지 0개, 중복 stem: 전체 입력 계약 오류로 즉시 중단
- 출력 열 순서: `image_id, year, month, day, final_date`
- 완전·부분·전체 누락 모두 `final_date == year + '-' + month + '-' + day`를 만족하도록 저장. 내부 `None`과 과거 단독 `NONE`은 저장 경계에서만 전체 누락 문자열로 변환

## 6. 검증과 시간 보고

`evaluate_pipeline.py`는 평가 입력 목록을 기준으로 누락된 출력도 오답에 포함하고, 실행 실패가 정답 NONE과 겹쳐도 정답으로 인정하지 않는다. 정확도 목표와 통과 여부는 `accuracy_target`, `accuracy_target_met`로 보고한다. 파일명 조회 정답이나 고정 OCR 문자열 평가를 전체 OCR 정확도로 표시하지 않는다.

내부 95% 목표는 날짜 전체 일치율이다. 공식 부분점수 배점은 미확정이므로 `field_metrics`의 연·월·일별 진단 지표를 공식 점수로 표시하지 않는다. 과거 `NONE-NONE-NONE`과 현재 `NONE`은 의미 비교에서만 동일하게 취급한다. 새 형식 준수율은 별도 `submission_format`으로 검사하며, 열 순서/필드 일관성/전체 누락 형식을 충족해야 결합 합격으로 처리한다. 과거 기록은 소급 수정하지 않는다. 상세 지표와 검증 범위는 [제출·평가 계약 정비](<submission-contract-20260910.md>)를 참조한다.

`run_pipeline`의 기존 `elapsed_seconds`는 이미지 처리·저장 구간이다. 추가한 `total_elapsed_seconds`는 함수 진입부터 모델 초기화·탐색·처리·저장까지 포함하지만 호출자와 Python import 시작 시간은 제외한다. 공식 500장 타이밍은 실행을 감싸는 외부 벽시계 측정으로 이를 포함해야 한다. OCR 호출 수와 `selection_reasons`를 함께 보고해 기본값 사용률과 복구 비용을 추적한다.
- 날짜 직렬화 예외도 이미지 단위 실패로 기록하고 다음 이미지를 계속 처리
- 출력 부모 디렉터리가 없으면 생성
