# 소비기한 날짜 판정의 근본 개선 작업 계획

2026년 9월 10일

목표는 전체 OCR 날짜 완전일치율 95% 이상과 500장 처리시간의 충분한 단축을 함께 달성하는 것이다. 2,400초는 타임아웃이고 새로운 수치형 속도 합격선은 아직 정하지 않았다. 순서만 모호한 경우 마지막 단계에서 DMY를 선택한다는 운영 방침은 유지한다. 이 문서는 계획이며, 코드·원본·라벨은 변경하지 않았다.

## 1 근본 원인과 해결 범위

현재 시스템은 숫자를 읽는 것과 그 숫자의 순서를 판단하는 것 사이의 근거 연결이 부족하다. 검수 자료에는 일련번호별 정답 순서가 있지만 그 판단을 재현할 포장 문구·대상 상품·영역·적용 범위가 없다. 제품 규칙 실행 기능은 있지만 실제 등록 목록은 비어 있다. 기본값을 바꾸는 것만으로 이 간극을 해결할 수 없다.

현재 비교 기록에서 727건 중 544건이 정답이고, 기존 정답에서 잃은 69건은 모두 DMY 기본값 선택에 해당한다. 이 69건을 복구하고 나머지 결과가 그대로라면 613/727, 약 84.3%다. 같은 평가에서 95% 이상은 최소 691건이므로 추가 78건의 개선이 더 필요하다. 이 계산은 고정된 OCR 증거에 대한 산술이며 실제 전체 OCR이나 독립 평가의 성능 예측이 아니다.

작업 범위는 순서 판단뿐 아니라 날짜 숫자 인식, 소비기한과 제조일 구분, 누락과 오탐, 조기 종료까지 포함해야 한다. 정답 날짜를 파일명으로 조회하거나 기본값을 다시 YMD로 되돌리는 방식은 채택하지 않는다.

## 2 작업 단위와 완료 조건

| 작업 단위 | 수행 내용 | 산출물 및 완료 조건 |
|---|---|---|
| 근거 데이터와 오류 원인 확정 | 검수 결과를 설명 가능한 라벨로 보완하고 기존·새 오답을 원인별 분류 | 회귀 69건 전부의 원인 기록, 전체 오답 분포, 제품·원본 그룹과 평가 분할 확정 |
| 날짜와 포장 근거의 연결 및 순서 선택 통합 | 현재 OCR에서 읽은 날짜·순서 안내·대응 날짜·상품 정보를 올바르게 연결 | 근거가 있는 사례는 앞 단계에서 결정되고 근거 없는 사례만 DMY로 이동. 일반 규칙의 양성·음성·충돌 테스트 통과 |
| 남은 인식 오류와 처리비용 개선 | 숫자 인식·기한 종류 오류를 개선하고 필요한 복구만 유지 | 변경 전후 실제 전체 경로 평가, 회귀 원인 설명, 각 복구 경로의 추가 정답과 추가 시간 측정 |
| 독립 평가와 최종 실행 검증 | 보지 않은 상품·포장·촬영에 대해 전체 OCR을 실행 | 날짜 완전일치율 95% 이상 확인, 공식과 같은 환경에서 500장 초기화·입출력 포함 시간 실측 |

수정할 파일 수에 따라 단계를 나누지 않는다. 판정 로직, 실행 흐름, 테스트, 평가 기록은 위 기능 단위마다 함께 처리한다. 성능 측정은 마지막에만 하지 않고 개발 중에도 같은 조건으로 반복한다.

## 3 먼저 정답 라벨을 근거 라벨로 확장한다

우선 회귀 69장을 확인하고, 441장 검수 후보와 명시적 순서 사례·전체 오류로 확장한다. 같은 포장의 회전·축소·중복 사진은 그룹으로 묶되, 각 사진에 실제로 보이는 정보는 별도로 기록한다. 한 사진의 뒷면 안내가 다른 잘린 사진에도 보인다고 가정하지 않는다.

각 사례에 다음을 남긴다.

- 실제 날짜 원문, 정규화 날짜, YMD·DMY·MDY 정답 순서.
- 해당 숫자의 종류: 소비기한·유통기한·품질유지기한·제조일·기타·미확인.
- 날짜 영역과 순서 안내 또는 대응 날짜의 위치, 실제 문구.
- 대상 상품 식별 정보와 포장 버전·판매시장. 확인되지 않은 정보는 추정값으로 분리.
- 정답 근거: 사진 안의 명시 안내, 동일 기한을 풀어 쓴 표시, 검증된 포장 규칙, 검수자 지정만 존재하는 경우.
- 근거 가시성: 입력 사진에 있음 / 다른 참고 사진에만 있음 / 확인 불가.
- OCR 원문과 누락·오독 여부, 연결 실패 여부, 최종 기본값 진입 이유.

검수자의 정답은 보존하지만 근거 문구를 추측해 채워 넣지 않는다. 사람이 외부 지식으로 판정한 사진을 모델도 입력 사진만으로 반드시 판정할 수 있다고 취급하지 않는다. 문서에 근거가 없는 사례는 원본 재확인이나 개발 시점의 검증 자료 확보가 필요하며, 추론 중 사람에게 묻지 않는다.

회귀 원인은 다음처럼 분리해야 한다.

1. 순서 안내가 사진에 있고 OCR에도 있지만 연결하지 못했다.
2. 안내는 사진에 있으나 OCR가 누락하거나 잘못 읽었다.
3. 안내는 없지만 검증된 제품·포장 규칙을 사용할 수 있다.
4. 입력에 순서를 결정할 근거가 없거나 개발 자료에도 확인되지 않았다.
5. 날짜 숫자·날짜 종류·라벨 자체에 충돌이 있어 순서 문제로 볼 수 없다.

이 분류 없이 제품 사전을 늘리면 연결 오류와 인식 오류를 암기 규칙으로 덮게 된다.

## 4 근거를 날짜에 연결하는 기능을 일반화한다

현재 `_resolve_orders`는 같은 OCR 패스에서 일정 거리 안의 문구를 사용한다. 예를 들어 순서 안내는 글자 높이의 3배, 제품 식별 문구는 8배 이내로 제한한다. 이는 안전장치이지만 포장 크기·배치에 따라 실제 안내를 놓칠 가능성이 있다. 이 가능성은 원인 분류 단계에서 사례별로 확인해야 하며 모든 회귀의 원인이라고 단정하지 않는다.

개선 원칙은 다음과 같다.

- 날짜 숫자, 날짜 종류, 순서 안내, 대응하는 풀어 쓴 날짜를 각각 추출한 뒤 연결한다.
- 같은 줄의 거리뿐 아니라 대상 상품 영역, 라벨 블록, 문구의 지시 관계를 사용한다. 가장 가까운 문자열을 무조건 연결하지 않는다.
- 배경의 다른 상품, 제조일 옆 안내, 다른 날짜를 가리키는 수입 스티커는 섞지 않는다.
- 원본·확대·회전 등 서로 다른 OCR 결과를 연결해야 하면 좌표 변환과 원본 영역의 출처를 기록한다. 변환 없이 좌표값만 비교하지 않는다. 현재의 좌표계 분리 안전장치는 유지한다.
- 제품 식별은 대상 상품 전체의 기존 OCR 증거를 사용하되 배경과 대상의 구분 근거가 있어야 한다. 고정 거리만 무조건 넓히는 방식으로 해결하지 않는다.
- 이미 인식한 문자·좌표로 가능한 연결부터 개선한다. 순서가 모호하다는 이유만으로 OCR 횟수를 늘리지 않는다.

근거끼리 충돌하면 처리 사유를 별도로 기록한다. 명시 안내가 있는 날짜를 제품 규칙이나 DMY 기본값으로 덮어쓰지 않는다.

## 5 제품 규칙은 적용 범위가 검증된 지식으로 만든다

제품 규칙에는 식별 조건, 포장 버전·판매시장 등 적용 범위, 해당 날짜 종류와 인쇄 영역, 읽기 순서, 확인 근거를 함께 둔다. 브랜드 하나나 국가 하나만 맞으면 작동하는 광범위한 규칙은 만들지 않는다. 소비기한 값이나 정답 일련번호를 조건에 넣지 않는다.

정확히 같은 이미지에만 맞는 문구 조합을 계속 늘리는 방식도 해결책이 아니다. 같은 제품의 다른 날짜·다른 촬영·다른 배치에서도 작동하는지 확인하고, 같은 브랜드의 다른 포장에는 잘못 적용되지 않는지 반례를 테스트한다. 규칙 조회는 로컬 색인으로 처리하고, 이미지마다 웹 검색이나 외부 API를 호출하지 않는다.

새 상품의 일반화는 제품 사전만으로 보장할 수 없다. 따라서 다음 두 집단을 따로 평가한다.

- 검증된 포장 규칙이 있는 제품의 새 사진.
- 사전에 없는 상품·포장 버전의 사진.

두 번째 집단에서는 명시 안내 인식과 날짜 연결 같은 일반 기능이 주된 해결책이다. 언어·브랜드·레이아웃에 따른 경량 통계 모델이 필요하다는 진단이 나올 경우에만 별도 개발안을 검토한다. 이는 확인된 제품 규칙과 다른 확률적 추정이므로, 운영상 어느 단계에서 허용할지 먼저 합의하고 그룹 분리 평가로 효과를 입증해야 한다. 이번 계획에서 새로운 모델을 무조건 도입하거나 국가 관행을 확정 규칙으로 바꾸지는 않는다.

## 6 기본값과 조기 종료를 분리해 기록한다

운영 순서는 날짜 종류 확인 → 명시 안내 → 달력상 유일성 → 검증된 제품 규칙 → DMY 기본값을 유지한다.

다만 다음 세 상태는 구분해서 다뤄야 한다.

- 숫자는 충분히 읽혔는가.
- 순서를 확인한 근거가 있는가, 아니면 기본값인가.
- 추가 OCR 없이 처리를 종료해도 되는가.

DMY 기본값으로 종료했다는 사실을 순서까지 높은 신뢰도로 확인했다는 뜻으로 사용하지 않는다. 현재 `confident`가 실행 종료 제어에도 사용되는 부분은 내부 기록에서 이 의미를 명확히 분리하는 방향으로 보완한다. 사용자에게 제출하는 다섯 열은 변경하지 않는다.

숫자가 명확하고 순서만 모호하면 DMY를 출력하고 종료한다. 숫자 누락·오독·날짜 종류 충돌로 재인식이 필요한 경우는 구분한다. DMY 기본값 정책을 시간 부족 때만 사용하거나 입력 순서에 따라 다르게 적용하지 않는다.

## 7 순서 외의 오류도 목표 정확도에 포함한다

고정 OCR 증거에서 회귀 69건만 복구해도 약 84.3%에 머무르므로, 다음을 별도로 개선해야 한다.

- 작은 점자형 숫자·반사·흐림·회전 등으로 날짜를 못 읽거나 잘못 읽는 오류.
- 제조일 또는 다른 숫자를 소비기한으로 선택하는 오류.
- 불완전한 날짜와 시각·로트 숫자를 잘못 합치는 오류.
- 잘못된 후보를 조기에 선택하여 뒤의 유효한 근거를 보지 못하는 오류.

진단 시 사람이 읽은 문자만 제공했을 때, 사람이 확인한 순서만 제공했을 때, 둘 다 제공했을 때의 결과를 비교하면 개선이 필요한 단계를 구분할 수 있다. 이러한 진단용 정답 주입은 오류 분석에만 쓰고 성능 달성 결과에는 포함하지 않는다.

복구 단계는 추가 정답 수와 추가 소요시간으로 평가한다. OCR 모델·전처리·임계값 변경은 원인이 확인된 범위에서만 시도하고, 날짜 순서 정책 변경과 효과를 혼동하지 않도록 대조 실험을 남긴다.

## 8 정확도와 속도의 검증 방식

### 데이터 누출 방지

이미지 단위 무작위 분할 대신 상품·포장·원본 촬영 그룹으로 개발·조정·최종 평가를 분리한다. 이미 분석하고 규칙을 수정한 441장과 회귀 사례는 독립 블라인드 성능의 근거로 사용하지 않는다. 완전히 새로운 상품 평가와 알려진 상품의 새 사진 평가를 구분한다. 미확정 라벨·제외 조건·평가 대상을 실행 전에 고정한다.

### 정확도

전체 이미지에서 최종 날짜 완전일치율 95% 이상을 목표로 한다. 정답 확정 500장이면 최소 475장 정답이어야 한다. OCR 실패, 날짜 종류 오류, 순서 오류, DMY 기본값 오판, 출력 누락을 모두 동일한 오답 예산에 포함한다. 전수 실행의 조기 종료와 복구 경로까지 평가해야 하며, 모든 OCR 증거를 마지막에 한꺼번에 주는 재평가로 대신하지 않는다.

함께 보고할 진단 지표는 숫자 원문 정확도, 기한 선택 정확도, 근거가 있는 순서 선택의 정답률과 적용률, 기본값 사용률과 오답률, 제품 규칙이 없는 상품의 정답률이다. 개발 회귀셋은 기존 정답을 잃은 사례마다 이유를 확인하며, 테스트 통과 수를 이미지 정답률로 제시하지 않는다.

### 속도

모델을 한 번 로딩하고 기존 OCR 결과를 재사용한다. 문구 정규화·규칙 조회·달력 검증은 같은 패스의 증거로 수행한다. 국가별 모델이나 순서별 OCR를 세 번 실행하지 않는다. 복구 상한과 효과를 측정하며, 95% 목표에 필요한 복구를 단지 느리다는 이유로 제거하지 않는다.

공식과 같은 4-vCPU·오프라인 조건에서 `predict.ipynb` 초기화부터 최종 파일 저장까지의 500장 실제 시간을 반복 측정한다. 전체 시간뿐 아니라 긴 지연 사례, OCR 호출 수, 복구 진입률, 기본값 사용률을 비교한다. 미리 저장된 OCR 결과를 사용하는 것은 개발 진단용이며 최종 속도 측정에서는 사용하지 않는다.

현재 정해진 것은 “2,400초보다 훨씬 빠르게”라는 방향이다. 후보들의 실측 정확도·시간을 비교해 수치형 속도 합격선을 정해야 하며, 1,800초 또는 임의의 초수를 사용자 승인 없이 목표 달성선으로 간주하지 않는다. 24장 결과를 단순 환산해 공식 500장 결과로 보고하지 않는다.

## 9 해결 가능한 범위의 한계도 먼저 확인한다

동일한 숫자 20-06-21만 있고 식별 가능한 다른 근거가 없다면, 그 문자열 자체만으로 2020-06-21과 2021-06-20 중 하나를 사실로 확정할 수 없다. 검수 라벨을 더 많이 적는 것만으로 사진에 없는 정보가 생기지는 않는다.

현재 정책에서 앞 단계가 결정할 근거를 얻지 못하고 DMY 기본값으로 남는 사례 중 실제 정답이 다른 사례가 평가셋의 5%를 넘으면, 다른 오류가 전혀 없어도 95%를 달성할 수 없다. 진단에서 이 집단의 크기를 측정해야 한다.

이 경우에는 추가로 검증된 포장 정보가 필요한지, 현재 이미지에 이미 있는 시각 정보에서 더 많은 근거를 얻을 수 있는지, 확률적 추정을 앞 단계에 허용할지를 검토해야 한다. 입력·정책·시간 제약을 모두 유지한 상태에서 95%가 불가능하다는 증거가 나오면 이를 명시적으로 보고한다. 숨은 파일명 예외나 날짜 분포 편향으로 목표를 맞춘 것처럼 보이게 하지 않는다.
