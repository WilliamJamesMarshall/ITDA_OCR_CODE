# OCR 구조적 개선: 역할 연결·숫자 복구·개발 검증

작성일: 2026-09-11. 작업 위치: `C:\ITDA_OCR_CODE`.

후속 갱신: 이 문서는 직전 작업 기록이다. 이후 미검출·월년 표기·반복 복구 개선 결과는 [후속 보고서](<ocr-followup-20260911.md>)를 참조한다.

## 결론과 적용 범위

보강 보고서의 남은 2~4단계를 기능 단위로 연속 수행했다. 역할 근거 유지, 제조일 전용 종료 보호, 제한된 날짜 쌍 선택, 명시 부분 기한 우선, 날짜 줄 인식 전용 복구, 문자 점수 계측과 개발 검증을 구현했다. **95% 정확도와 전체 평균 3초/장 목표의 달성을 뜻하지 않는다.** 아래 개발 자료는 이미 사용한 자료이며 독립 성능 추정치가 아니다.

`karpathy-guidelines`에 따라 변경 전 소스를 별도 보존하고, 초기 변경안의 정답 손실을 확인해 적용 조건을 수정했다. 파일 번호 예외, 정답 라벨 수정, 전역 숫자 치환, 새로운 가중치 다운로드·학습은 하지 않았다. `테스트용데이터`와 독립 500장 검증은 제외했다.

## 1. 역할 및 날짜 선택의 변경

- 숫자가 아직 날짜로 파싱되지 않아도 제조/소비기한 표제와 인쇄된 날짜 쌍의 역할을 유지한다. BBD·TETT를 기한 단서로 수집한다. 제조시설/제조회사 등의 일반 설명을 제조일 표제로 취급하는 것을 줄였다.
- 짧은 같은 행 표제는 대응 날짜가 유일할 때만 연결한다. 서로 다른 패스는 원본 좌표로 엄격하게 일치할 때만 역할을 전달한다. 크게 잘린 날짜 줄은 원본 줄 안에 포함되고 충분한 면적·높이를 유지하며 대응이 유일할 때만 원본 역할을 상속한다. 큰 병합 영역이 작은 표제 하나의 역할을 상속하지 않도록 제한한다.
- 서로 다른 역할이 같은 영역에서 충돌하면 확정하지 않는다. 충돌 영역을 가로 병합해서 후보로 재진입시키는 경로도 차단한다.
- 명시 소비기한이 읽히지 않고 제조일만 읽힌 경우에는 소비기한 없음으로 조기 종료하지 않는다. 단, 다른 정상 기한이 있는데 멀리 있는 안내 문장 때문에 이를 전부 NONE으로 만드는 전역 차단은 하지 않는다.
- 명시 부분 소비기한은 무관한 완전 날짜보다 우선할 수 있다. 인증번호·허가번호 같은 문장을 부분 기한으로 승격하지 않는다. 기존 허용 출력 범위를 늘리거나 없는 일자를 보충하지 않았다.
- 개별 표제가 없는 가까운 두 날짜에는 **먼저 순서를 해석한 후** 나중 날짜를 선택한다. 명시 소비기한, 별도 블록, 세 개 이상 근접 날짜, 복원된 숫자, 모호한 두 자리 연도 쌍 등에는 신규 정책을 강제로 적용하지 않는다. 네 자리 후치 연도의 월/일이 여전히 모호하면 기존 사용자 DMY 정책을 먼저 적용하되 `order_resolved=False`를 유지한다. 날짜 비교 결과를 만들기 위해 순서를 역으로 고르지 않는다.
- 신규 쌍 정책은 550일 상한을 쓰지 않는다. 기존의 다른 기간 점수 경로는 회귀 위험 때문에 일괄 제거하지 않았다. `local-date-pair`와 개별 날짜의 `order_reason`을 구분한다.
- 떨어진 ‘별도 표시/뒷면 표시’ 순서 안내 연결을 보강했다. 제조국/판매국만으로 YMD·DMY·MDY를 강제하지 않는다.

단일 무표제 날짜 질문과 연도 후치 일괄 DMY 질문은 운영진 확답이 없는 상태를 유지한다. 부분점수 배점을 임의로 정하지 않는다.

## 2. 숫자 인식 복구의 변경

기본 검출에서 얻은 짧은 날짜형 줄 최대 2곳만 대상으로 한다. 영양성분·전화·시각·로트 등 명백한 비날짜 단서는 제외한다. 각 줄에 원본 대비 보정, 작은 여백 추가, 여백+대비 보정의 최대 3개 입력을 만들고 **이미 로드한 인식기만** 배치 실행한다. 추가 검출, 새 모델 초기화, 전체 이미지 3회 재인식이 아니다.

### 숫자와 표제의 신뢰도 분리

설치된 CTC 후처리를 그대로 호출하면서 선택 문자별 점수를 읽는 어댑터를 추가했다. 빈 토큰과 반복 제거를 원래 방식과 맞추고, 실제 출력 문자열과 위치가 정확히 일치할 때만 점수를 연결한다. 미지원 형태나 정렬 불일치는 미확인으로 남긴다. 어댑터는 성공/실패와 관계없이 원래 후처리기를 복원한다. 설치 패키지를 수정하지 않았다.

날짜 토큰 숫자의 평균(`date_digit_score`)과 최솟값(`date_digit_min_score`), 전체 문자 점수 배열을 별도로 기록한다. 줄 점수는 원래 값으로 보존한다. 숫자 평균도 정답 확률이 아니며 가장 약한 문자 점수와 함께 확인해야 한다.

### 보수적인 채택 조건

- 원래 파서가 숫자 치환 없이 읽는 단일 날짜 토큰이어야 한다.
- 줄 점수 0.85 이상, 또는 줄 점수 0.65 이상이면서 날짜 숫자 평균 0.90 이상인 화면을 안정성 검사에 사용한다. 확인된 숫자 최솟값이 0.50 미만이면 제외한다. 이 값들은 개발 단계의 안전 문턱이며 확률 보정 결과가 아니다.
- 같은 날짜 해석 집합을 지지하는 화면이 2개 이상이어야 한다. 안정성 문턱을 통과한 상충 날짜가 있으면 원문을 유지한다. 원래 날짜와 같으면 점수를 부풀리지 않는다.
- 채택 화면은 **같은 모델의 상관된 관측**이다. 독립 표가 늘어난 것으로 가산하지 않고 활성 관측 하나의 문자만 교체한다. 원문·채택/기각 화면·원본 박스·문자 점수·역할 근거를 trace에 보존한다.
- 판독 실패나 어댑터 오류는 기존 기본 OCR 결과를 버리지 않고 기존 복구 경로로 넘긴다.

`enable_line_recovery=False`로 신규 경로만 끄고 비교할 수 있다. 기록 켬/끔은 판정에 영향을 주지 않는다. 모델을 바꾸거나 없는 숫자를 만들어내는 수정은 하지 않았다.

## 3. 검증

모든 수치는 기존 개발 자료에 대한 결과다. 서로 다른 표본의 정답 수를 합쳐 하나의 정확도로 표시하지 않는다.

### 저장 OCR 705건 재생

이미지를 다시 읽는 검증이 아니라 같은 저장 문자열에 날짜 정책을 적용한 비교다. **555/705 → 556/705**, 새 정답 1건, 기존 정답 손실 0건. 숫자 복구의 실제 성과는 이 수치에 포함되지 않는다.

연/월/일별 일치 수는 각각 `576/622/564 → 577/622/564`다. `003415`, `000305`의 근거 없는 부분 출력은 미판독 기한으로 바뀌었지만, 전체 날짜와 필드 정답을 잃지는 않았다.

### 같은 개발 이미지 28장 실제 전후 OCR

기존 개발 표본 24장과 이미 진단한 오류 4장을 사용했다. 입력 해시를 확인하고 같은 백엔드를 재사용해 전후 순서를 교차 실행했다. 공통 초기화는 따로 기록했다. 최종 수치는 함께 저장된 `live_result.json`과 `verified.json`을 기준으로 한다.

| 항목 | 변경 전 | 변경 후 |
|---|---:|---:|
| 전체 날짜 정답 | 21/28 (75.00%) | 25/28 (89.29%) |
| 연도/월/일 일치 수 | 23 / 24 / 23 | 26 / 26 / 25 |
| 새 정답 / 기존 정답 손실 | — | 4 / 0 |
| 실제 OCR 호출 평균 | 2.816초/장 | 2.748초/장 |
| 이미지 처리 평균(로딩·후처리 포함, 공통 초기화 제외) | 2.890초/장 | 2.868초/장 |

최종 소스 해시를 실행 전후 확인한 재측정이다. 변경 후 OCR 시간은 3초 대비 0.252초 짧고 이미지 처리 시간은 0.132초 짧았다. 공통 초기화 3.726초는 두 방식이 공유하므로 전후 평균에서 제외했다. 수십 밀리초의 차이를 확정적인 속도 향상으로 해석하지 않는다. 이 표만으로 초기화·입출력을 포함한 500장 목표 달성을 주장하지 않으며, 아래 실제 실행 관리 경로의 전체 시간과 구분한다.

개선된 오류는 `003645 → 2021-09-02`, `003666 → 2021-06-25`, `003714 → 2023-07-01`, `000276 → 2026-03-25`다. 코드에서 이 번호를 조회하지 않는다.

남은 오답은 `003355`, `003531`, `003590`이며, 앞의 두 장은 날짜 미검출/미복구, 마지막은 월·년만 있는 기한을 완전 날짜로 잘못 읽는 문제다. 새로운 문자/영역 주석과 인식 보완이 필요한 검토 목록으로 남긴다.

### 실제 제출 실행 경로 14장

기존 `date-target-role-1500-20260910/live_inputs`와 기존 라벨 파일만 사용한다. 입력을 복사해 새 독립 평가셋을 만들거나 라벨 상태를 변경하지 않는다. 프로세스 시작·모델 초기화·이미지 로딩·OCR·선택·CSV 저장을 포함한 시간과 OCR 호출 시간 합을 따로 비교한다. 최종 수치는 `runner_report.json`에 기록한다.

이 점검 중 제조일 표제가 잘리는 확대 화면에서 역할이 사라지는 오류를 발견해, 원본 줄 안에 포함된 잘린 관측의 역할 유지 및 회귀 테스트를 추가했다. 중간 결과는 `runner_initial_report.json`으로 보존했다.

최종 **14/14 정답, 제출 형식 14/14 준수, 실행 오류 0건**이다. 이 위험 사례들은 개발 중 반복 확인한 표본이므로 100%를 전체 데이터 정확도로 일반화하지 않는다. 과거 같은 14장 기록은 10/14였으나 시점이 다른 실행이므로 시간의 엄밀한 전후 비교로 사용하지 않는다.

| 시간 구분 | 실제 | 3초/장 대비 |
|---|---:|---:|
| OCR 호출 시간 합 / 14 | 3.739초/장 | +0.739초 |
| 프로세스 시작·초기화·입출력 포함 전체 | 59.040초 / 14 = 4.217초/장 | +1.217초 |

상대 목표 시간 `14×3=42초`를 넘어서도 끝까지 수행했고 2,400초 강제 종료에는 도달하지 않았다. 평가는 `internal_target_missed_within_hard_limit`이며 **500장 통과/불통과를 판정하지 않는다**. 500장 단순 환산 2,108.6초는 실제 500장 측정이 아니다. 평균 3초/장 속도 목표는 이 실행에서 미달이다.

14장 OCR 호출 시간 52.349초 중 기본 검출기 계열(원본·ROI·대비·타일) 42.135초, 복구 검출기 7.835초, 신규 인식 전용 경로 2.379초였다. 신규 경로 자체는 전체 14장 기준 0.170초/장이었다. 최상위 시간 사례는 `003714`, `003602`, `003512`로, 추가 속도 작업은 무조건 문자 재인식을 제거하기보다 기존 복구/종료 경로의 중복 비용부터 비교해야 한다.

### 자동 테스트 및 시간 계약

자동 테스트 **183개 통과**, Python 문법 검사 및 `git diff --check` 확인. 역할/숫자 분리, 미판독 기한, 반례 날짜 쌍, 부분 출력, 문자 위치 불일치, 복구 오류, trace 켬/끔 동일성, 제출 계약과 타임아웃 보호를 포함한다.

장당 목표 3초와 500장 내부 목표 1,500초는 계속 **소프트 목표**다. 넘겼다는 이유로 바로 실패 종료하지 않는다. 실제 강제 종료는 기존 프로세스 감독기의 2,400초다. 이번에 500장을 실행하거나 2,400초를 실제 기다리는 테스트는 하지 않았고, 감독기 종료 동작은 기존 짧은 한도 주입 테스트로 확인했다.

## 4. 남은 일과 제한

이번 기능 구현·개발 검증 묶음은 수행했지만 **95%·3초/장 동시 달성 작업이 끝난 것은 아니다.** 다음 과제는 남은 실패의 원본 날짜 줄/표제/문자 정답을 검수한 개발 주석 구축, 인식 전용 입력 정렬 또는 경량 인식기 보완의 비교, 복구 진입 조건과 비용의 위험별 조정이다. 현재 자료만으로 학습 정답이나 확률 보정 결과를 만들어내지 않았다.

역할 전달의 기하학적 조건은 상품 정체성 분할을 완전히 대체하지 못한다. 신규 재인식의 투표 중복은 막았지만 기존 전체 패스의 날짜값별 가산점과 모든 복구 경로까지 전면 재설계한 것은 아니다. 문자 점수 계측은 신규 인식 전용 경로에서 제공하며, 미검출 날짜 자체를 자동으로 생성하거나 모델 학습을 대신하지 않는다.

독립 500장 검증은 이 세션의 다음 작업으로 넣지 않는다. 별도 검증 일정과 미확정 운영진 답변은 그대로 남겨둔다.
