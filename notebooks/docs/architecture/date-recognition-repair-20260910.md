# 날짜 문자 처리·부분 날짜·조기 종료 후속 구현

2026-09-10. 앞선 근거 연결 개선 다음 작업을 코드·테스트·실제 실행까지 함께 수행했다. 작업을 수정 파일별로 나누지 않았다.

## 구현 범위

karpathy-guidelines에 따라 실제 원본과 OCR 기록에서 확인한 형태만 일반 규칙으로 보완했다. 제품/국가/일련번호별 정답 예외는 넣지 않았고, 원본 사진·정답 라벨·다른 작업의 재번호 결과는 변경하지 않았다.

- 붙은 일·월과 연도(`2106/2022`), 제한된 짧은 연도 슬래시 형식(`2212/21`), 월 내부 공백(`2021.1 1.26`), 네 자리 연도 앞의 중복 구두점을 처리한다. 주소 `1312-23`이나 부분 연도 `2001.19`로 확대 해석하지 않는다.
- 날짜 안의 `0ct`와 연도 위치의 `2U25`/`2D21`, 날짜 끝 `$` 등 제한된 OCR 혼동을 처리한다. `E`를 2 또는 6으로 일괄 치환하거나 누락된 연도 숫자를 임의로 추가하지 않는다.
- 로트 조각이 뒤따르는 완전 날짜를 먼저 소모하지 않도록 겹친 토큰을 검사한다. 영문 월 이름 번역 대조표를 날짜로 읽는 오류를 막는다.
- `MM/YYYY`, `MM.YYYY`, `MM-YYYY`를 부분 날짜로 읽고 없는 일자는 `NONE`으로 유지한다. 제조일/로트 번호나 불가능한 완전 날짜의 일부를 부분 날짜로 구제하지 않는다.
- 부분 날짜 안내(`월년순`, `MM/YYYY`, `Best before end`)가 연결되고 숫자 신뢰도 ≥0.90, 안내 신뢰도 ≥0.75, 경쟁 날짜 없음 조건을 만족하면 조기 종료한다. 완전 날짜 안내 `DD/MM/YYYY`는 이 조건에 사용하지 않는다. 안내 없는 부분 날짜와 불명확한 숫자는 기존 복구를 유지한다.

DMY 최종 기본값, 명시 순서의 우선권, 출력 5개 열, 기존 OCR 모델과 복구 단계 수는 유지했다. 이미지마다 추가 API를 호출하거나 새 모델을 설치하지 않았다.

## 데이터 고정과 비교 범위

별도 정리 작업에서 추가 사진 22장이 제거되고 번호가 바뀌었다. 이전 727건 중 현재 남아 있는 동일 이미지 705건을 SHA-256으로 연결해 검증 목록을 고정했다. 기존 수동 확정 341건 + 추가 자료 364건이다. 이전 번호와 현재 번호를 모두 기록했고, 삭제된 22건은 별도 제외 목록에 남겼다.

따라서 이전 보고서의 559/727과 아래 555/705를 직접 비교해 감소라고 해석하면 안 된다. **이번 시작 코드도 같은 705건에서 재평가한 결과가 542/705**다. 개발에 사용한 사진/정답이며 독립 평가 집합은 아니다.

## 검증 결과

### 자동 테스트 및 저장 OCR 비교

- `python -m unittest discover -s tests -q`: **82개 통과**.
- 고정 OCR 증거: **542/705 (76.88%) → 555/705 (78.72%)**.
- 새 정답 13건, 기존 정답 손실 0건.
- 문자 처리/후보 생성 8건 + 월·년 부분 날짜 5건 개선.
- 일부 오답은 다른 오답으로 바뀌었다. 단순히 ‘변경된 날짜’ 전체를 개선으로 세지 않았으며 상세 비교에 보존했다.

모든 저장 OCR 증거를 재생한 결과는 실제 OCR 전체 경로의 독립 정확도와 다르다.

### 실제 OCR 비교

먼저 개선 대상 8장과 대조 사진을 합친 24장을 변경 전/후 코드로 각각 실제 처리했다. 실행 순서를 번갈아 적용했고 같은 백엔드에서 모델 초기화를 먼저 완료했다. 타이머는 이미지 로딩·OCR·판정을 포함하지만 모델 초기화/프로세스 시작은 제외한다.

| 24장 비교 | 변경 전 | 문자 처리 보완 후 |
|---|---:|---:|
| 정답 | 13/24 | 21/24 |
| OCR 호출 | 87회 | 74회 |
| 이미지 처리 합계 | 80.19초 | 83.55초 |

8건 개선을 실제로 재현했고 정답 손실은 없었다. 호출 수는 감소했지만 이 단일 실행의 시간은 늘었으므로, 전체 속도 개선을 달성했다고 판단하지 않는다. 이 실행 뒤 부분 날짜 기능을 보완했으며, 최종 코드로 위 24장의 실제 OCR 기록을 다시 재생해 출력과 종료 패스가 모두 동일함을 확인했다. 이 재생을 최종 코드의 새 시간 측정으로 취급하지 않는다.

이어 새로 지원한 부분 날짜 5장을 최종 코드로 실제 재실행했다.

| 부분 날짜 5장 | 형식 지원 후·조기 종료 전 | 최종 조기 종료 적용 |
|---|---:|---:|
| 정답 | 5/5 | 5/5 |
| OCR 호출 | 36회 | 24회 |
| 모델 초기화 포함 측정 | 47.51초 | 28.51초 |

부분 날짜 실행 타이머는 모델 초기화 시작부터 처리 완료까지이며 Python import/시작 및 최종 보고서 저장은 제외한다. 이번 5장 중 2장이 첫 OCR에서 종료했다. 입력 파일은 각 처리 직전/직후, 코드는 실행 전후 해시를 검증했다. 이 작은 개발 표본의 시간은 공식 500장 처리시간으로 환산할 수 없다.

## 미해결 문제와 다음 작업 — 있음

고정 증거에서 남은 오답 150건의 자동 분류:

| 분류 | 건수 | 다음 확인 사항 |
|---|---:|---|
| 정답 날짜가 원문 파싱 후보에도 없음 | 81 | 실제 숫자 미검출·오독, 날짜 영역/복구 우선순위, 아직 미지원인 문자 형태 구분 |
| 정답 후보가 순서/근거 선택에서 제외 | 52 | 입력에 보이는 포장 근거, 동일 상품의 검증된 규칙, DMY 기본값 적용의 한계 |
| 후보에는 정답이 있으나 다른 날짜 선택 | 5 | 제조일·소비기한·다른 상품·다른 인식 패스 사이의 연결과 점수 |
| NONE/부분 날짜 관련 | 12 | 시각/로트 혼입, 제조일 전용 사진, 근거 없는 완전 날짜 선택 |

이는 **자동 원인 분류이지 150장 전수 육안 확정 결과가 아니다.** `[정답 후보 없음]`도 반드시 OCR 모델만의 잘못이라는 뜻은 아니다.

다음 기능 묶음은 날짜 영역 검출·복구 우선순위와 날짜 종류 선택을 개선하는 작업이다. 특히 현재 ROI 선택은 구분자를 포함한 숫자 줄을 OCR 점수순으로 최대 2개 선택하므로, 선명한 전화번호/영양 정보가 약한 날짜보다 먼저 선택되는지 실제 오류에서 확인해야 한다. 새 모델 학습이나 광범위한 제품 규칙 등록은 검증 데이터와 적용 범위를 먼저 확정해야 한다.

제품/중복 그룹을 분리한 독립 평가, 내부 정확도 95%, 공식 환경에서 초기화·입출력을 포함한 500장 시간 측정은 여전히 미완료다. 705건에서 95% 이상은 최소 670건이므로 현재 고정 기록에서는 추가 115건의 개선이 필요하다. 2,400초는 목표가 아닌 타임아웃이며 더 빠른 시간의 수치 합격선은 아직 정해지지 않았다.
