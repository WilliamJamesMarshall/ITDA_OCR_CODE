## 처리시간과 정확도

모든 새 최초 테스트·재시험·후보 평가의 시간 목표는 `3.2 × 대상 이미지 수`초다.
500장 미만은 `전체 처리시간 / 대상 장수 ≤ 3.2초/장`, 500장은 전체 1,600초 이하로 표시한다.
시간은 nbconvert 시작부터 모델 초기화·전체 이미지 처리·CSV 저장·종료까지다.
준비 복사와 사후 채점은 제외한다. 일부 누락·실패가 있으면 시간만으로 통과시키지 않는다.
개별 이미지의 3.2초 초과를 곧바로 실패로 판정하지 않으며 회차 전체 평균을 사용한다.
강제 종료는 기존 노트북 전체 2,400초를 유지한다. 목표 초과와 강제 종료는 별개다.
학습 시간은 별도 기록하며 이 추론 시간 목표를 optimizer 실행에 적용하지 않는다.

주 정확도는 `date-fields-v1`: 정답 year/month/day 필드 수 / (3 × 대상 이미지 수), 목표 95% 이상이다.
216장은 분모 648·최소 616필드, 394장은 분모 1,182·최소 1,123필드,
500장은 분모 1,500·최소 1,425필드가 필요하다. 정답 NONE과 출력 NONE 일치도 정답이다.
누락·실패 이미지는 분모에 남고 득점하지 않는다. 전체 날짜 완전일치는 보조 지표다.
보호 정답과 개별 보호 필드 퇴행 0, 실행 오류 0, 출력 형식 준수를 함께 확인한다.
각 회차의 목표 미달을 평균으로 숨기지 않는다.

## 운영과 학습

순서는 1회 → (2·3회) → (4·5회) → 6회다. 단계별 누적 평가 장수는 216 → 1,216 → 2,110 → 2,610이다.
같은 묶음은 이전 묶음이 선정한 동일 코드·모델로 최초 테스트한다.
묶음의 두 최초 테스트가 모두 끝나고 보고서가 작성된 뒤 해당 후보 학습 절차를 진행한다.
보고서 확인·사용자 피드백·실제 학습 승인과 원본/crop/그룹/config 연결 절차를 유지한다.
이미 유효한 승인은 범위와 해시를 확인하여 사용하며 이관으로 새 승인을 만들지 않는다.

회차 후보는 이전 묶음까지 편입된 누적 승인 원본과 해당 회차 승인 원본을 사용한다.
상품/촬영/파생 그룹의 optimizer/내부 검증 역할을 영구 고정하고 미래 회차 원본을 조기 편입하지 않는다.
2·3회 및 4·5회는 개별 후보 검증 후 별도로 승인된 합집합 통합 학습·누적 평가·선정을 거친다.
1·6회는 단독 후보 평가·선정으로 종료한다. 후보를 공용 weights에 자동 반영하지 않는다.
CPU4, seed 20260911, 고정 초기 checkpoint·사전/runtime, 승인 config를 유지한다.
epoch/LR/학습 범위·실시간 증강은 검토된 설정을 사용하며 75 epoch는 상한이지 실행 승인 아니다.
checkpoint 선정은 내부 검증 crop 필드 정확도 → micro CER → NED → 이른 epoch, patience 5다.
crop의 필드 정답은 승인 pool의 명시적 date_fields를 사용하고 문자열에서 임의 추론하지 않는다.
BN 통계 고정과 마지막 batch 처리 등 기존 학습 계약을 유지한다.

병행 CPU는 0,1,4,5 / 2,3,6,7 (각 P2+E2·4스레드), 단독 1·6회 및 통합 작업은 0–3이다.
공유 RAM·I/O, 병행 여부, 실제 CPU·시간·메모리를 기록한다. OS 오프라인 검증이 기본이며
기존 2·3회 온라인 허용은 해당 실제 지시·고정 코드·모델·실행 범위에만 연결한다.
폴더 이관만으로 새 환경 검증이나 과거 승인 범위 확대를 인정하지 않는다.
