## 2. 실행 전 필수 확정

### 2.1 실제 학습 모듈

0단계에서 CPU 학습 진입점 `scripts/train_recognition_cpu.py`와 동일 초기 가중치·의존성을 준비하고 합성 스모크 학습을 통과했다. 실제 데이터 학습에는 2단계 OCR 주석 승인과 그룹 분할 후 아래 입력·출력 계약을 충족하는 라벨 목록이 필요하다. 고정값과 증거는 `00_protocol/execution_policy.md`를 따른다.

- 입력: 누적 학습 manifest, 이미지 경로, 정답 라벨, 초기 가중치/설정
- 출력: 회차별 모델 체크포인트, 학습 로그, 설정, 베스트 체크포인트 선정 근거
- 필수 증거: 손실값과 평가지표 변화, 학습 데이터 수, 난수 seed, 모델 파일 SHA-256

이 학습 명령이 없이 사람이 오류를 보고 규칙만 수정하면, 결과는 `머신러닝 학습` 대신 `규칙 기반 파이프라인 튜닝`으로 표기한다.

### 2.2 출력 계약

2026-09-11 사용자가 전달한 최종 공지에 따라 year/month/day가 모두 `NONE`이면 `final_date=NONE`으로 확정한다. 기존 `NONE-NONE-NONE`은 과거 기록의 의미 비교에서만 호환하고 새 제출로는 인정하지 않는다. 부분 날짜 `NONE-MM-DD`, `YYYY-MM-NONE`은 유지한다. 구현·평가기·정답지는 이 계약을 따른다.

## 4. 1회성 데이터 준비

2026-09-12 변경 통제: 아래 522장 조건은 목표값이다. 상품 그룹 무결성이 우선이며, 그룹 확정 후 정확한 균등 분할이 불가능하면 실제 크기와 허용 범위를 승인받아 이 계획을 개정한다. `01_splits/draft`는 공식 분할이 아니다. fold 5 manifest에는 정답을 포함하지 않으며 정답·주석·과거 복사본의 채점자 전용 접근 분리가 완료되어야 최종 잠금으로 판정한다. 상세 최신 규칙은 `00_protocol/execution_policy.md` 13절을 따른다.

단계 경계: 1단계는 정답지·정본 데이터·provenance 정비와 주석 검수 입력 준비까지다. 2단계는 OCR 원문·polygon 구축과 사람 승인, 상품 그룹·난이도·조건 검수다. 아래 fold/inner validation 생성은 주석과 그룹을 승인한 뒤 실행한다. 현재 결과는 `00_protocol/stage1_readiness.json`, 상세 규칙은 `00_protocol/stage1_data_protocol.md`에 기록한다.

1. 2,610개 이미지의 상대경로, 파일 크기, SHA-256을 `dataset_inventory.json`에 저장한다.
2. 중복 파일과 파손 이미지를 검사한다.
3. 유사 상품·연속 촬영·동일 원본의 변형본은 하나의 `group_id`로 묶는다.
4. `group_id`를 유지하면서 정답 유형(전체 날짜/부분 날짜/미표기)과 난이도가 가능한 균등하게 되도록 522장씩 나눈다.
5. 난수 seed를 고정하고 `split_manifest.csv`에 모든 이미지의 fold를 저장한다.
6. 검증은 다음 세 조건을 모두 만족해야 통과한다.
   - fold별 정확히 522장
   - fold 간 교집합 0장
   - 5개 fold의 합집합 2,610장
7. `fold_05_final.csv`의 정답은 1~4회차가 완료될 때까지 분석·코드 수정·하이퍼파라미터 선정에 사용하지 않는다.

`--limit 522`는 정렬된 앞 522장을 선택하므로 무작위 fold 선택용으로 사용하지 않는다. 각 fold manifest에 들어 있는 이미지만 평가 입력 폴더에 연결하거나 복사하여 실행한다.

## 5. 회차별 실행 순서

### 5.1 평가 전 고정

1. 해당 회차의 학습 데이터 ID와 평가 ID 간 겹침이 0인지 검증한다.
2. 학습에 사용된 정확한 manifest와 모델 SHA-256을 `model_before.json`에 기록한다.
3. Git 커밋, 파이썬·패키지 버전, CPU/OS, OCR 가중치 해시, 설정을 동결한다.
4. 정답지를 열지 않은 상태에서 추론을 완료한다.

### 5.2 채점환경 평가

1. fold 522장을 전용 입력 폴더에 준비한다.
2. Standard 4-Core vCPU, CPU 전용, 오프라인 상태에서 실행한다.
3. 추론 전에 모든 가중치가 로컬에 있는지 확인한다.
4. `ITDA_INPUT_DIR`를 fold 입력 폴더, `ITDA_OUTPUT_PATH`를 해당 `round_*\submission.csv`로 지정한다.
5. `predict.ipynb` Run All을 실행하고 2,400초 하드 타임아웃을 적용한다.
6. 초기화, 이미지 읽기, OCR, 후처리, CSV 저장을 전체 시간에 포함한다.
7. 522장은 공식 500장보다 4.4% 많으므로 2,400초를 적용하면 공식 조건보다 더 엄격한 스트레스 테스트로 해석한다.

### 5.3 평가 및 분석

1. 추론이 종료된 후에만 해당 fold의 정답을 공개한다.
2. `final_date` 완전 일치율을 주 지표로 계산한다.
3. year/month/day 필드별 일치율, 미검출, 오검출, 날짜 불일치, 출력 누락, 실행 오류를 별도 집계한다.
4. 총소요시간, 장당 평균, p50, p95, 시간 초과 여부를 기록한다.
5. `submission.csv`, trace, 오류 목록과 집계 결과를 해당 회차 폴더에 저장한다.

### 5.4 평가 후 학습—1~4회차

1. 이번 fold의 이미지와 정답을 누적 학습 manifest에 추가한다.
2. 누적 데이터를 이용하여 매번 동일한 승인 사전학습 초기 가중치에서 다시 학습한다. 이전 회차 체크포인트에서 이어서 학습하지 않는다.
3. 현재 회차 데이터의 평가 결과로 하이퍼파라미터를 선택하더라도, 해당 점수를 최종 성능으로 보고하지 않는다.
4. 학습 완료 후 체크포인트와 로그를 `models\round_NN`과 `round_NN`에 저장한다.
5. 다음 fold는 현재 회차의 실행·채점·학습 산출물이 모두 검증된 후에만 연다.

### 5.5 5회차 최종 평가

1. 1~4 fold 2,088장으로 학습한 모델과 추론 설정을 동결한다.
2. `fold_05_final.csv` 522장을 1회만 실행한다.
3. 결과를 보고 코드·규칙·가중치를 수정한 후 다시 실행하지 않는다.
4. 5회차 정확도와 속도를 최종 일반화 성능으로 보고한다.
5. 1~4회차 점수는 학습곡선으로만 표시하고 5회차 점수와 평균하지 않는다.
