# 8회 테스트·학습 / 5단계 병행 실행 계획

정책 `grouped-8-v2`. 이 세션에서 사용자가 승인한 재분할 및 병행 운영 계획이다.
현재 실행 정본은 이 문서이며 `sequential_8_rounds.md`는 과거 번호순 계획이다.
구현 승인은 미래 보고서 검토나 회차별 학습 승인을 대신하지 않는다.

## 회차와 단계

| 단계 | 회차 | 테스트 ID | 장수 | 초기 개발 사용 | CPU |
|---|---|---|---:|---:|---|
| 1 | 1 | AMLT000001–AMLT000216 | 216 | 206 | 0–3 |
| 2 | 2 | AMLT000217–AMLT000352 + BMLT003353–BMLT003716 | 500 | 499 | 0–3 |
| 2 | 3 | AMLT000353–AMLT000852 | 500 | 0 | 4–7 |
| 3 | 4 | AMLT000853–AMLT001352 | 500 | 0 | 0–3 |
| 3 | 5 | AMLT001353–AMLT001852 | 500 | 0 | 4–7 |
| 4 | 6 | AMLT001853–AMLT002352 | 500 | 0 | 0–3 |
| 4 | 7 | AMLT002353–AMLT002852 | 500 | 0 | 4–7 |
| 5 | 8 | AMLT002853–AMLT003352 | 500 | 0 | 0–3 |

2회의 초기 개발 미사용 1장은 AMLT000263이다. 전체 3,716장·중복/누락 0.
초기 개발 노출은 보존된 705장 SHA 목록 기준이며, 증강 원본/상품 관계의 간접 노출 여부와 구분한다.
같은 원본이 여러 회차에 있으면 처음 승인 편입한 때부터 후속 성적에 노출 이력을 표시한다.

## 순서와 보고

1회 완료 → (2,3) 완료 → (4,5) 완료 → (6,7) 완료 → 8회 완료.
같은 묶음은 이전 묶음이 선정한 동일 코드·모델로 최초 테스트한다. 앞 번호의 학습이 뒤 번호의 최초 테스트를 선행하는 구조가 아니다.
두 최초 테스트가 모두 종료·채점되기 전에는 해당 묶음의 optimizer 학습을 실행하지 않는다.
한쪽이 먼저 끝나면 그 회차 보고서 작성과 저장된 결과 분석은 가능하다.

회차마다 대표 `report.md` 하나(총 8개)를 유지한다. 최초 점수, 필드별 진단, 출력 형식,
시간·오류, 오답 구조 분석, 사용자 피드백, 학습, 재평가·퇴행, 채택/기각 근거를 분리한다.
최초 `initial_report.json`과 사용자가 검토한 버전·해시는 보존한다.
학습·재평가가 기존 최초 성적을 덮어쓰지 않는다. 실패도 보고하며 자동 승인하지 않는다.

오답의 검출/잘림/문자 인식/조각 결합/날짜와 시각/제조일·소비기한 역할/최종 선택을
두 회차에서 병행 분석한다. 각 작업은 독립 코드 사본과 로그·후보 폴더를 사용한다.
안전한 공통 개선을 통합한 코드 사본을 다음 학습 release의 `--code-root`로 지정한다.
실행 중인 코드·가중치는 불변이다. 학습한 후보를 공용 weights에 자동 복사하지 않는다.

## 보고서 확인 → 승인 → 원본 학습

테스트 입력 `C:/ITDA_OCR_CODE/테스트용데이터`에는 증강본이 섞여 있다.
학습 원본 폴더는 `C:/ITDA_OCR_CODE/학습대상데이터`이다.
각 회차 테스트와 보고서 작성 후 실제 사용자 피드백 및 명시적 학습 승인이 있어야 한다.
보고서 해시·확정 이후 승인 시각·지시 원문·출처·피드백·회차·설정·코드·모델·원본 대응을 승인에 연결한다.
피드백이 없으면 소프트웨어가 대신 작성하지 않는다. 사용자의 명시적 '추가 의견 없음'은 기록할 수 있다.

테스트 증강 파일은 optimizer/inner validation에 사용하지 않는다. 대응 원본을 찾고
원본 디렉터리·SHA·승인 주석 및 전사를 검사한 뒤 승인된 원본 OCR crop만 입력한다.
crop을 다른 디렉터리에 복사해도 기존 증강 테스트 바이트와 같으면 거부한다.
기존 계획의 온라인 RecAug/RecConAug는 테스트 증강 파일 편입과 별개이며, 실제 학습 설정은 승인된 config로 고정한다.

원본 대응 미확정 또는 원본 파일 부재는 학습 편입을 차단한다.
2026-09-13 후속 조사에서 기존 미확정 1,106건 중 1,084건을 현재 원본에 연결했다.
나머지 22건은 삭제 전 출처·해시를 확인했으나 현재 원본 파일이 없다:
1/2/3회 0건, 4회 4건, 5회 2건, 6회 2건, 7회 1건, 8회 13건.
이는 출처 불명과 다르며, 과거 중복 제거로 삭제된 원본을 복원·재편입할지는 별도 결정이 필요하다.
후속 지시로 22건 모두 기존 상품사진 참조 연결은 완료했다. 이 참조 파일은 증강본이므로 학습 원본을 대신하지 않는다.
상세 근거는 [원본 대응 조사 결과](../training/derivative_resolution_20260913.md)와 현재 `status`의 mapping_readiness를 확인한다.
출처·파생 관계 검토 근거를 확보하여 `revise-mapping`으로 버전 이력을 남긴다.
번호나 유사도만으로 확정하지 않는다. 이전 연결·평가 목록·초기 노출 표시를 임의 변경하지 않는다.

회차별 후보는 이전 묶음까지 승인된 누적 원본과 해당 회차 승인 원본으로 학습한다.
공통 group_roles 레지스트리로 같은 상품/촬영/파생 그룹의 역할을 영구 고정한다.
내부 검증 그룹이 다른 작업자나 다음 회차의 optimizer로 들어갈 수 없다.
두 후보를 검증한 다음, 별도 통합 학습 승인으로 두 회차 승인 원본의 합집합을 중복 제거하여
단일 다음 묶음용 후보를 학습한다. 서로 다른 후보의 정답을 합산하거나 가중치를 단순 평균하지 않는다.

CPU4, seed 20260911, 고정 초기 checkpoint/사전/runtime을 사용한다. 이어 학습은 기본 경로가 아니다.
epoch/LR/증강/학습 범위는 보고 후 승인한 config로 고정하며 75는 상한이지 실행 승인 아니다.
선정은 내부 문자열 정확도 → micro CER → NED → 이른 epoch, patience 5.
승인 config의 `Global.freeze_bn_statistics: true`로 BN running 통계를 고정할 수 있다.
기존 학습/내부 검증 마지막 batch도 빠짐없이 처리한다.

## 선정과 종료

모든 후보는 현재 묶음까지의 누적 회차 전체를 각각 216/500장 단위로 재평가한다.
누적 표본수는 단계별 216 → 1,216 → 2,216 → 3,216 → 3,716이다.
기존 보호 정답 퇴행 0, 실행 오류 0, 출력 형식 준수와 개별 회차 시간·정확도를 확인한다.
회차 정확도·시간을 평균해 개별 실패를 숨기지 않는다.
회차별 개발 100%는 별도 지표이며 최초 95% 성능 목표와 구분한다.
목표 미달을 수용하고 다음 묶음으로 가려면 해당 결과에 대한 실제 명시적 수용이 필요하다.
후보 기각·이전 모델 유지는 `--retain` 평가와 실제 선정 승인으로 기록한다.
단순 상태 문자열이나 checkpoint 파일 존재로 단계 완료를 인정하지 않는다.

8회는 단독 테스트 후 보고·승인·원본 학습·export·검증·선정으로 끝난다. 9회는 없다.
8회 학습 후 최종 모델의 독립 테스트 성적은 없으며 누적 개발 재평가와 구분한다.

## 환경과 보존

두 작업을 0–3 / 4–7에 분리하며 자식 프로세스까지 affinity를 검사한다.
추론은 OS outbound 차단·사전 로컬 가중치·nbconvert Run All, GPU 없음.
목표는 1회 648초, 나머지 각 1,500초, 강제 종료는 각 노트북 전체 2,400초.
8코어/16GB PC의 두 작업은 메모리·I/O를 공유하므로 실제 메모리와 각각의 시간을 기록한다.
운영진 서버의 동일 하드웨어 성능 인증이라고 표현하지 않는다.
부하가 겹친 측정과 단독 측정은 보고서에 구분한다.

새 작업 공간: `C:/ITDA_OCR_WORKSPACE/grouped-8-rounds-v2`.
기존 sequential-8-rounds와 1회 실제 실행·remediation 학습 이력은 보존한다.
이력 참조 가져오기는 재테스트나 학습 완료 인정이 아니다.
보호 이미지·정답·기존 가중치·predict.ipynb CONFIG를 변경하지 않는다.

실행 명령과 승인 형식은 [운영 안내](../training/grouped_operations.md),
새 세션의 상태 보고 프롬프트는 [세션 프롬프트](../training/grouped_session_prompts.md)를 따른다.
