# 논문 전체 계획 구현 — 실행 금지 상태

후속 실행 준비는 `prepare_execution.py`와
[2·3단계 인계](../../../docs/training/stage2_stage3_preparation_20260914.md)를 따른다.
원래 아래 구현 사본은 변경하지 않고 새 회차별 준비 사본에 현재 6회 제어 코드를 연결한다.
새 실행의 목표는 3.2×N초, 강제 종료는 2,400초이며 아래 1,600초 제한 승계는 당시 구현 이력이다.
`run_prepared.py`는 별도 실행 지시·해시 결합 승인을 요구하며 준비 중 호출하지 않는다.

사용자 지시: **계획 전체 적용을 시작하되 테스트는 별도 지시 전까지 실행하지 않는다.**

후보: `C:/ITDA_OCR_WORKSPACE/grouped-6-originals-v1/paper-plan-implementation-20260914/code`.
기존 `paper-ocr-20260914/code-monitor`, `full-01`, `full-02`, 공용 추론 코드·가중치를 수정하지 않는다.

현재 단계는 구현이며 성능 검증이 아니다. 단위 테스트, replay, crop OCR 진단,
소량/전체 OCR, 벤치마크, 보정기 fitting, optimizer/내부 검증을 실행하지 않는다.
과거 테스트 통과 기록은 이 새 후보에 적용되지 않는다. 향후 실행 전에 사용자 지시와
데이터/설정 검토, 생성 노트북과 소스의 일치 확인이 필요하다.

## 구현 범위

1. 기존 날짜/시각 경계·좌표 기반 표기 연결·부분 crop 보호를 승계한다.
2. 정답 crop/전사 개입 진단 도구와 승인 원본 기반 증강·미세조정 설정을 준비한다.
3. 인식기 지원 범위 안에서 종횡비 기반 배치를 구성하고 캐시를 전처리 조건에 연결한다.
4. bounded CTC 후보 수집 및 검증 자료 전용 신뢰도/복구 이득 모델의 입출력을 구현한다.
5. 보정 자료가 있을 때만 필드 순증/비용 우선순위를 적용하고 없으면 기존 순서를 유지한다.
6. 점 인쇄 복원은 기존 선택적 복구 경로를 유지한다. 생성형 복원/새 대형 모델은 도입하지 않는다.

## 이번 구현 상태와 남은 작업

|---|---|---|

| 원인 분리 | `oracle_diagnosis.py`: 기본 OCR/정답 crop/정답 전사 비교 | 검토된 영역 입력과 실제 진단 실행 |
| 포장 학습 | candidate `scripts/packaging_augmentation.py`, 학습기 등록, `training_recipes.json`, YAML 생성 도구 | 그룹/전사/내부 검증 필드 검토, 설정 승인, 실제 optimizer 실행 |
| 종횡비/배치 | candidate `src/crop_batching.py`를 recovery 인식에 연결, cache key에 전처리 조건 포함 | 속도·정확도 비교. 기본 PaddleX 전체 OCR은 이미 비율 정렬을 하므로 중복 구현하지 않음 |

| 복구 배분 | 검증된 table이 있을 때만 순증/시간으로 큐 선택, 샘플 부족은 기존 순서 | 실제 이득 table 없음: 현재는 기존 스케줄러로 동작 |

`test_paper_plan.py`는 작성만 했으며 실행하지 않았다. 노트북 생성은 코드 패키징만 수행한다.
노트북 실행 guard는 `ITDA_EXPLICIT_TEST_INSTRUCTION=1`을 요구한다. 이 값 자체가 사용자
승인을 만드는 것은 아니므로 실제 별도 지시 없이 설정하지 않는다.

기존 `code-monitor` 보존 대상의 해시 변경은 0건이다. 새 코드/모델 성능을 확인하는
테스트 대신 파일 보존과 코드 패키징만 확인했다. 공용 소스와 모델은 승격하지 않았다.

학습률 0.00005/0.0001, 최대 15 epoch 등의 값은 비교를 시작하기 위한 **검토 초안**이다.
검증으로 선정된 최적값이나 실행 승인이 아니다. 처음부터 모든 후보를 자동 실행하지 않는다.
점 누락·잉크 확산은 문자를 바꿀 수 있어 별도 후순위/낮은 강도 실험으로만 설정했다.

학습 전에 상품 그룹과 optimizer/내부 검증 역할을 확정해야 한다. crop 필드 정답을
전사나 전체 이미지 정답에서 자동 생성하지 않는다. 승인되지 않은 초안은 학습 입력이 아니다.
모델 구조/문자사전을 유지하는 미세조정이 우선이며 SVTRv2 전체 교체는 계획대로 후순위다.
