# 파일구조 변경 및 3단계 인계

2026-09-12. 권장 A안(필수 루트 파일 + 기존 실행 코드 폴더 유지)을 적용했다. 사용자 추가 조건에 따라 8개 데이터·정답지 폴더는 예외적으로 현재 위치에 보존했다. 추론 알고리즘·학습 정책은 변경하지 않았다.

## 실제 변경

- 추론 노트북·requirements·다운로드 스크립트·src·configs·weights·training_runtime 위치 유지.
- 설계 문서: `notebooks/docs/architecture/`로 이동. 기존 `docs/`는 로컬 호환 junction이다.
- 학습·평가 정책과 단계별 보고: `notebooks/docs/protocol`, `data`, `evaluation`에 열람용 사본 게시. 원본 계획과 승인 자료는 그대로이며 사본보다 원본이 우선한다.
- 학습 의존성 lock: `notebooks/environment/requirements-train-cpu.lock.txt`로 이동하고 준비 스크립트 수정.
- 회차별 결과 요약: `notebooks/reports/round_01` ~ `round_05_final`, `baselines`, `summary`에 저장할 구조 마련.
- `학습 및 테스트 결과` → `C:/ITDA_OCR_WORKSPACE/workspace`.
- artifacts·labels·.codex-tmp → `C:/ITDA_OCR_WORKSPACE/archive/` 아래 각 폴더.
- outputs → `C:/ITDA_OCR_WORKSPACE/runs/legacy-outputs`.
- 위 원시 산출물의 기존 경로에는 junction을 남겼다. 따라서 승인 snapshot·crop 절대 경로를 고쳐 쓰지 않았다. 원본 이미지·승인 자료·계획 내용의 직렬화 해시가 그대로 유지된다.
- 데이터·정답·캐시 등은 Git index에서 추적 해제했고 새 ignore 규칙을 추가했다. **디스크 파일 삭제가 아니며 GitHub 원격이나 과거 이력은 바뀌지 않았다.** 커밋·푸시는 하지 않았다.

현재 로컬에는 데이터 8개 폴더 및 호환 junction이 보이므로 루트 항목이 7개뿐인 구조는 아니다. 깨끗한 제출 checkout에는 ignore된 데이터나 junction이 포함되지 않는다. 구조 계획의 외부 data 이동 및 과거 이력 제거는 사용자 보존 조건과 별도 승인 경계에 따라 수행하지 않았다.

## 다음 단계

**현재 다음 작업은 사용자의 학습·평가 계획 수정사항 반영이며, 그 뒤 3단계를 재개한다.** 기존 폴더에 존재하는 3~5단계 준비 기록을 이번 요청으로 새로 실행하거나 승인하지 않았다. fold 확정, 정답 잠금, 실제 학습도 수행하지 않았다.

원본 계획: `C:/ITDA_OCR_CODE/학습 및 테스트 결과/학습_및_평가_실행계획.md`.

2단계 승인 자료는 기존 경로 그대로 접근 가능하다. 계획 변경으로 데이터 모집단·평가 계약이 바뀌면 기존 705장 정책과 분할 초안의 적합성을 먼저 다시 확인한다. 기존 공개 정답 이력이 사라졌거나 fold 5가 물리적으로 잠겼다고 간주해서는 안 된다.

호환 junction은 이 Windows 작업 공간의 연속성을 위한 장치다. 새 학습 PC로 이전할 때는 외부 자료와 경로를 복원해야 한다. 추론 제출은 src와 사전 준비된 weights만 사용하며 외부 작업 공간을 요구하지 않는다.
