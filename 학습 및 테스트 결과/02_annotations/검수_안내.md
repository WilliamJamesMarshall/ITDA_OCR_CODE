# 2단계 OCR 학습 주석 구축

추가수집 XLSX의 최종 날짜 364건은 사용자가 이미 사진을 직접 눈으로 확인한 정답이다. 모든 추가수집 레코드의 `final_date_review.method`에 `human_visual_review_of_all_364_images`로 기록했다. 이 단계는 사진에 실제로 인쇄된 원문·영역·역할과 학습용 주석을 구축한다.

## 바로 검수하기

실행 중인 로컬 화면: http://127.0.0.1:8765

서버가 종료되면 프로젝트 루트에서 다음 명령으로 다시 연다.

```powershell
.venv\Scripts\python.exe scripts\ocr_annotations.py serve --port 8765
```

1. 추가수집/상품사진을 선택하고 원본 ID 또는 학습 ID로 이미지를 찾는다. 검색 후 Enter 또는 이미지 선택을 사용한다.
2. 날짜 줄(청록색), 표제(노란색), 기타/코드(보라색) 영역을 선택한다. 전체 화면 맞춤·확대·스크롤·선택 crop으로 사진을 대조한다. 다각형 꼭짓점을 드래그하거나 좌표 JSON을 수정하고, 빠진 영역은 다각형 추가로 만든다.
3. 날짜 줄별 실제 인쇄 원문을 입력한다. `21.05.26`을 `2021-05-26`으로 바꾸지 않는다. 숫자, 구분자, 내부 공백, 영문 월, 함께 인쇄된 시각·로트를 보존한다. 여러 줄이면 각 줄의 영역을 따로 만든다.
4. 날짜·표제 역할을 expiry/manufacture/other로 확인하고 근거와 관련 표제 영역 ID를 연결한다. 원천 class due/prod/exp 또는 최종 날짜 일치만으로 역할을 자동 승인하지 않는다. 역할 불명은 other와 불명 사유를 기록한다.
5. 연·월·일이 보이는지, 원래 없는지, 가려졌는지, 판독 불가인지 각각 표시한다. 가려진 문자 위치·내용은 설명 배열에 기록한다. 읽을 수 없는 문자를 정답에서 복원하지 않는다.
6. 반사·곡면·번짐·점 인쇄·저해상도 등의 품질 태그와 난이도를 확인한다. 초기 빈 품질 태그는 정상 승인 상태가 아니다.
7. 같은 상품·연속 촬영·파생본에 동일 group_id를 지정하고 근거를 남긴다. 초기 SHA 기반 group_id는 파일 동일성만 의미한다. 상품 그룹 확정은 실제 비교가 필요하다.
8. 확인한 영역은 직접 확인 완료, 잘못된 후보는 학습 대상에서 제외로 표시한다. 모든 날짜 줄·표제·품질·그룹을 확인하고 실제 검수자 이름을 입력한 뒤 검수 완료·학습 주석 승인을 누른다. 최종 날짜 NONE이어도 제조일 등 날짜 줄이 있으면 해당 영역을 주석 처리한다.

임시 저장은 pending이다. 승인된 레코드를 수정해 임시 저장하면 이전 승인이 해제되고 재승인이 필요하다. 수정 전 내용은 history에 보존된다. 동시에 수정된 버전은 덮어쓰지 않고 다시 불러오도록 거절한다. 사용자 이름을 자동으로 입력하거나 OCR 후보를 자동 승인하지 않는다.

## 데이터 형식과 좌표

- `annotation_schema.json`: 최소 필드·타입·열거값. 좌표 범위, polygon 교차, 역할·표제 연결과 승인 조건은 Python 검사기가 추가 검증한다.
- `records/{image_id}.json`: 이미지별 현재 작업 정본. 2,610개. 원본 ID, 이미지 SHA-256과 승인된 final_date는 편집 화면에서 변경할 수 없다.
- `candidate_crops/`: 원천 날짜 줄 404개의 검수용 crop. 미승인 자료이며 학습 목록에 자동 편입하지 않는다.
- `history/{image_id}/{revision}.json`: 수정 전 버전.
- `status.json`: audit 명령으로 갱신하는 집계.
- 좌표는 EXIF 회전을 적용하지 않은 저장된 원본 래스터의 픽셀이다. 화면도 같은 래스터를 표시하고 crop/OCR 역시 같은 좌표계를 사용한다.
- 원천 bbox는 직사각형 polygon 후보일 뿐이다. 사람이 영역을 수정하고 승인한다.
- 인식 crop은 polygon 바깥을 흰색으로 마스킹한 경계 상자 crop이다. 원근 보정이나 인쇄 문자 변형은 하지 않는다. 강한 회전/곡면 샘플은 품질 태그로 남기고 모델용 추가 전처리는 이후 동결한다.

## 후보 생성

추가수집 원천 주석에서 날짜 줄 404개·표제 280개·코드 150개를 가져왔다. 원천 문자열이 비어 있는 표제·코드는 아래 CPU OCR로 후보를 보완할 수 있다. 날짜 정답이나 기존 날짜 원문은 덮어쓰지 않는다.

```powershell
.labeling_paddle_env\Scripts\python.exe scripts\ocr_annotations.py suggest-missing-text
```

상품사진 한 장의 자동 후보는 다음 명령으로 만든다. 기존 승인 이미지와 이미 자동 후보가 있는 이미지는 덮어쓰지 않는다. 초기 구축 때 AMLC000001에서 실제 로컬 OCR 후보 생성을 확인했다. 나머지 상품사진은 주석 생성 대기 상태이며 init 완료가 전체 원문 구축 완료를 의미하지 않는다.

```powershell
.labeling_paddle_env\Scripts\python.exe scripts\ocr_annotations.py suggest --image-id AMLC000002
```

모든 후보는 pending으로 저장한다. 자동 OCR의 정확도 점수는 사람 검수 완료가 아니다. 정답의 연도·날짜를 원문으로 주입하지 않는다.

## 검사와 내보내기

```powershell
.venv\Scripts\python.exe scripts\ocr_annotations.py audit
.venv\Scripts\python.exe scripts\ocr_annotations.py export
```

export는 승인된 이미지 레코드만 읽는다. 새 exports/시각 폴더에 인식 crop+원문 목록과 전체 장면+날짜 줄 polygon 검출 목록을 저장한다. 이는 승인 주석 풀이고 실제 학습/validation 분할은 아직 아니다.

- 읽을 수 있는 단일 날짜 줄만 인식 목록으로 내보낸다. 가려짐/판독 불가, 여러 줄, 현재 인식기 최대 25자를 넘는 원문은 이유와 함께 인식 목록에서 제외한다. 원문을 잘라서 길이 제한에 맞추지 않는다.
- 검출 목록에는 판독 불가라도 실제 날짜 줄인 polygon을 포함한다. PaddleOCR용 검출 txt의 transcription은 무시 토큰 ### 대신 중립 토큰 date다. 원래 인쇄 문자열은 detection_pool.jsonl에 보존한다.
- 사람이 실제 날짜 줄이 없음을 확인한 이미지만 빈 polygon 검출 음성으로 내보낼 수 있다.
- 표제·코드·시각·날짜 블록은 맥락 주석으로 보존하고 날짜 줄 전용 검출 라벨에 섞지 않는다.
- group_id와 개발 노출 여부를 모든 인식/검출 풀에 보존한다. 기존 개발 노출 705장과 같은 상품 그룹은 fold 5에서 제외해야 한다.
- 그룹 분할·영구 내부 validation·문자 사전 호환 확인이 완료된 뒤 실제 PaddleOCR train/validation 목록을 생성한다. 전체 승인 풀을 그대로 학습 명령에 넣지 않는다.

2단계 완료에는 사람의 원문·영역·역할·품질·그룹 확인이 필요하다. XLSX 날짜 승인 건수와 OCR 학습 주석 승인 건수는 별도 집계한다.
