# 초안 우선 검수

2,610장의 모든 필드를 처음부터 입력하는 작업이 아닙니다. 승인된 XLSX 최종 날짜는 유지하고, 외부 원문·영역과 CPU OCR을 이용해 미승인 초안을 먼저 채웁니다.

## 현재 자동으로 하는 일

- 추가수집 364장의 기존 날짜·표제·로트 영역 및 OCR 원문 후보 재사용.
- 상품사진 2,246장에 CPU 4-thread OCR 실행. 이미지마다 결과를 저장하며 재실행 시 완료 이미지는 건너뜁니다.
- 이번 전체 처리에서는 새 CPU OCR 1,103장과 기존 로컬 CPU OCR 1,143장을 결합했습니다. 기존 기록은 당시 이미지 해시가 없어 역사적 동일성을 확정하지 않습니다. 현재 연결·해시·리사이즈 크기를 검사하고 EXIF 방향/축척을 원본 좌표로 역변환한 미승인 후보입니다. 상세 출처는 각 영역의 `provenance`에 있습니다.
- 원문/외부 클래스/같은 높이의 표제를 근거로 역할 초안, 날짜 필드 존재 여부, 구분자·시각·로트 초안 생성. 확정된 최종 날짜에서 인쇄 문자열을 역으로 만들지 않습니다.
- 기존 품질 태그 재사용. 모르는 반사·곡면·가려짐 등을 추측해 확정하지 않습니다.
- 전체 이미지의 시각 해시 비교로 가까운 사진 후보 제시. 자동 그룹 병합은 하지 않습니다. 후보가 없다는 사실은 단독 상품의 증명이 아닙니다.
- 날짜와 관련 없어 보이는 일반 문구는 `ocr_context`에 보존하여 필수 주석 목록의 불필요한 항목을 줄입니다. 잘못 분류된 날짜는 화면에서 후보로 가져올 수 있습니다.
- 날짜 줄이 누락된 사진에는 기존 다른 해상도 OCR을 대조하고, 픽셀 기반 줄 영역 제안과 한글/영문 인식기를 추가 적용했습니다. 실패를 날짜 없음이나 `NONE` 정답으로 바꾸지 않습니다.

## 화면에서 할 일

1. 잘린 사진과 채워진 원문·역할을 대조합니다. 원본 전체에서 빠진 날짜/표제가 없는지도 봅니다.
   상단의 **초안 준비 상태**에서 **확인 후 바로 승인 가능**과 **수정 필요**를 나눠 볼 수 있습니다. 이는 필수 항목 충족 여부이며 정확도 보증이 아닙니다.
2. 틀린 부분만 수정합니다. 초안이 맞으면 **초안이 맞음 · 승인하고 다음**을 한 번 누릅니다. 영역별 확인과 이미지별 네 가지 확인란은 이 명시적 승인 동작으로 함께 기록됩니다. 역할·원문·날짜 필드가 미확정인 영역은 먼저 보완하도록 안내합니다.
3. 사진 품질과 상품 그룹을 확인합니다. 그룹의 SHA-256은 동일 파일 식별자일 뿐 같은 상품·연속 촬영까지 확인한 값이 아닙니다. 같은 상품이라면 동일 group_id로 맞추고 실제 확인 근거를 남깁니다.
4. 검수자 표시 기본값은 이 로컬 화면의 **사용자**입니다. 원하는 이름을 한 번 설정하면 브라우저에 기억합니다. 판단하기 어려운 사진은 **보류하고 다음**으로 편집 내용만 저장할 수 있습니다. 승인 버튼을 누르기 전에는 사람이 확인한 것으로 기록되지 않습니다.

폴리곤 좌표를 새로 입력할 필요 없이 기존 꼭짓점을 드래그해 고칠 수 있습니다. 불확실한 날짜 순서·역할·빈 원문·낮은 OCR 점수는 해당 영역에 표시됩니다. 자동 신뢰도는 정답 보증이 아닙니다.

## 실행 및 상태

프로젝트 루트에서:

```powershell
$env:PADDLE_PDX_DISABLE_MODEL_SOURCE_CHECK='1'
.labeling_paddle_env\Scripts\python.exe scripts\build_annotation_drafts.py --ocr
.venv\Scripts\python.exe scripts\refine_annotation_drafts.py
.venv\Scripts\python.exe scripts\build_group_candidates.py
.venv\Scripts\python.exe scripts\report_annotation_drafts.py
.venv\Scripts\python.exe scripts\ocr_annotations.py serve --port 8765
```

이미 실행 중인 OCR 작업을 중복 실행하지 않습니다. `draft_progress.json`은 보고 명령 실행 시점의 스냅샷이며 실시간 완료 표시는 아닙니다. `focused_review_queue.json`은 그 시점의 확인 필요 항목입니다. 이미지별 `ocr_draft_pass`가 실제 완료 여부입니다. 실패/충돌은 보고서에 남기고 기존 기록을 보존합니다.

## 승인 경계

자동 초안은 전부 미승인입니다. XLSX의 승인 범위는 최종 날짜뿐입니다. 검수 화면의 승인 버튼을 사용자가 명시적으로 누를 때에만 확인/승인 상태를 기록하며, 가려진 글자를 정답 날짜로 메우지 않습니다. 초안 생성 완료와 2단계 최종 주석 승인 완료는 다릅니다. fold 분할과 학습은 이 작업에서 시작하지 않습니다.

한 번의 승인 버튼은 반복 체크를 줄이는 사용자 동작이지, 미확정 원문·날짜 필드·누락 영역 검증을 생략하는 기능이 아닙니다. 이런 사진은 수정 전 승인되지 않습니다. 픽셀 측정으로 제안한 품질 태그, 불명 역할, 파일 단위 임시 그룹도 사진과 비교해야 합니다. 원본의 모든 결함과 동일 상품 관계가 자동 검증됐다고 간주하지 않습니다.
