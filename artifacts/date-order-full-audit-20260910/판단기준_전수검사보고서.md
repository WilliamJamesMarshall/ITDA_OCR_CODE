## 2. 먼저 ‘날짜 종류’와 ‘날짜 순서’를 분리

날짜처럼 보이는 숫자를 곧바로 소비기한으로 취급하면 안 됩니다. 날짜 영역의 주변 문구와 본문 라벨의 ‘어디에 기한을 표시했는지’ 안내를 함께 읽어야 합니다.

- 소비기한/유통기한/EXP/Use by/Best before/TETT는 각각 원문 종류를 별도 필드에 보존합니다. 이번 목록은 기존 사진의 유통기한·품질유지기한까지 포함한 기한 후보입니다. 모든 Best before를 한국의 안전상 소비기한과 동일시하지 않습니다.
- 제조일(MFD/PROD/製造), 포장일, 냉동일, 해동일, 등급판정일, LOT/배치 코드는 기한과 별도입니다. 001134의 `SELL BY 03-03-21`은 판매기한이므로 소비/품질유지기한 목록에서 분리했습니다.
- 날짜 종류 문구가 없는 캔·컵 바닥은 `date_kind=unknown`으로 두어야 합니다. 누락 방지를 위해 모호 후보에는 남길 수 있지만 소비기한으로 자동 확정하면 안 됩니다.
- 연월만 있거나 일이 가려진 경우는 `precision=month` 또는 `unreadable`로 분리합니다. 날짜 순서 모호성과 OCR 판독 불능은 다른 문제입니다. 002458은 `2022 04`이므로 `20.12.04`라는 세 부분 날짜로 읽지 않습니다.

튀르키예 TETT는 품질 특성이 유지되는 기한이고 STT와 다릅니다. [튀르키예 농림부의 TETT/STT 구분](https://guvenilirgida.tarimorman.gov.tr/Haber/Detay/17236). 미국의 캔 추적 코드도 소비자가 해석할 기한과 구별해야 합니다. [USDA FSIS, Shelf-Stable Food Safety](https://www.fsis.usda.gov/food-safety/safe-food-handling-and-preparation/food-safety-basics/shelf-stable-food).

## 3. 명시적·수학적으로 단일한 경우를 먼저 제외

다음 단계는 추측보다 앞에 둡니다.

1. **형식 안내 확인:** `년/월/일`, `월/일/년`, `일/월/년`, `YYYY/MM/DD`, `DD/MM/YY`, `日/月/年` 등을 날짜 영역뿐 아니라 포장 전체와 한글 수입 라벨에서 찾습니다. 해당 안내가 어떤 날짜 필드에 적용되는지도 확인합니다.
2. **동일 기한의 대응 표기 확인:** 같은 사진에 `10/09/21`과 `2021년 10월 09일까지`가 함께 있으면 MDY로 확정할 수 있습니다. 단, 제조일과 기한, 냉동기한과 해동기한처럼 서로 다른 필드를 대응 번역으로 연결하면 안 됩니다.
3. **달력 후보 생성:** YMD·MDY·DMY 각각에 대해 월 범위, 월별 일수, 윤년까지 검증합니다. ‘형식 수’가 아니라 **서로 다른 실제 날짜 수**를 셉니다.
4. 실제 날짜가 하나뿐이면 날짜 값은 모호하지 않습니다. 예컨대 `21.05.21`은 YMD와 DMY가 모두 2021-05-21이며 MDY는 불가하므로 제외합니다. 다만 입력 형식 이름까지 확정됐다고 기록하지는 않습니다.

| 인쇄 예 | 유효 해석 | 처리 |
|---|---|---|
| `2024/02/23` | YMD 2024-02-23 | 요청한 세 형식 중 하나만 성립 |
| `23/02/2024` | DMY 2024-02-23 | 네 자리 연도가 끝에 있고 23은 월 불가 |
| `02/23/2024` | MDY 2024-02-23 | 네 자리 연도가 끝에 있고 중간 23은 월 불가 |
| `03/07/2021` | MDY 2021-03-07 / DMY 2021-07-03 | **네 자리 연도여도 모호** |
| `20-06-21` | YMD 2020-06-21 / DMY 2021-06-20 | 모호 후보 |
| `11/11/21` | YMD 2011-11-21 / DMY·MDY 2021-11-11 | 앞의 두 숫자가 같아도 연도 위치는 모호 |
| `12/01/24` | YMD 2012-01-24 / MDY 2024-12-01 / DMY 2024-01-12 | 세 후보를 모두 보존 |

이 보고서의 두 자리 연도 계산은 후보 비교를 위한 **2000+YY 가정**입니다. 실제 시스템에서는 촬영/유통 시기와 제조사 근거로 세기를 별도 검증해야 합니다. 현재 날짜에 가까운 해석을 자동 선택하거나 과거 날짜를 지우지 않습니다. 연속 6자리도 날짜라는 주변 근거를 먼저 확인한 뒤 `YYMMDD`, `MMDDYY`, `DDMMYY` 후보를 만듭니다. LOT 숫자에 무조건 적용하지 않습니다.

미국에는 모든 식품에 통일 적용되는 하나의 날짜 표시 체계가 없으므로 `미국=MDY`를 확정 규칙으로 만들면 안 됩니다. [USDA FSIS 안내](https://www.fsis.usda.gov/food-safety/safe-food-handling-and-preparation/food-safety-basics/shelf-stable-food).

### 적용 우선순위

1. 해당 날짜에 적용되는 포장의 직접 형식 안내 또는 정확히 대응하는 풀어 쓴 날짜 → 명시적 분류, 모호 목록에서 제외.
2. 달력상 불가능한 후보 제거 → 날짜 하나만 남으면 숫자만으로 해소.
3. **같은 상품·같은 판매시장·같은 포장 버전**의 제조사 확인 형식 → 강한 근거. 비슷한 브랜드의 다른 상품에서 읽은 형식을 그대로 전파하지 않음.
4. 필드 연결이 확인된 제조일 ≤ 기한, 문서로 확인된 보존기간, 동일 인쇄 템플릿의 명확한 제조일 → 제약 조건. 서로 다른 형식으로 인쇄되는 필드일 수 있으므로 같은 형식이라는 전제도 검증.
5. 포장 언어·판매시장·제조/수입자 주소·기한 문구 → 보조 정황으로 후보 순위만 추천.
6. 근거 부족 또는 충돌 → `HOLD`, 후보 날짜 전부 표시, 포장 다른 면이나 제조사 확인 요청.

예를 들어 002083·002084의 제조일13/03/2020은 DMY만 가능하여 기한06/11/2020의 DMY 해석을 지지하지만, 두 기한 후보 모두 제조 이후입니다. 이를 ‘선후 관계로 다른 후보가 탈락했다’고 설명하면 안 됩니다. 같은 인쇄 템플릿이라는 정황과 시간 모순은 구분해야 합니다.

‘이 식품은 보통 1년 보관한다’, ‘아직 판매 중이므로 미래 날짜다’, ‘더 늦은 날짜가 합리적이다’ 같은 추정은 확정 조건으로 쓰지 않습니다. 바코드 앞자리나 원재료 원산지도 상품 생산국·판매시장·날짜 순서의 확정 근거로 사용하지 않습니다.

## 6. 구현할 때 저장할 정보와 검증

저장 형식 `YYYY-MM-DD`와 **원본의 날짜 순서**를 별개로 두십시오. YMD·MDY·DMY 어느 방식으로 읽었더라도 정규화 결과는 YYYY-MM-DD로 저장할 수 있습니다.

최소 저장 항목은 `image_id`, 원문/위치, `date_kind`, 날짜 정밀도, 숫자 판독 신뢰 상태, `candidate_dates`, `input_order`, `normalized_date`, 판단 근거 원문/위치, 사용한 상품 템플릿과 판매시장, `decision_status`입니다. 모호할 때 `input_order`와 최종 `normalized_date`는 확정하지 않고 추천 값을 별도 필드에 둡니다.

```text
날짜 종류와 본문 안내 연결
→ 모든 유효한 날짜 후보 생성
→ 직접 안내/대응 날짜로 해소되는지 확인
→ 검증된 상품 템플릿과 날짜 간 제약 적용
→ 남은 후보의 정황상 순위 추천
→ 확정 근거가 없으면 HOLD 또는 REVIEW_REQUIRED
```

이번 JSON의 `recommended_date`는 추천값이며 실제 시스템의 확정 `normalized_date`가 아닙니다. `evidence_level=context_not_ground_truth`인 값을 확정 학습 라벨로 자동 복사하지 마십시오. 특히 `date_kind`도 종류별 정답 검수 완료를 뜻하지 않으므로, 원문의 EXP/BB/제조일 등 필드 검수가 별도로 필요합니다.

평가는 날짜 OCR 정확도, 날짜 종류 식별 정확도, 순서 정확도, 최종 날짜 정확도, 잘못된 자동 확정률, 보류율을 나누어 측정하는 것이 적절합니다. 확률을 검증하지 않은 상태에서 ‘신뢰도95%’ 같은 수치를 붙이지 않습니다. 원본과 회전/축소 변형 사진은 같은 묶음으로 train/test를 나눠 같은 상품 사진이 양쪽에 새지 않게 해야 합니다.
